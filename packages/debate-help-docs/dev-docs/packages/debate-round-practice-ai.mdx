# debate-practice-vs-ai

**Practice vs AI** — a full timed debate round against an AI opponent, mounted
in debate-ai.com at `/versus-ai` and reachable from the app dock.

This package is the Node/TypeScript port of the Go `arguehub` vs-bot server and
its Vite/React client. Nothing in the port calls Go, Mongo or Gin: it is plain
TypeScript, `fetch`-based, and runs under Next.js or a Cloudflare Worker.

## What's in it

| Export | What it is |
| --- | --- |
| `./backend` | The vs-bot server: 13 bot personalities, prompt construction, AI judging, gamification rules |
| `./client` | The browser client for those endpoints |
| `./ui` | The round screens |

## Using it

```tsx
import { DebatePracticeVsAi } from "debate-practice-vs-ai"

<DebatePracticeVsAi userId={session.user.id} userDisplayName={session.user.name} />
```

## What a saved round keeps

A signed-in round is one `practice_vs_ai_debates` row, owned by the user, with
the full `DebateVsBotRecord` in its `data` JSON blob. Besides the transcript and
phase timings, the record can carry:

| Field | Set by | Shown in |
| --- | --- | --- |
| `plan` | `POST /vsbot/create`, from the setup wizard's chosen arguments (`savedRoundPlan`: clipped like the per-turn plan, without the evidence `cards`) | Debate History, "Arguments chosen" (`RoundPlanView`) |
| `judgeFeedbackStyle` | `POST /vsbot/judge` | Debate History |
| `debrief` | `POST /vsbot/debrief` | Debate History |

`isValidDebateVsBotRecord` checks each optional field (`isValidSavedRoundPlan`
for the plan), so Settings → Restore from export keeps them, and the D1 store's
`rowToRecord` drops a malformed one instead of failing the round. Rounds started
from the quick bot picker, and rounds from before a field was stored, simply
lack it. The evidence cards stay out of the saved plan on purpose; the Coach
debrief still reads the plan from the live round, not the saved one.

## Finding a round in Debate History

`DebateHistory` lists every row `GET /vsbot/history` returns, newest first.
Above the list, a search box (every word must appear in the topic or the
opponent's name, case-insensitive), a result filter (All / Won / Lost / Draw /
Conceded / In progress) and a status line ("3 of 12 rounds · Record: 4–2 · 1
draw · 1 conceded") narrow it. The pure helpers live in `ui/history-filter.ts`:
`debateHistoryResult` classifies an `outcome` the same way the round's badge
does (blank → in progress, `"User conceded"` → conceded, else
`resolveResultStatus`), `filterDebateHistory`, `tallyDebateHistory`,
`debateHistoryRecordLabel` and `debateHistoryCountLabel`. The record always
counts every saved round; the "Fallacy hints across your speeches" summary
follows the filtered rounds. Filtering is client-side over the one response,
and the search and filter aren't remembered across visits.
