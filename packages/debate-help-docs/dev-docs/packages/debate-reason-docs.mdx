`@debate-ai/reason-docs` · [source on GitHub](https://github.com/debate/debate-ai.com/tree/master/packages/debate-reason-docs)

Package name `@debate-ai/reason-docs`. The REASON docs workspace moved out of
`debate-webview`: the sidebar file tree and tabs, the file manager, the editor screen,
sharing a file with contacts, selling it (`SellFileDialog`), Topic Starters, and the
helpers for slugs, paths, the save queue and the stored `.cmir` format. Signed-in state
arrives through `ReasonSessionProvider`, which the shell mounts. Depends on
`debate-editor`, `debate-file-market`, `debate-team-collaboration`, `debate-data-sync`,
and `debate-card-parser`; depended on by `debate-webview` and
`debate-webview-admin`.

## Where a file may live in the tree

The sidebar builds the file tree top-down from `parentId === null`, so a
`documents` row whose parent is missing, someone else's, a plain file, or the
row itself or one of its own sub-folders is never reached: it stays in D1 but
drops out of My Files. `lib/reason-docs/doc-parent.ts` holds the rule:
`isSelfOrDescendant` (what `FileTree` uses to refuse a drop) and
`checkDocumentParent`, which `POST /api/doc/documents` and
`PUT /api/doc/documents/:id` run on any `parentId` they are asked to write
(the PUT only when it differs from the row's current parent). A refused parent
answers 400 with the reason and writes nothing; someone else's folder reads as
missing so the answer doesn't confirm it exists. `parseDocumentPatch`
type-checks `title` / `content` / `parentId` first, so a wrong type is a 400
rather than a 500. The walk up the tree reads one row at a time through
`apps/debate-web/lib/api/document-tree.ts` and stops at `MAX_FOLDER_DEPTH`
or on a cycle already in the data.

Known gaps: the save queue retries a 400 like any other failure (up to its
attempt limit) and the optimistic move stays on screen until the next reload;
rows already orphaned before this check are not repaired.
