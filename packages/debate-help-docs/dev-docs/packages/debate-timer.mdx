# debate-timer

Round timing: the per-speech timer, the prep timer, per-format speech times, and the
speech recorder (mic selection, live waveform, playback) that records while the timer runs.

```tsx
import { SpeechTimer, PrepTimer, useSpeechRecorder } from "debate-timer"
import { debateStyles, type DebateStyleKey } from "debate-timer/src/formats/debate-format-times"
import { wordCountStyles, getWordCountStatus } from "debate-timer/src/formats/word-count-format"
```

Speech times are the source of truth for which columns a flow gets, so `debate-round`
depends on this package rather than the other way around.

## Package layout

Logic lives under `src/`, grouped by role; tests live under `test/`.

```
debate-timer/
├── src/
│   ├── audio/        # timer sound effects
│   ├── formats/      # per-format speech times and column layouts
│   ├── hooks/        # useSpeechRecorder
│   ├── recorder/     # mic selector, live waveform, recording player
│   ├── timers/       # SpeechTimer, PrepTimer
│   ├── types/        # timer and speech types
│   └── index.ts      # public entry point
└── test/             # Vitest suites for the format tables
```

## Recorder playback speed

`AudioPlayerProvider` (`src/recorder/audio-player.tsx`) remembers the last speed
picked in `localStorage` under `debate-playback-speed`, written as
`{"speed":1.5,"chosenAt":<Unix ms>}` (`serializeStoredSpeed`). Values written
before `chosenAt` existed are a bare number (`"1.5"`); `parseStoredSpeed` reads
both. A stored speed wins over the `initialPlaybackRate` prop.

The key is the `recorderPlaybackSpeed` collection in `debate-search-evidence`'s
`TOOL_RECORD_COLLECTIONS`, so a signed-in user's speed syncs to their
`saved_tool_records` rows. `account-sync/playback-speed-codec.ts` wraps the value
as one `{ id: "speed", speed, chosenAt? }` record. Only a finite speed from 0.25×
to 4× is pushed or written back, and a `chosenAt` that isn't a positive whole
number of milliseconds is dropped. A record with a time is written back as the
object, one without as the bare number. An empty merge writes `null`, which the
player reads as "never chosen".

When both sides hold a speed, the collection's `prefer` hook
(`preferPlaybackSpeed`) settles it: this device's speed wins only when its
`chosenAt` is later than the account's, or the account's copy has no time
(stored before `chosenAt` existed). A tie, or a local copy with no time, keeps
the account's. When this device wins, the merge pushes its speed up.

The provider listens for `storage` events on the key. A speed chosen in another
tab, or adopted from the account by a merge, applies to the open player without
a reload. A cleared or unusable value keeps the current speed.

Known gaps:

- ~~The account's speed wins over this device's on a merge, even if this device
  picked its speed more recently.~~ Fixed: the record carries `chosenAt` and the
  newer pick wins.
- `chosenAt` comes from each device's clock, so a device whose clock runs well
  ahead can beat a pick made later on another device.
- The video watch page's own playback speed (`debate-videos`) is separate and
  doesn't use this key.
