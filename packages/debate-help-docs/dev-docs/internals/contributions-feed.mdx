# Contributions Feed

How the Contributions Feed form picks the contributor a new submission is
credited to, and how that ties to the signed-in account.

- **Route:** `/research?section=rewards` (Research Workspace, Rewards tab)
- **Package:** `debate-research-evidence` (`packages/debate-search-evidence`):
  `src/panels/ContributionsFeedPanel.tsx`, `src/state/contributions.ts`
- **App wrapper:** `packages/debate-webview/src/components/research/identity/ContributionsFeedWithIdentity.tsx`
- **User docs:** [Contributions Feed](/docs/features/team-collaboration#contributions-feed)

## Identity

`ContributionsFeedWithIdentity` is the only piece that knows about the
session. It derives a contributor id with
`deriveContributorIdFromSessionIdentity(user)` and passes it to the panel as
the plain `signedInContributorId` prop; the panel stays app-agnostic.

The panel uses that id twice:

1. **Endorsing** is locked to it (`deriveLockedVerifierId`), and the Endorse
   button is disabled on the visitor's own rows.
2. **Contributor ID prefill.** An effect copies `signedInContributorId` into
   `draft.contributorId` while `hasEditedContributorId` is `false`. Typing in
   the box sets the flag, so a later prop change (a session refresh) never
   overwrites an edit. A successful submit resets the draft to
   `{ ...EMPTY_DRAFT, contributorId: signedInContributorId ?? "" }` and clears
   the flag. The note under the box reads "Filled in from your account." when
   the value equals the account id, otherwise "Your account's ID is …". It is
   the same pattern `ReviewQueuePanel` uses for its acting reviewer id.

Signed out (`signedInContributorId` unset) nothing changes: the box starts
empty and an empty submit shows "Contributor ID is required.".

## Known gaps

- The Contributor ID is prefilled, not locked: a signed-in visitor can still
  submit under any typed id. Locking it is an auth-policy decision.
- Contributions live in `localStorage` (`"contributions"`); the contributor id
  is a label, not a server-verified owner.
- `AttributedContribution` has no citation field, so the Evidence Library's
  **Format citation** button has no counterpart here.
