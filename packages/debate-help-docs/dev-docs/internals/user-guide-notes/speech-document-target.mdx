> These notes were moved here from the user guide when [its page](/docs/features/flow-speech/speech-document-target) was rewritten for end users (November 2026). They describe how the feature was built at that time; check the code before relying on a path or name.


`/speech-documents` shows a durable, listable send log of everything the
live Reason Editor (Debate Editor) has sent into a designated "speech doc"
pane.

- **Route:** `/speech-documents` (view/manage history) — send from any
  Debate Editor document (e.g. `/reason-editor`)
- **Package:** `debate-editor`

## How sending works

Debate Editor's speech-doc feature is a pane-designation model: mark a pane as
the speech doc (File menu → Speech), then send the current selection (or
card/section) with the backtick key. A live ProseMirror slice is inserted
directly into the designated pane — same-window, or cross-tab via
`BroadcastChannel`. The speech doc is just an ordinary open document —
Debate Editor keeps no separate copy.

## What this page shows

A **send log**, not a document list: the plain text of what actually landed
for every send, in IndexedDB, newest first, with per-entry Remove and a
Clear history action.

## Data flow

```
debate-editor/src/editor/speech-doc-send.ts → sendToSpeech / insertSpeechSlice
debate-editor/src/editor/speech-send-log.ts (IndexedDB, "speech-send-log")
apps/debate-ai.com/app/speech-documents/SpeechSendLogPanel.tsx
```

## Fallacy hints across the send log

`SpeechSendLogPanel` (`packages/debate-webview/src/routes/speech-documents/`)
mounts `FallacyFrequencySummary` from `debate-speech-writer` above the list
once at least one entry exists. Its input comes from
`sentSpeechFallacySpeeches` (`packages/debate-webview/src/lib/speech-send-fallacy-speeches.ts`),
which turns the newest-first entries into `{ label, text }` speeches:
`"<short date> · <snippet>"` (snippet from `preview`, clipped to
`SENT_SPEECH_LABEL_SNIPPET_MAX` = 40 with "…"; date dropped when `sentAt` is
not a positive finite number), skipping blank or non-string text.

Nothing is persisted and there is no schema change: the summary is derived on
read from the same entries the page lists, which for a signed-in user are
merged with the account's `saved_speech_send_log` rows by
`useSpeechSendLogSync`. Both the entry list and the speeches are memoised on
`entries`.

Tests: `packages/debate-webview/test/lib/speech-send-fallacy-speeches.test.ts`
and the "fallacy summary" cases in
`packages/debate-webview/test/routes/speech-documents/speech-send-log-deep-link.test.tsx`.

## Known gaps

Today's log is one global history, not grouped per speech-doc identity.

The fallacy summary scans whatever was sent, including evidence cards quoted
verbatim, so an author's phrasing can raise a hint the debater did not write.

## Linking a speech to an editor document

A speech's header can point at one of your recent editor documents, so its
word counts come from that file instead of the flow's own speech text. Links
are scoped to the round (or the flow, when it has no round) and are stored as
`speechDocLinks` records (`id` is `ROUND-SCOPE:SPEECH`, `docId` is the
document's account id). The store is in the account's synced tool records, so
a signed-in user's links follow them to other devices; a signed-out browser
keeps them in `localStorage`. Links saved under the old `speech-doc-links`
map are read once and folded into the new store on the next change.

A link only resolves on another device once both the round and the document
it names have synced there too — until then the speech falls back to its own
text.
