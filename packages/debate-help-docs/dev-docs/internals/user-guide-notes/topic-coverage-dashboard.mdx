> These notes were moved here from the user guide when [its page](/docs/features/research-evidence#topic-coverage-dashboard) was rewritten for end users (November 2026). They describe how the feature was built at that time; check the code before relying on a path or name.


Tracks a topic's argument checklist and shows which arguments are
well-covered, thin, or missing entirely, based on cards already submitted
to the shared evidence library.

- **Route:** `/research?section=coverage`, the **[Research Workspace](/docs/features/research-evidence/research-collaboration)**'s Topic Coverage tab (the old `/research/cards/coverage` redirects there)
- **Package:** `debate-card-search`

## What it shows

A topic switcher, an "Add to checklist" form, coverage rows (missing/
thin/covered, card count, word count), a "Needs the most work" list, and an
untracked section for submitted-but-unchecklisted argument blocks.

## Data flow

```
state/trackedArguments.ts (localStorage — topic checklist)
  → buildPersistedTopicCoverageReport(topic)
      → buildTopicCoverageReport() — lib/topic-coverage.ts (pure)
  → panels/TopicCoverageDashboardPanel.tsx
  → apps/debate-ai.com/app/cards/coverage/page.tsx
```

## Known gaps

The checklist (`trackedArguments`) syncs to a signed-in user's account —
see Tool Data Sync — but still per-user,
not a shared team resource: two contributors tracking the same topic each
keep their own checklist rather than editing one shared list.
