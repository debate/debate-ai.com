The Leaderboard & Team Rankings page covers the full technical details of the leaderboard system within the Debate AI platform. It includes the implementation and data flow of the `/api/leaderboard` route, various scrapers for rankings and tournament results including CSV import, the qualification cutoff and points table logic, NDCA/TOC bid data, and the user interface components such as `StandingsPanel` and `RankingsLeaderboardPanel` that render these data.

---

## Purpose and Scope

This module focuses on aggregating, persisting, scoring, and displaying competitive debate team rankings across multiple debate divisions (PF, LD, Policy (CX), NDT). It supports:

- Import and scraping of TOC bid data, DebateDrills Elo ratings, and tournament results.
- Local storage of user-entered tournament results and customizable qualification points tables.
- Filtering, sorting, and multi-tab viewing of leaderboards and standings.
- Qualification cutoff logic to mark and count teams who qualify under custom criteria.

The main code lives mainly in two scopes: backend data scraping and API feeding logic (`/api/leaderboard` route and `debate-data-sync` package), and frontend presentation via React components in `debate-videos`.

## 1. System Architecture and Data Flow

The leaderboard system orchestrates data from various external sources, processes it, persists local user data, and exposes an API for consumption by client UI components.

### Data Flow Overview

- External scrapers load ranking data and TOC bid data.
- The API `/api/leaderboard` merges these using heuristics (`mergeElo()`) and serves JSON.
- Tournament results and points tables are saved on-demand by users locally (using `localStorage`), managed by `state/tournamentResults.ts` and `state/qualificationPointsTable.ts`.
- Qualification cutoff settings are also persisted locally (`state/qualificationCutoff.ts`).
- Frontend React components use these sources to render leaderboards and standings in two tabs.

## 2. /api/leaderboard Route and Ranking Data Processing

The Next.js API route `/api/leaderboard` serves combined and processed leaderboard data according to specified parameters.

### Behavior Overview

- **Division & Year Parameters:** The endpoint accepts `division` (e.g., "VPF", "VLD", "VCX") and `year` query parameters to determine which data sources to query and how to combine them.
- **Historical Data:** For prior years (e.g., 2021-2025), ranking data is fetched from DebateDrills's CSV downloads, using the `getDatasets()` and `scrapeDivision()` helpers [apps/debate-ai.com/app/api/leaderboard/route.ts111-127](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/leaderboard/route.ts#L111-L127)
- **Current Year Data:** For the present season, the route queries live TOC bid data from `tocbidlist.com` scrapers (`scrapeVCX`, `scrapeVPF`, `scrapeVLD`). For VPF and VLD, it additionally fetches Elo ratings and merges them using `mergeElo`[apps/debate-ai.com/app/api/leaderboard/route.ts129-151](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/leaderboard/route.ts#L129-L151)

### Team Name Normalization and Matching (`mergeElo`)

Because different sources may use different naming conventions or partial names for teams, merging is approximate and normalized:

- `normalizeTeamName(str: string)` converts team names to lowercase, strips punctuation, and collapses whitespace [apps/debate-ai.com/app/api/leaderboard/route.ts23-29](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/leaderboard/route.ts#L23-L29)
- For LD teams, student initials appended to team names are extracted and used to improve fuzzy matching [apps/debate-ai.com/app/api/leaderboard/route.ts78-84](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/leaderboard/route.ts#L78-L84)
- For PF teams, trailing partner initials might be swapped to handle differing partner orderings [apps/debate-ai.com/app/api/leaderboard/route.ts46-50](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/leaderboard/route.ts#L46-L50)[apps/debate-ai.com/app/api/leaderboard/route.ts89-95](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/leaderboard/route.ts#L89-L95)

This matching enables combining TOC bid counts with Elo rankings for enriched leaderboard rows.

## 3. Tournament Results Persistence and CSV Import

Since automated live scraping of Tabroom results is blocked and manual entry is cumbersome, a bulk CSV import and manual entry system is implemented for tournament results storage.

### Data Model and Local Storage in `tournamentResults.ts`

- Each tournament result is stored as a **TournamentResultRecord**, extending `TournamentResult` with a unique synthetic `id` to differentiate multiple results for a team [packages/debate-data-sync/src/state/tournamentResults.ts25-27](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/state/tournamentResults.ts#L25-L27)
- Tournament records include fields: `teamId`, `tournamentName`, `date`, `division`, `bidLevel`, `finish` (outround finish), `prelimWins`, `prelimLosses`.
- Data is persisted in the browser's `localStorage` under key `"tournamentResults"` with robust read/write helpers that fallback gracefully on corrupt or missing data [packages/debate-data-sync/src/state/tournamentResults.ts31-46](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/state/tournamentResults.ts#L31-L46)

### CRUD Operations

- `listTournamentResults()` returns all persisted results.
- `listTournamentResultsForTeam(teamId)` filters persisted results by a team.
- `saveTournamentResult(record)` appends a new record.
- `deleteTournamentResult(id)` removes a record by its unique id [packages/debate-data-sync/src/state/tournamentResults.ts48-68](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/state/tournamentResults.ts#L48-L68)

### Bulk CSV Import

- CSV import parses a spreadsheet-like CSV string into results, skipping and reporting malformed rows without aborting the entire import [packages/debate-data-sync/src/rankings/tournament-results-csv-import.ts130-191](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/rankings/tournament-results-csv-import.ts#L130-L191)
- The parser supports columns in any order, case-insensitive headers, and defaults for missing optional columns.
- After parsing, entries are appended to persisted store with generated unique ids [packages/debate-data-sync/src/state/tournamentResults.ts85-101](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/state/tournamentResults.ts#L85-L101)

## 4. Qualification Points Table and Cutoff

The system supports a customizable points table and qualification cutoff criteria for NDCA-style cumulative standings.

### Points Table (`qualificationPointsTable.ts`)

- Users can supply a point value for each outround finish, a points-per-prelim-win, and a bid-level bonus multiplier.
- These values are persisted locally under `"qualificationPointsTable"`.
- A default illustrative points table is provided but users should save their circuit-specific values [packages/debate-data-sync/src/state/qualificationPointsTable.ts](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/state/qualificationPointsTable.ts)

### Qualification Cutoff (`qualificationCutoff.ts`)

- Represents optional settings:

- `minPoints`: minimal points to qualify.
- `maxQualifiers`: cap on number of qualifying teams.
- Both fields can be `null` if unconfigured.
- The system stores these in local storage under `"qualificationCutoff"` and offers helpers for reading, writing, resetting, and checking configuration status [packages/debate-data-sync/src/state/qualificationCutoff.ts](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/state/qualificationCutoff.ts)

## 5. Standings Computation and Ranking

The core ranking calculations rely on the helper functions in `ndca-standings.ts`. This layer provides:

- `computeTournamentPoints(result, pointsTable)` — scores a single tournament result based on point weights.
- `buildTeamStanding(results[], options)` — aggregates multiple results per team.
- `buildStandings(byTeamResults, options)` — builds standings from grouped team results.
- `rankStandings(standings)` — assigns ranks based on points and tiebreakers [packages/debate-data-sync/src/rankings/ndca-standings.ts40-150](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/rankings/ndca-standings.ts#L40-L150)

The `buildStandingsFromStore()` function in `tournamentResults.ts` reads all persisted records, groups by team, and applies the ranking pipeline for display [packages/debate-data-sync/src/state/tournamentResults.ts124-130](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/state/tournamentResults.ts#L124-L130)

## 6. User Interface Components

### RankingsLeaderboardPanel

- Located in `packages/debate-videos/src/panels/leaderboard/RankingsLeaderboardPanel.tsx`.
- Orchestrates top-level UI state such as division, season year, sorting, and switching between tabs ("Leaderboard" vs "Standings").
- Delegates filtering controls to `LeaderboardFilterBar` and rendering to `LeaderboardTable` (for Elo/TOC leaderboard) and `StandingsPanel` (for NDCA standings).
- Fetches leaderboard data using `useLeaderboardData` hook, passing division/year.
- Syncs division changes to URL query param `?format=` for bookmarking and sharing.
- Handles hiding internal filters when controlled by props [packages/debate-videos/src/panels/leaderboard/RankingsLeaderboardPanel.tsx24-167](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/panels/leaderboard/RankingsLeaderboardPanel.tsx#L24-L167)

### StandingsPanel

- Located in `packages/debate-videos/src/panels/leaderboard/StandingsPanel.tsx`.
- Provides UI for manual tournament result entry, bulk CSV import, and editing the qualification points table and cutoff settings.
- Uses `debate-data-sync` state modules to persist results and points.
- Displays a ranked standings table with expandable rows showing individual tournament results.
- Supports validation and error reporting for result input.
- Refreshes leaderboard on data changes and resets sort state when division changes.
- Part of the "Standings" tab within `RankingsLeaderboardPanel`[packages/debate-videos/src/panels/leaderboard/StandingsPanel.tsx1-176](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/panels/leaderboard/StandingsPanel.tsx#L1-L176)
