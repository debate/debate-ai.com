This section details the browser extensions developed for the Debate AI platform. These extensions provide specialized functionality that integrates directly with the user's browsing experience, extending the capabilities of the main web application. Currently, there are two primary extensions: `apps/debate-web-ext` for on-page card reuse checking and `apps/debate-timer-progress-ext` for a round timer with timeline export.

## Card Reuse Check Extension (`apps/debate-web-ext`)

`apps/debate-web-ext` is a Manifest V3 browser extension built with WXT, React 18, and TypeScript. It provides two main utilities for debaters:

1. **On-page card reuse check** — Queries whether the current tab's URL has already been "cut" into a shared evidence library, leveraging the Debate AI backend's `/api/evidence-reuse-check` endpoint. This prevents duplicate research and duplicate card cutting by allowing rapid team-wide source URL reuse lookup.
2. **Round timer launch control** — Provides a toolbar popup to open a dedicated round timer window (`timer.html`) supporting debate formats, clock management, timeline export, and session persistence.

The extension features a popup UI, an options settings page, and an isolated popup window for the timer. It uses the `storage.sync` API to persist user settings such as API base URL and domain skip lists, and makes cross-tab updates via `storage` events.

### Purpose and Scope

The reuse check functionality prevents extra work by searching the shared server-side `evidenceReuseIndex` table for entries whose normalized source URL matches the current page. The extension taps into this shared index instead of relying solely on the local browser storage that the web app uses internally. This allows all team members to avoid duplicating cards cut from the same source, independent of device.

The timer provides an independent, resizable popup window instead of toolbar dropdown controls because dropdowns auto-close on tab switches, which would disrupt timer usability in live rounds.

### Implementation Details

- **Build system and stack:** Uses [WXT](https://wxt.dev) for MV3 bundling with React and TypeScript.
- **UI Components:**

- Popup page (`popup.html`) renders reuse check status and buttons including "Open round timer".
- Timer page (`timer.html`) hosts the timer + timeline UI.
- Options page (`options.html`) configures API base URL and skip domains.
- UI components use the shadcn UI primitives such as `Select`, `Tabs`, `Button`, and `Tooltip`.
- **Shared logic:**`api.js` provides reusable functions for:

- Reading/writing stored settings
- Parsing skip-check domain whitelist
- Normalizing URLs for domain skip checking
- Calling `/api/evidence-reuse-check` endpoint
- **Extension behavior:**

- On popup open, reads the current active tab URL, skips querying if the domain is whitelisted, or sends a fetch request to the server.
- Displays results as "Already cut" or "Safe to cut" and lists matching cards.
- Logs reuse check usage for analytics in the backend.
- Handles configuration changes via the options page backed by `chrome.storage.sync`.

The backend `apps/debate-ai.com/app/api/evidence-reuse-check/route.ts` implements the reuse check API:

- **Normalization:**`normalizeSourceUrl(url: string): string` strips schemes, leading `www.`, query strings, fragments, and trailing slashes for consistent source URL matching.[apps/debate-ai.com/app/api/evidence-reuse-check/route.ts29-38](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/evidence-reuse-check/route.ts#L29-L38)
- **GET `/api/evidence-reuse-check`** — Queries `evidenceReuseIndex` D1 table for normalized URL matches, returns whether `alreadyCut` with matching cards array, and logs each check to `reuseCheckLog`.
- **POST `/api/evidence-reuse-check`** — Upserts source URL entries into `evidenceReuseIndex` on card submission (used by the main web app only).
- **Logging:** The `reuseCheckLog` table tracks all checks with metadata (URL, normalized URL, matched count, source ["extension" or "web"], timestamp) for analytics and a team dashboard view.

### Local Development and Installation

To install and test the extension locally:

1. Navigate to `chrome://extensions`.
2. Enable "Developer mode".
3. Click "Load unpacked" and select the `apps/debate-web-ext` directory.
4. The extension defaults to querying `https://debate-ai.com`. To use a local backend (e.g., `http://localhost:3000`), update the API base URL in the extension Options page.

Domains allowed in `host_permissions` are the production domain and localhost; other hosts require manifest updates and extension reloads.

The options page also configures a domain skip-check whitelist. Domains in this list (including subdomains) do not trigger network reuse checks, showing a neutral "skipped" status instead.

## Debate Timer Progress Extension (`apps/debate-timer-progress-ext`)

The `apps/debate-timer-progress-ext` extension offers a robust round timer with timeline visualization and PNG export capabilities. It uses WXT and React, building atop the modular `debate-timer` package that offers timer logic and UI components.

### Purpose and Scope

The extension provides an always-available timer window designed specifically for debate rounds, covering:

- Constructive, Rebuttal, and Cross-examination speech timings per side
- Prep time banks
- Timeline visualization of speech timing with exports to PNG
- Resumable sessions to persist progress

This timer runs in its own popup window to prevent UI disruption during rounds, avoiding issues with toolbar dropdowns closing upon tab focus changes.

Sources: [apps/debate-web-ext/README.md5-7](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-web-ext/README.md?plain=1#L5-L7)[packages/debate-timer/src/index.ts1-5](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-timer/src/index.ts#L1-L5)

### Implementation Details

While the full source code for this extension is not included here, it leverages:

- **Timer state and hooks:** Provided by `useTimer.ts` in the extension source, managing speech states, prep times, auto-advance, and session persistence.
- **UI Components:**
- `TimerFace.tsx` renders the circular countdown meter with speech and prep buttons, including the digital-7 font and ring depleting animation.
- `Timeline.tsx` renders a scalable SVG timeline with recorded speech intervals.
- **Export functionality:**
- Exports timeline visualization as PNG via an offscreen `<canvas>`.
- **Persistence:**
- Uses `browser.storage.local` to save current timer state and timelines for resumability.
- **Format handling:**
- Supports multiple debate formats (HS Policy, Lincoln Douglas, etc.) with configurable speech times.

### Relationship to `debate-timer` Package

The `debate-timer-progress-ext` builds atop the reusable `debate-timer` package which exports:

- `SpeechTimer` and `PrepTimer` components for managing timers
- `TimerProgressRing` for the circular depletion visualization
- Format-specific timing tables and helpers (e.g., `debate-format-times`)
- Utilities for word counting during speeches (`SpeechWordCounter`)
- Hooks for microphone transcription (`useSpeechRecorder`)

This modular design enables consistent timer logic across the browser extension, web app, and native desktop wrappers.
