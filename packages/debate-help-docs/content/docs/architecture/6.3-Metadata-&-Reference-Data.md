The Debate AI platform utilizes a collection of flat-file JSON databases to manage historical records, tournament metadata, and reference materials. These files serve as the "ground truth" for semi-static content, enabling high-performance retrieval through static API endpoints without the overhead of relational or synchronous databases.

## Metadata Directory Structure

The core metadata resides in the directories:

- `packages/debate-data-sync/data/metadata/`
- `packages/debate-data-sync/data/videos/`

These directories contain JSON files describing debate topics, champions, tournaments, dictionary entries, school names, and YouTube statistics. Each data file is validated against JSON schemas to preserve structural integrity during ingestion and consumption [packages/debate-data-sync/README.md9-12](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/README.md?plain=1#L9-L12)

### Core Reference Files

| File | Content Description | Schema Reference |
| --- | --- | --- |
| `debate-topics.json` | Historical list of debate resolutions by year and format | `debate-topics.schema.json` |
| `debate-champions.json` | National champions for major debate formats (NDT, Policy, LD, PF) from 2000 to present | `debate-champions.schema.json` |
| `debate-dictionary.json` | Comprehensive glossary of debate terms and jargon | `debate-dictionary.schema.json` |
| `debate-tournaments.json` | Validated flat list of tournament names used for normalization | `debate-tournaments.schema.json` |
| `youtube-stats.json` | Aggregated YouTube video metrics (views, counts) derived from video sync | N/A (Generated artifact) |

These files provide canonical data for features like the history timeline, tournament recognition, term lookup, and statistics dashboards.

## Video Data Persistence

Video metadata is stored as positional arrays in JSON files, grouped by debate format style. These files adhere to the `debate-rounds-videos.schema.json` schema which dictates a strict 17-field array format optimized for compactness [packages/debate-data-sync/data/videos/rounds-college.json2-3](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/data/videos/rounds-college.json#L2-L3)

### Positional Array Round Fields (17 Elements)

Each video round data entry is a tuple with the following fields:

1. `videoId`
2. `title`
3. `date` (ISO string)
4. `channel`
5. `views` (integer)
6. `description`
7. `style` (1=Policy, 2=PF, 3=LD, 4=College)
8. `tournament`
9. `roundLevel` (e.g. Octafinals, Finals)
10. `affTeam` (Affirmative side)
11. `negTeam` (Negative side)
12. `winner` (boolean indicating win for Aff side)
13. `judgeDecision` (string)
14. `arg1AC` (argument from 1AC)
15. `arg2NR` (argument from 2NR)
16. `isTopPick` (boolean)
17. `speechDocsUrl` (optional URL for speech document referencing the round)

### Representative Files per Format

- Policy: `rounds-policy.json`
- Public Forum: `rounds-pf.json`
- Lincoln-Douglas: `rounds-ld.json`
- College (NDT/CEDA): `rounds-college.json`

These files are the authoritative curated video round data sets driving the video library UI and search features [packages/debate-data-sync/data/videos/rounds-policy.json3-21](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/data/videos/rounds-policy.json#L3-L21)[packages/debate-data-sync/data/videos/rounds-pf.json3-21](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/data/videos/rounds-pf.json#L3-L21)[packages/debate-data-sync/data/videos/rounds-ld.json3-21](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/data/videos/rounds-ld.json#L3-L21)[packages/debate-data-sync/data/videos/rounds-college.json3-21](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/data/videos/rounds-college.json#L3-L21)

## Tournament Results & Standings

While the metadata directory handles curated static data, user-generated reference data such as tournament results and season standings use a persistence layer built on top of `localStorage`.

### Persistence Layer: Tournament Results

Stored in `packages/debate-data-sync/src/state/tournamentResults.ts`, tournament results are modeled as `TournamentResultRecord` objects with unique IDs (composed keys to avoid conflicts):

- Storage key: `tournamentResults` in `localStorage`.
- Functions:

- `saveTournamentResult(record)`: appends new results.
- `listTournamentResults()`: retrieves all saved results.
- `listTournamentResultsForTeam(teamId)`: filters results by team.
- `deleteTournamentResult(id)`: deletes by record ID.
- `bulkImportTournamentResults(rawCSV)`: parses and saves bulk CSV input [packages/debate-data-sync/src/state/tournamentResults.ts1-112](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/state/tournamentResults.ts#L1-L112)

### Standings Computation

The `buildStandingsFromStore()` function:

- Reads all tournament data.
- Groups results by `teamId`.
- Applies scoring logic with a qualification points table (custom or default).
- Calls `rankStandings()` for final rank ordering.
- Returns a ranked array of `RankedTeamStanding` entries [packages/debate-data-sync/src/state/tournamentResults.ts124-130](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/state/tournamentResults.ts#L124-L130)

### Qualification Points Table

This scoring table assigns numeric weights for:

- Outround finishes (champion, finalist, semifinalist, etc.).
- Points per prelim win.
- Bonus rates for bid levels.

Users can persist custom tables in `localStorage` under `qualificationPointsTable`. Retrieval falls back to the default if not set [packages/debate-data-sync/src/state/qualificationPointsTable.ts1-12](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/state/qualificationPointsTable.ts#L1-L12)[packages/debate-data-sync/src/state/qualificationPointsTable.ts58-61](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/state/qualificationPointsTable.ts#L58-L61)[packages/debate-data-sync/src/state/qualificationPointsTable.ts73-75](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/state/qualificationPointsTable.ts#L73-L75)

## YouTube Statistics

The `youtube-stats.json` file is a generated aggregate of video metrics processed during the data sync pipeline. It aggregates total views, video counts, and provides channel-level breakdowns.

### Metrics Overview

- **Summary counts:**

- Total views: 5,647,144
- Total videos: 2,779
- Total channels: 44
- **Per-channel breakdown:** Includes total view counts, video count, and average views per video for channels such as "PF Videos", "Debate Stream", "Kansas Debate", etc.
- **Aggregate by debate style:** Views aggregated for each style ID (e.g. Style 4 = College debate).

This data drives the `/api/youtube-stats` endpoint and the "Stats" dashboard UI [packages/debate-data-sync/data/metadata/youtube-stats.json1-300](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/data/metadata/youtube-stats.json#L1-L300)
