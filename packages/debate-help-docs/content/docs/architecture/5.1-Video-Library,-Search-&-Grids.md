The Video Library and Rounds Archive is a core component of the LEARN module, providing a searchable, categorized repository of thousands of competitive debate rounds and educational lectures. It utilizes a SQL-backed feed with scroll pagination to handle thousands of entries efficiently, replacing the legacy system that required downloading the entire dataset upfront.

## Architecture & Data Flow

The system transitioned from a pure JSON-in-memory model to a hybrid SQL/JSON architecture. While flat-file JSON assets in `packages/debate-data-sync/data/videos/` remain the source of truth for the YouTube sync pipeline, they are projected into a `videos` table in Cloudflare D1 for high-performance filtering, search, and pagination [docs/features/video-library.md13-23](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/video-library.md?plain=1#L13-L23)

### Data Source Projection

The system aggregates data from multiple specialized JSON files. These are transformed into `VideoRow` objects and seeded into the database [packages/debate-data-sync/src/videos/video-rows.ts](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/videos/video-rows.ts) (not shown in full).

| File Path | Content Type |
| --- | --- |
| `rounds-policy.json` | High School Policy Debate rounds |
| `rounds-pf.json` | Public Forum (PF) rounds |
| `rounds-ld.json` | Lincoln-Douglas (LD) rounds |
| `rounds-college.json` | NDT/CEDA College Policy rounds |
| `debate-lectures.json` | Educational lectures and topic analyses |
| `debate-top-picks.json` | Curated list of high-quality YouTube IDs |

## Implementation Details

### 1. The SQL Schema & Seeding

The `videos` table contains derived columns to keep filtering cheap. `season_year` (June-to-June) and `search_text` (lowercased title + channel + description) are generated during the seed process to enable efficient `LIKE` queries [docs/features/video-library.md29-34](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/video-library.md?plain=1#L29-L34)

The seeding process is idempotent and handles D1's 100 KB statement limit by batching based on byte size rather than just row count, as video descriptions vary significantly in length [packages/debate-data-sync/src/videos/video-seed-sql.ts49-58](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/videos/video-seed-sql.ts#L49-L58)

- **`buildVideoSeedStatements`**: Generates `INSERT INTO ... ON CONFLICT DO UPDATE` statements and a final `DELETE` statement to prune rows no longer in the JSON assets [packages/debate-data-sync/src/videos/video-seed-sql.ts133-175](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/videos/video-seed-sql.ts#L133-L175)
- **`sqlLiteral`**: A utility to escape SQLite literals, doubling single quotes and handling non-finite numbers [packages/debate-data-sync/src/videos/video-seed-sql.ts74-79](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/videos/video-seed-sql.ts#L74-L79)

### 2. Serving & Pagination

The `/api/videos` route supports complex filtering (source, style, year, sort) and uses `limit` and `offset` for infinite scroll [docs/features/video-library.md38-40](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/video-library.md?plain=1#L38-L40) The OpenAPI specification for this route is defined in `debate-openapi.yml`[apps/debate-ai.com/public/debate-openapi.yml2000-2060](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/public/debate-openapi.yml#L2000-L2060)

- **JSON Fallback**: If the SQL table is unseeded or unreachable, the system automatically falls back to `src/videos/video-query.ts` (not shown in full), which performs the same filtering and pagination logic in-memory using the bundled JSON assets [docs/features/video-library.md57-63](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/video-library.md?plain=1#L57-L63)
- **Facets**: When `facets=1` is requested, the API returns per-season and per-style counts for filter dropdowns. These counts ignore their own dimension's filter to keep the UI intuitive [docs/features/video-library.md48-51](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/video-library.md?plain=1#L48-L51)

### 3. Client Hooks & Infinite Scroll

The frontend consumes the paginated API via specialized hooks:

- **`useVideoFeed(filters)`**: Manages the feed state, refetching from offset 0 when filters change and appending pages on `loadMore()`[docs/features/video-library.md68-70](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/video-library.md?plain=1#L68-L70)
- **`useInfiniteScroll`**: Observes a sentinel element below the grid to trigger the next page load [docs/features/video-library.md73-74](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/video-library.md?plain=1#L73-L74)
- **`useVideoState`**: Holds filter state (search, season, style, sort). Favorites are handled client-side and passed as an ID allow-list to the server [docs/features/video-library.md77-80](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/video-library.md?plain=1#L77-L80)

### 4. Video Player & Annotations

The `PersistentVideoPlayer` uses a Zustand store to maintain playback state across route changes. It is rendered in the root layout [apps/debate-ai.com/app/layout.tsx56](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/layout.tsx#L56-L56) (not shown in full).

- **`setActiveVideo`**: Sets the active YouTube ID and metadata. It supports a `startTimeSeconds` parameter, used when clicking a timestamped annotation (not shown in provided files).
- **`FlowAnnotationsPanel`**: Allows users to link specific flow cells to video timestamps. It reads the current time from the player store to generate links (not shown in provided files).
