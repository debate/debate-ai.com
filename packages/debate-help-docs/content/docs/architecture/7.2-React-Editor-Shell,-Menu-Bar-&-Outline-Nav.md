This page provides an in-depth technical overview of the React components that constitute the CardMirror editor shell within the Debate AI platform. It covers the `CardMirrorEditor` component, the `MenuBar` with its categorized command structure, the multi-pane shell architecture, the styles isolation strategy using the `/settings/editor-panel` iframe, and the native outline navigation panel complete with collapsed headings support.

These components are implemented inside the `debate-editor` package located under `src/react/` and are integrated within the web app, notably via the `/reason-editor` route.

---

## 1. React Editor Shell — CardMirrorEditor Component

### Overview

`CardMirrorEditor` is the main React wrapper around the CardMirror ProseMirror engine, exposing a React-friendly interface while managing the singleton nature of the editor instance.

- The CardMirror editing engine is a **page-level singleton**, meaning only one live editor instance can exist at a time.
- `CardMirrorEditor` manages the lifecycle of this singleton: claiming it when active and releasing upon unmount.
- It supports a **read-only preview mode** (`live={false}`) for cases with multiple editor panes side-by-side (such as Flow's split mode).
- The component binds props such as `content` (HTML string), `contentKey` (document identity), and `onChange` (callback for updates), maintaining compatibility with prior host interfaces like `reason-editor`.

### Key Features and Props

- `content`: The HTML content to render.
- `contentKey`: A stable key for the document instance, used to claim the singleton.
- `onChange`: Called when content changes.
- `live`: Whether this instance is the live editor owning the singleton or a read-only preview.
- `defaultNavPaneHidden`: To transiently override whether CardMirror's own outline navigation pane is visible on mount.
- `onActivate`: Used by read-only previews to request becoming the live instance.
- Supports imperative methods (via ref) such as `getHTML()`, `setHTML()`, `focus()`, and DOCX/CMIR import/export commands.

### Lifecycle and Singleton Management

`CardMirrorEditor` uses these React hooks:

- `useEffect` to claim and attach to the singleton when `live` is true and first mounted / when `contentKey` changes.
- Another `useEffect` to react to `content` changes of the current live document.
- Cleanup releases the singleton to allow other instances to claim it.
- A `useImperativeHandle` for external refs to interact with editor internals.

### Nav Pane Visibility Toggle

For hosts like `/reason-editor` that embed their own sidebar, the CardMirror editor's own nav pane is hidden initially by temporarily toggling the `navPaneVisible` setting to false, restored on unmount.

## 2. Menu Bar & Command Categories

### MenuBar Component

The `MenuBar` React component renders the full top-level menu bar above the editing ribbon. It exposes all ~500 Ribbon commands grouped logically for discoverability and compactness.

- Implements dropdown menus for categories like File, Speech, Card, Edit, Format, Color, Insert, AI, View, Panes, Tools, Flow, Workspace, and Plugins.
- Commands are dispatched via `runRibbon(commandId)` dynamically loaded from the editor engine module.
- Also includes a Settings button that opens the CardMirror settings UI.
- Workspace and Plugin menus provide links and plugin-registered commands respectively.

### Categorization: menu-bar-categories.ts

The menu bar groups commands into ~12 top-level categories:

| Category | Description | Ribbon Groups |
| --- | --- | --- |
| File | Document/file and collaboration commands | File, Collaboration |
| Speech | Speech and send/receive card tools | Speech, Dropzone / Send etc |
| Card | Card structural styles and condensing | Quick Cards, Numbering, etc |
| Edit | Editing utilities, search, select, comments | Editing utilities, Find, etc |
| Format | Character and inline formatting | Character styles, Inline formatting |
| Color | Highlighting and color pickers | Highlight tools, Color pickers |
| Insert | Table insertion | Table |
| AI | AI-related commands | AI |
| View | View and reading controls | View, Reading |
| Panes | Multi-pane workspace, zoom controls | Multi-pane workspace, Zoom & scale |
| Tools | Timer, diagnostics, learn, voice | Timer, Diagnostics, Learn, Cleanup, Voice |
| Flow | Flow-related commands | Flow |
| Workspace | Links out to other app tools (non-Ribbon) | Workspace links |
| Plugins | Runtime plugin commands | Plugin commands |

### Data Loading

- The category definitions (`MENU_BAR_CATEGORIES`) are dynamically imported to keep bundle size small.
- The `MenuBar` component asynchronously loads the category list and renders the dropdown menus.
- Commands trigger `runRibbon(id)` to dispatch Ribbon commands from the editor.

## 3. Multi-Pane Shell & Document Layout

CardMirror supports a multi-pane workspace shell capable of showing up to three document panes side-by-side, such as in Flow split mode.

- The `multi-pane-shell.ts` module (in `src/editor/`) manages three pane slots (`slot1`, `slot2`, `slot3`), each holding a stack of open documents.
- Each pane renders a ProseMirror editor instance (shared singleton) and coordinates focus, saved states, and footers.
- The outline navigation panel divides into sections per active pane, enabling drag-and-drop reordering, multi-selection, and live highlighting.
- A small title chip identifies each pane.
- The ribbon commands, status bar, and save actions route through the currently focused pane.
- Comments live in a dedicated separate column outside the main shell split.

**Note:** Because CardMirror is a singleton editor engine, only one live editing instance is possible; the shell manages, hides, or shows the single instance as needed.

## 4. Styles Isolation via `/settings/editor-panel` iframe

A crucial architectural detail is the isolation of CardMirror's large, global stylesheet via an iframe embedded at `/settings/editor-panel`.

- CardMirror ships a huge, unscoped stylesheet (`styles.css`) that applies global resets and base styles (e.g., `body`, `html`, `:root`).
- Directly including this stylesheet inside the main app component tree leads to conflicts with Tailwind CSS base layers.
- To prevent CSS leakage, the CardMirror settings UI is rendered inside a **same-origin `<iframe>`**, isolating the global stylesheet inside that document.
- The iframe communicates content height back to the parent to allow dynamic resizing.
- The loading process fetches user settings from `/api/settings` and hydrates the CardMirror settings store.

This approach was introduced and is utilized in the `/settings/editor-panel` route and its hosting component.

## 5. Outline Navigation Panel & Collapsed Headings

CardMirror's **native outline navigation panel** is one of the core navigation aids included in every CardMirror instance outside `/reason-editor`.

### What the Panel Shows

- The nav panel lists all heading-anchored nodes in the document: Pocket (H1), Hat (H2), Block (H3), Tag, and Analytic nodes, hierarchically indented.
- Each heading can be **collapsed or expanded** with chevrons or double-click.
- Supports **drag-and-drop** to reorder document sections.
- Supports **multi-selection** of headings.
- Provides a filter to show heading levels 1 through N.
- Highlights the heading under the current text caret.
- Clicking a heading scrolls precisely to that section in the document.

### Default Visibility

- The nav panel defaults to **visible** for all CardMirror hosts except `/reason-editor`, which renders its own file tree and tabs sidebar and so hides the nav panel initially (via `defaultNavPaneHidden` prop).
- Users can toggle it on/off via the ribbon command `toggleNavPane` or a left-edge pull-tab.
- The visibility is persisted in the `navPaneVisible` setting.

### Heading Breadcrumb Bar

- A sticky one-line breadcrumb bar shows the heading ancestry of the heading currently at the top of the visible editor viewport.
- Segments are clickable links that jump to the respective heading.
- Visible if the `showHeadingBreadcrumb` setting is enabled (default on).
- The breadcrumb is pinned to the `#app` scrollbox element for single documents or per pane in multi-pane mode.

### Data Flow for Outline Navigation

The following modules coordinate to implement outline navigation:

- `editor/headings.ts`: Exports `collectHeadings(doc)` to produce a flat list of all headings in doc order.
- `editor/nav-panel.ts`: The `NavigationPanel` React component renders the nav panel with collapse state, selection, drag-drop, and filtering features.
- `editor/heading-breadcrumb.ts`: Provides `computeBreadcrumbPath(headings, pos)` to compute the breadcrumb ancestry chain.
- `editor/heading-breadcrumb-bar.ts`: The `HeadingBreadcrumbBar` component renders the sticky breadcrumb bar and tracks scroll position.
- Clicks into headings use `precise-scroll.ts`'s `scrollToHeadingId` for smooth scrolling.
