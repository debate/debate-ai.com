This page details the administrative functionalities and the `AdminDashboard` component within the `debate-ai.com` application. It covers API routes for managing YouTube videos (listing, publishing, and bulk publishing), retrieving an overview of system statistics, managing topic starters, seeding video data, and the reuse-check log purge endpoint, including its scheduled worker.

## AdminDashboard Component

The `AdminDashboard` component [apps/debate-ai.com/components/admin/AdminDashboard.tsx29-372](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/components/admin/AdminDashboard.tsx#L29-L372) provides a centralized interface for platform administrators. It facilitates management of YouTube videos, system analytics, topic starter imports, and reuse-check log retention.

### State Management

Key state variables and hooks:

- `videos`: List of `YoutubeRoundVideo` objects queued for publication [line 31].
- `nextCursor`: Cursor string for keyset pagination of video lists [line 32].
- `style`: Current filter for debate styles (Policy, PF, LD, College) [line 33].
- Boolean flags such as `isLoading`, `isLoadingMore`, `isResyncing`, `isPublishingAll`, `isPurgingReuseLog` track various async operations [lines 34–44].
- `lastRun`: Information about the latest YouTube resync run [line 37].
- `pendingIds`: Set of video IDs currently in publishing or deletion process [line 41].
- `rowErrors`: Per-video error messages [line 42].
- `reuseLogPurgeResult` and `reuseLogPurgeError`: Feedback on reuse-check log purge [lines 43–45].

These states are managed primarily by React hooks: `useState`, `useCallback`, and `useEffect`.

### YouTube Video Management

The admin dashboard embeds a paginated and filterable video queue from YouTube rounds (round debate videos inbound from resync):

#### Listing Videos

- The function `loadFirstPage(styleFilter)` fetches the initial page or reloads data on style change by GET `/api/admin/youtube/videos` with optional style query [lines 49-63, 84-85].
- The `loadMore` function implements infinite scroll loading triggered by an `IntersectionObserver` linked to a bottom sentinel element ref [lines 66-81, 88-110].
- Pagination is keyset-based, using `(publishedAt, id)` encoded cursor, avoiding offset-based inconsistencies [app/api/admin/youtube/videos/route.ts10-90](https://github.com/debate/debate-ai.com/blob/34937310/app/api/admin/youtube/videos/route.ts#L10-L90)
- Filtering by style (Policy, PF, LD, College) is supported [lines 46-49].

#### Publishing Individual Videos

- `handlePublish(id)` sends a `POST` to `/api/admin/youtube/videos/[id]` to publish a single video [lines 138-159].
- After successful publish, the video is removed from the local list.
- Any errors per video are stored in `rowErrors`.

#### Deleting Individual Videos

- `handleDelete(id)` sends a `DELETE` to `/api/admin/youtube/videos/[id]` to remove a queued video without publishing [lines 161-176].
- Similarly updates UI state for in-progress actions and errors.

#### Bulk Actions: Resync and Publish-All

- `handleResync()` triggers a YouTube resync by POST `/api/admin/youtube/resync`, fetching the latest channel videos into the queue [lines 111-135].
- `handlePublishAll()` publishes all videos currently queued by POST `/api/admin/youtube/videos/publish-all` and clears the queue upon success [lines 200-220].

### System Overview

The dashboard fetches global site statistics by GET `/api/admin/overview`, including user counts, session totals, files, and video publish stats. Recent users are also shown [lines 222-236].

### Topic Starter Upload

The `TopicStarterUpload` component [apps/debate-ai.com/components/admin/TopicStarterUpload.tsx](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/components/admin/TopicStarterUpload.tsx) integrated into the dashboard enables bulk DOCX or ZIP uploads of new topic starters organized in folders, published to CardMirror for all users. The server-side importer is at `/api/admin/topic-starters`[apps/debate-ai.com/app/api/admin/topic-starters/route.ts](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/admin/topic-starters/route.ts)

### Reuse-Check Log Retention

To prevent unbounded growth of the `reuse_check_log`, the dashboard offers a manual purge button to delete old entries. The retention duration is driven by `REUSE_CHECK_LOG_RETENTION_DAYS` (default 180 days) [lines 20, 240-259].

Invoking purge sends `POST /api/admin/evidence-reuse-check-log/purge`, which calls the purge logic deleting expired rows from the database [apps/debate-ai.com/lib/evidence-reuse-check/purge-reuse-check-log.ts](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/evidence-reuse-check/purge-reuse-check-log.ts)

## UsersTable Component & Usage Analytics

The `UsersTable` component provides a detailed paginated view of all user accounts, their activity, and usage metrics across multiple features.

### Data Fetching & Pagination

- Fetches data from `/api/admin/users` with support for search, pagination, filter for anonymous users, and sorting [apps/debate-ai.com/components/admin/UsersTable.tsx95-352](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/components/admin/UsersTable.tsx#L95-L352)
- The `/api/admin/users` route aggregates usage counters by querying correlated counts across tables such as documents, flows, saved rounds, judging decisions, speeches, practice rounds, and drills [apps/debate-ai.com/app/api/admin/users/route.ts9-45](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/admin/users/route.ts#L9-L45)

### Sorting & Filtering

- Columns include user info and multiple usage metrics, sortable by admin interaction.
- Usage counters correspond to specific tables in the database and are computed by correlated subqueries to prevent row fan-out [lib/admin/user-usage.ts28-154](https://github.com/debate/debate-ai.com/blob/34937310/lib/admin/user-usage.ts#L28-L154)
- Search supports filtering by name/email and toggle to hide anonymous accounts.

### UI Behavior

- Debounced search input with delay to limit request frequency.
- Sort toggles between ascending/descending; first click sorts descending except for alphabetical columns.
- Displays summary tile counts for aggregated totals over site-wide data.
- Date formatting includes relative "how long ago" for last active time to highlight dormant users.

## API Routes

### `/api/admin/youtube/videos`

Handles listing queued YouTube round videos.

#### GET

- Authenticates admin users.
- Supports keyset pagination via cursor roughly representing `(publishedAt, id)` of last fetched row.
- Allows filtering by style, channel, and search query over title and channel name.
- Excludes videos already published by left-joining with `videos` table and filtering out matches.
- Returns array of videos and next cursor for infinite scroll.

Implementation references cursor encoding/decoding functions to support consistent pagination [apps/debate-ai.com/app/api/admin/youtube/videos/route.ts10-90](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/admin/youtube/videos/route.ts#L10-L90)

### `/api/admin/youtube/videos/[id]`

Handles operations on a single video.

#### POST

- Publishes the specified video by:

- Validating admin access.
- Fetching the video details from `youtubeRoundVideos`.
- Calling `publishRoundVideos` to migrate it into published `videos` table.
- Deleting from resync queue.

#### DELETE

- Authenticates admin.
- Deletes video entry from resync queue without publishing.

### `/api/admin/youtube/videos/publish-all`

- Publishes all queued videos in bulk.
- Authenticates admin.
- Bulk retrieves `youtubeRoundVideos`.
- Passes all to `publishRoundVideos`.
- Deletes all queued entries afterwards.

### `/api/admin/youtube/resync`

- Triggers a manual resynchronization to fetch fresh YouTube round videos from configured channels.
- Calls `resyncYouTubeRounds(null)` which accesses YouTube APIs, retrieves channels/videos data, and upserts into `youtubeRoundVideos` table.

### `/api/admin/overview`

- Provides aggregate statistics about the platform:

- Total users, sessions, files, published videos, staged (queued) videos.
- Recent list of users with key metadata.

### `/api/admin/topic-starters`

- Supports admin uploads of DOCX or ZIP containing topic starters for the research/Reason Editor.
- Parses uploaded files into HTML cards and inserts into `topicStarterItems` table.
- Handles nested folder hierarchy mirroring ZIP structure.
- Provides detailed error reporting per file in import batches.

### `/api/admin/videos/seed`

- Triggers seeding of video data for development or initial database population.
- Admin-only.

### `/api/admin/evidence-reuse-check-log/purge`

- Allows admins to immediately purge `reuse_check_log` entries older than retention period.
- Calls `purgeOldReuseCheckLogRows()` which deletes expired log entries in database.
- Retention period stored in constant `REUSE_CHECK_LOG_RETENTION_DAYS` (default 180 days).

## Scheduled Worker for Reuse-Check Log Purge

The `reuse_check_log` table, which records every `GET /api/evidence-reuse-check` lookup, is append-only. To prevent unbounded storage growth, a scheduled worker periodically purges old log entries.

### Worker Configuration

The Cloudflare worker is configured to run weekly at 08:00 UTC on Mondays via the `wrangler.jsonc` configuration [apps/debate-ai.com/wrangler.jsonc27-30](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/wrangler.jsonc#L27-L30):

### Worker Implementation

- The worker's `scheduled` handler [apps/debate-ai.com/worker/index.ts80-91](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/worker/index.ts#L80-L91) runs on the cron trigger.
- It calls `purgeOldReuseCheckLogRows()`, which calculates a cutoff timestamp using `getReuseCheckLogPurgeCutoff()` and executes a D1 database query to delete rows older than that cutoff.
- This scheduled purge runs alongside the YouTube resync task triggered on the same cron [apps/debate-ai.com/worker/index.ts74-79](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/worker/index.ts#L74-L79)
