The `debate-ui` package forms the foundational shared component library and design system used throughout the Debate AI platform. It provides a cohesive set of themed, accessible, and reusable components consumed by all applications and feature packages in the monorepo.

## Purpose and Scope

`debate-ui` is a workspace-level package that centralizes the platform's consistent "look and feel" by abstracting UI primitives, layout frameworks, charts, icons, and utility helpers into one package. This helps feature-specific packages focus purely on business logic with no duplication of UI code or style definitions. It includes:

- **shadcn / Radix UI primitives**: Styled and composable interactive UI elements like buttons, dialogs, tooltips.
- **Charts**: Wrapper components standardizing chart visualizations.
- **Custom icon set**: Debate-specific SVG/PNG icons centrally exported.
- **Layout components**: `Footer`, `Dock`, and other structure helpers.
- **Panel shells**: Shared container components for layouts of feature modules.
- **Feature catalog**: A global features data structure and components.
- **Utility helpers**: The `cn` Tailwind class name merge utility, URL-state management functions.

This package is imported by all the main apps (e.g. `apps/debate-ai.com`) and core feature packages (`debate-videos`, `debate-round`, `debate-editor`, `debate-card-search`).

---

## Architectural Role and Dataflow

`debate-ui` lives at the base of the monorepo UI hierarchy. Its components wrap or compose Radix primitives and provide core building blocks used directly or indirectly by higher-level feature packages which themselves integrate into the main app.

This layered structure reduces duplication, ensures a consistent user experience, and improves maintainability.

## Core Modules in `debate-ui`

### 1. Primitives (`primitives/`)

Containers for styled shadcn/ui and Radix UI primitives. These are minimal wrappers around popular accessible UI patterns such as buttons, dialogs, popovers, tooltips, that conform to Debate AI's design tokens and Tailwind CSS themes.

By re-exporting these primitives centrally, the codebase standardizes interaction and appearance across features.

Sources: [packages/debate-ai-docs/content/docs/packages/debate-ui.mdx35](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-ai-docs/content/docs/packages/debate-ui.mdx?plain=1#L35-L35)

### 2. Charts (`charts/`)

Wrappers around charting libraries (likely recharts) to present statistics and analytics consistently.

Sources: [packages/debate-ai-docs/content/docs/packages/debate-ui.mdx28](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-ai-docs/content/docs/packages/debate-ui.mdx?plain=1#L28-L28)

### 3. Effects (`effects/`)

Houses eye-candy and UX enhancements such as animated motion, glow effects, and spotlight components used to highlight UI areas.

Sources: [packages/debate-ai-docs/content/docs/packages/debate-ui.mdx29](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-ai-docs/content/docs/packages/debate-ui.mdx?plain=1#L29-L29)

### 4. Features (`features/`)

Contains components related to the platform-wide features catalog, supporting the `/features` page and related feature discovery UI. This includes a `FeaturesPanel` component rendering the master list of app features grouped by category.

These icons are embedded throughout the UI: in footers, sidebars, docks, and tool listings.

### 6. Layout Utilities (`layout/`)

This module manages compositional UI elements that form the application's skeleton:

- **Footer**: A global footer component listing legal links, credits, and external references, which resolves internal paths relative to the app origin for correct navigation. It dynamically splits links into two rows for responsive design.
- **Dock System**: Implements a macOS-style dock with magnification effects via `framer-motion`. Core components include `Dock`, `DockIcon`, `DockItem`, and `DockLabel`. The dock supports two layout modes: free-floating sized to content, and fluid mode constrained to sidebar width with wrapping.
- **Category Dock and Grids**: Related components for categorizing features and laying out complex grids.

Sources: [packages/debate-ui/src/layout/footer.tsx7-64](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-ui/src/layout/footer.tsx#L7-L64)[packages/debate-ui/src/layout/dock.tsx1-197](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-ui/src/layout/dock.tsx#L1-L197)

### 7. Utility Library (`lib/`)

Key utility functions and helpers consumed app-wide:

- **`cn`**: A utility function combining `clsx` and `tailwind-merge` to compose conditional and variant-aware Tailwind CSS class strings effortlessly.
- **URL-state helpers**: Functions managing application state directly encoded in the URL, enabling shareable URL views and state persistence without local or server storage.

## Key Implementation Examples

### Resizable Columns Hook (`useResizableColumns`)

The `useResizableColumns` hook encapsulates logic enabling drag-to-resize functionality on table columns, used e.g. by `VideoListRows` in the videos package to resize list columns.

- Maintains a `widths` state map `{ [columnKey]: widthPx }`.
- Tracks the resizing action using refs (`resizingKeyRef`, `resizeStartRef`).
- Listeners on `document` handle mouse/touch move and up events.
- Limits widths between minimum (60px) and maximum (700px).
- Updates widths smoothly during drag.

**Resizable Columns Control Flow**

This hook is invoked from various grid components needing resizable columns.

### Footer Component

The `Footer` component renders a responsive footer with clickable links and icons. It handles:

- Dynamic link arrays (`FOOTER_LINKS`) providing text, href, and SVG icon.
- Internal routes have their href prefixed with `window.location.origin` for absolute URLs.
- External links open in a new tab.
- Two rows layout for better presentation on narrow screens.

## Debating Tools Sidebar Integration

The `debate-videos` package provides the sidebar structure for the Coaching / Research / Practice tools and a tool nav tree which plugs into `AppSidebarShell` in the main app.

- `SIDEBAR_TOOL_SECTIONS` enumerates coaching, research, and practice tool sections with their links and Lucide icons.
- `APP_DOCK_LINKS` specify the main dock destinations (Videos, Shared, Debate, Practice vs AI, Docs).
- `ToolNavTree` renders the sidebar nav tree expanding relevant tool groups based on active path.
- Utilities like `matchesToolSidebarHref()` and `isGenericToolSidebarRoute()` determine if the sidebar or dock should render on a given route.

# Summary

The `debate-ui` package is the essential shared UI toolkit underpinning all feature packages and applications in the Debate AI monorepo. It provides consistent, accessible, and thematic components ranging from design primitives and iconography to layout helpers and shared UI shells.

By centralizing these elements, the codebase maintains high UI consistency, reusability, and scalability, improving developer efficiency and platform UX cohesion.
