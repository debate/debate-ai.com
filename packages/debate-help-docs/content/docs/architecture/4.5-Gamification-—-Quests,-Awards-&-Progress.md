The gamification subsystem in the Debate AI platform is designed to motivate contributors through structured goals, rewards, and performance tracking. It integrates tightly with the CARDS module’s evidence-focused crowdsourcing features, tracking and rewarding contributions daily and over time. This page details the implementation and data flow for **Daily Quests**, **Quest Streaks with lapse reminders**, **Progress Unlock Tiers**, **Contributor Awards**, **Group Challenges**, and **Research Progress Tracking**.

---

## Architectural Overview

Gamification logic is implemented as pure functional slices in the `lib/` directories of relevant packages, composed against persisted state stores, mostly backed by `localStorage`. This structure supports reactive frontends while maintaining deterministic business rules for contributions, streaks, and awards.

## Daily Quests & Streak Tracking

Daily quests embody time-limited, contributor-driven goals like "Add 3 frontline answers today" that encourage sustained engagement.

### Core Models and Logic

- **Quest Templates (`QuestTemplate`)** define what contributions count toward a quest, specifying:

- Target kind (e.g., `card`, `annotation`)
- Argument block (`argBlock`) optionally narrowing scope
- Target count (number of qualifying contributions needed)
- Optional expiration date (`expiresOn` as YYYY-MM-DD)
- Recurrence cadence (`daily` or `weekly`) to roll expired quests forward automatically
- Difficulty tier (`easy`, `medium`, `hard`) with associated point values for completion rewards
These are managed in persistent storage through `state/dailyQuests.ts` and their core logic lives in `lib/daily-quests.ts`.
- **Progress Computation**`computeQuestProgress` computes how many qualifying contributions a contributor made on a given UTC calendar day, marking quests complete when the target is reached.
- **Quest Board and Team Competitions**`buildPersistedDailyQuestBoard` combines stored templates with real contributions and handles quest expiry rollovers. Team quest competitions aggregate scores of contributors grouped into named teams.
- **Mission Results**
Once a contributor completes their daily quests, a `DailyMissionResult` is persisted via `state/dailyMissionResults.ts`, which tracks which contributor completed what quests on what days.

### UI Integration: `DailyQuestsPanel`

Implemented in `panels/DailyQuestsPanel.tsx`, this client component renders the live quest board for the current day, allowing contributors to:

- View all active quests with progress bars and completion status
- Add custom quests with description, contribution kind, target counts, expiry, recurrence, and difficulty
- Seed quests automatically from under-covered topic arguments using Topic Coverage Dashboard data
- Clean up expired quests or roll over recurring quests automatically
- Participate in team quest competitions displaying team scores and member contributions
- Record today's quest mission result and view streak rewards on the same panel
- See their current streak status and receive nudges to maintain streaks
Cross-tab sync is supported via listening to `localStorage` events, keeping quest boards consistent across browser tabs.

## Quest Streaks & Lapse Reminders

A **quest streak** tracks consecutive days a contributor has completed all their daily quests.

### Features

- Streaks record current and longest streaks, track milestone badges for durations (3, 7, 14, 30 days), and can be frozen using **streak freezes** to prevent resets.
- **Streak Freeze (Grace Day):** Contributors can spend streak freezes for one missed day to maintain streak continuity. Freeze counts replenish over a 30-day rolling window.
- **Streak-Lapse Reminder:** Contributors can opt-in for a UI reminder banner that warns them if their streak is at risk of lapsing today (i.e., in-progress streak but no quests completed today yet).
- Signed-in users automatically get a prefilled contributor ID field, allowing personalized streak tracking and freeze/reminder sync across devices.

### Implementation Details

- Streak computations and badges are handled by `lib/gamified-quests.ts`.
- Freeze state is persisted per contributor and day in `state/streakFreezes.ts`.
- Reminder opt-in flags are persisted in `state/streakLapseReminders.ts`.
- The `QuestStreaksPanel.tsx` renders a roster of all contributors and their streak status, with actions to run today's mission check and apply freezes.

## Progress Unlock Tiers

Contributors "unlock" tiers that grant different research-task skill levels, combining raw contribution counts and routed research task completions.

### Unlock Tier Logic

- Tiers are Novice, Apprentice, Veteran, and Expert, each enabling progressively harder tasks.
- Unlock tier calculations consider:

- **Contribution volume and helpfulness score**: Aggregated in `state/contributions.ts` and processed by `lib/progress-unlocks.ts`.
- **Completed routed research tasks**: Persisted in `state/researchProgress.ts` and factored into tier computation enabling unlocks by completion alone.
- The unlock state also integrates daily quest streak badges.

### Panel and Data Flow

`ProgressUnlocksPanel.tsx` renders a roster of contributors by alphabetical order with tier, badges, task completions, and progress bars toward the next tier.

## Contributor Awards

Contributor awards highlight top contributors in each contribution category, recognizing excellence.

### Award Categories

- Categories correspond to `ContributionKind`s: card, summary, highlight, annotation, original argument, refutation.
- Each category shows the contributor with the highest total helpfulness score.
- A daily "announce" feature freezes current standings to prevent fluctuation throughout the day.

### Peer Nominations and Support

- Peers can nominate contributors informally.
- Supporters may "second" nominations, aggregating support counts displayed on the UI.
- Nomination and seconding logic prevents self-nomination and duplicate seconds.

### Data Flow and Rendering

- Awards are computed live from `state/contributions.ts` with pure logic in `lib/contributor-awards.ts`.
- Announcements are persisted in `state/contributorAwardAnnouncements.ts`.
- The UI `ContributorAwardsPanel.tsx` subscribes to cross-tab updates, rendering live standings, historical announcements, and the Hall of Fame.

## Group Challenges and Win Events

Group Challenges enable squad competitions with goals like reaching contribution targets or win counts.

### GroupChallenge Model

- Defined in `state/groupChallenges.ts`, each challenge includes:

- Title, description, challenge type (`contribution_target` or `win_target`)
- Challenge window (`startsAt`/`endsAt`)
- Squad roster of contributors (`memberIds`)
- Win events are flat records in `state/challengeWinEvents.ts`, scoped to contributors and timestamped.

### Progress Tracking

- The live standings are computed via `buildPersistedGroupChallengeBoard`, aggregating matching contributions and win events against roster and challenge window.
- Contributors can record wins manually through UI action with free-text contributor ID input.

### UI Behavior: `GroupChallengesPanel`

- Renders each group's current progress and leader.
- Allows recording new win events.
- Features signed-in prefill of contributor ID in win forms.

## Research Progress Tracking

This feature presents a comprehensive view of contributors' research efforts across topics, displaying both contribution counts and routed task completions.

### Displayed Data

- Contributor IDs.
- Contribution counts and total helpfulness scores (`lib/contribution-leaderboard.ts`).
- Routed task completion and assignment counts (`lib/research-progress.ts`).
- Topic-level progress with completed vs. assigned tasks.

### Data Flow and Persistence

- Marking a task complete (`completeAndRecordResearchTask`) records a persisted completion with `completedAt` timestamps in `state/researchProgress.ts`.
- Active tasks tracked in `state/routedTaskQueues.ts`.
- Contributions persist in `state/contributions.ts`.
- The `buildPersistedResearchProgressBoard` function merges these data to supply the rendering panel.

## Cross-Tab Live Synchronization

All gamification-related UI panels register listeners for the `storage` event to detect changes to persistent stores across different open tabs/windows.

- Dedicated helpers in `state/live-update.ts` determine if a `storage` event concerns data relevant to a particular panel (e.g., quests, streaks, awards, progress).
- When a matching event occurs, affected panels reload their persisted data and re-render, ensuring consistent state.

This pattern is ubiquitous across the gamification suite, closing a long-standing "lack of cross-tab sync" gap.
