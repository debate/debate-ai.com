This page documents the API endpoints responsible for serving video archives, historical debate metadata, and reference datasets. These routes serve as a bridge between the flat-file JSON database managed by `debate-data-sync` and the SQL-backed video library used for paginated delivery in the LEARN module.

## Overview of Content Delivery

The system has transitioned from a purely static JSON-serving model to a hybrid SQL-backed architecture. While the JSON assets in `debate-data-sync/data/videos/` remain the source of truth for the YouTube ingestion pipeline, they are now projected into a `videos` SQL table (Cloudflare D1 in production, SQLite in development) to support efficient server-side filtering, search, and pagination [docs/features/video-library.md13-17](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/video-library.md?plain=1#L13-L17)

## Video API (`/api/videos`)

The `/api/videos` route provides a paginated feed of debate rounds and lectures. It replaces the legacy model where the entire 1.1MB JSON dataset was downloaded on first paint [apps/debate-ai.com/app/api/videos/route.ts8-13](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/videos/route.ts#L8-L13)

### Query Parameters

The endpoint supports extensive filtering pushed down into the SQL layer:

| Parameter | Description | Example Values |
| --- | --- | --- |
| `source` | Video source type filter | `round`, `lecture`, `all`[apps/debate-ai.com/app/api/videos/route.ts32-33](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/videos/route.ts#L32-L33) |
| `style` | Numeric debate style filter (1 to 4) | `2`, `3`[apps/debate-ai.com/app/api/videos/route.ts35](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/videos/route.ts#L35-L35) |
| `year` | Season year or legacy | `2026`, `legacy`[apps/debate-ai.com/app/api/videos/route.ts46](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/videos/route.ts#L46-L46) |
| `q` | Free-text search on title, channel, description | `finals`, `government`[apps/debate-ai.com/app/api/videos/route.ts47](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/videos/route.ts#L47-L47) |
| `facets` | Set to `1` to return counts for season/style dropdowns | `1`[apps/debate-ai.com/app/api/videos/route.ts26](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/videos/route.ts#L26-L26) |

### Implementation & Fallback

The route uses `getVideoPage()` from the video repository for fetching filtered data:

- **SQL Backend:** Executes a `SELECT` with dynamically built `WHERE` filters using `buildConditions()` that push filtering and pagination into the SQL query [apps/debate-ai.com/lib/videos/video-repository.ts126-155](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/videos/video-repository.ts#L126-L155)
- **JSON Fallback:** If the SQL table is not seeded or unavailable, it falls back to in-memory filtering of JSON assets via `getVideoRowsFromJson()` and `queryVideoRows()` providing identical semantic results to clients. The response includes a `backend` field indicating `"sql"` or `"json"` as the data source [apps/debate-ai.com/lib/videos/video-repository.ts5-8](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/videos/video-repository.ts#L5-L8)[apps/debate-ai.com/lib/videos/video-repository.ts35-50](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/videos/video-repository.ts#L35-L50)

## YouTube Transcript API (`/api/transcript`)

This route fetches a YouTube video's transcript, powering the synchronized transcript modal seen in the LEARN module [apps/debate-ai.com/app/api/transcript/route.ts1-72](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/transcript/route.ts#L1-L72)

### Request Parameters & Validation

- Requires a query parameter `videoId` validated as an 11-character YouTube video ID using regex [apps/debate-ai.com/app/api/transcript/route.ts13-34](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/transcript/route.ts#L13-L34)
- Optional `lang` parameter defaults to `"en"`.

### Transcript Fetching Logic

- Uses InnerTube's `player` API with mobile client user-agents to get caption tracks, overcoming YouTube's bot detection limitations [apps/debate-ai.com/lib/youtube/transcript.ts22-200](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/transcript.ts#L22-L200)
- Ranks caption tracks by language and reliability (human captions preferred over auto-generated).
- Supports parsing two formats of caption payload: JSON3 and legacy XML.

### Caching & Error Handling

- Employs an Edge Cache (`globalThis.caches?.default`) to store fetched transcripts and serve repeat requests quickly [apps/debate-ai.com/app/api/transcript/route.ts20-39](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/transcript/route.ts#L20-L39)
- Implements graceful error handling:

- `TranscriptUnavailableError` triggers a 404 response with transcripts-not-available message.
- Rate-limit responses from YouTube (e.g., "not a bot" errors) result in a 503 with no cache to allow rapid retries [apps/debate-ai.com/app/api/transcript/route.ts49-70](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/transcript/route.ts#L49-L70)
- Sets cache-control headers to optimize for both public caching and quick invalidation when necessary.

### Client-Side Integration

The `useTranscript` React hook in `packages/debate-videos` uses this API to retrieve and cache transcripts for synchronized display in components like `TranscriptModal`[packages/debate-videos/src/components/transcript-modal/useTranscript.ts59-88](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/components/transcript-modal/useTranscript.ts#L59-L88)[packages/debate-videos/src/components/transcript-modal/TranscriptModal.tsx30-174](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/components/transcript-modal/TranscriptModal.tsx#L30-L174)

## Admin & Sync Routes

### `/api/admin/videos/seed`

An admin-gated endpoint to seed the `videos` SQL table from bundled JSON assets [apps/debate-ai.com/app/api/admin/videos/seed/route.ts21-30](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/admin/videos/seed/route.ts#L21-L30)

- **POST:** Runs `seedVideosIntoDb()` which performs bulk `INSERT ... ON CONFLICT` statements constructed by `buildVideoSeedStatements()` to upsert all video records. The operation is idempotent and prunes stale records [packages/debate-data-sync/src/videos/video-seed-sql.ts133-175](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/videos/video-seed-sql.ts#L133-L175)[apps/debate-ai.com/lib/videos/seed-videos-to-db.ts44-57](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/videos/seed-videos-to-db.ts#L44-L57)
- **GET:** Returns current table row counts and whether the video feed is served from SQL or still falling back to JSON [apps/debate-ai.com/app/api/admin/videos/seed/route.ts50-68](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/admin/videos/seed/route.ts#L50-L68)

### `/api/sync-videos`

Endpoint triggers the YouTube sync process, updating the JSON assets in `debate-data-sync/data/videos/`. Note that re-seeding the SQL table is required to surface new videos in `/api/videos` pagination [docs/features/video-library.md116-118](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/video-library.md?plain=1#L116-L118)

### `/api/video-issues`

Viewer reports about a video (`POST`, open to signed-out viewers), listed and
resolved by admins and moderators (`GET`, `PATCH`). Rows live in the
`video_issues` table.

Two `kind`s are **change requests** from the watch page's edit button rather
than reports: `edit` (with a `proposedChanges` object) and `delete` (with an
optional `reason`). They require a signed-in account, keep only the fields a
viewer may propose (`lib/videos/video-change-requests.ts` —
`sanitizeProposedChanges`), store an edit's fields as JSON in `issue`, and drop
an in-app notification on every admin and moderator. Nothing changes on the
video until a moderator presses **Apply** / **Delete video** in the admin
panel's Reports card. `GET /api/admin/videos/library/{id}` is public so the
viewer's dialog can load the row; writes on that route stay staff-only.
