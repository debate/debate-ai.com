This page details the implementation of the Shared Evidence Library and Argument Library, focusing on how evidence is stored, searched, and reused across the platform. It covers the search and scoring mechanisms, the `EvidenceLibraryPanel` UI, argument library collections, and the on-page card reuse check functionality, including its server-backed components and retention policies.

---

## Evidence Library (CARDS)

The Evidence Library serves as the submission and search interface for research artifacts. It distinguishes between `card` entries (evidence with citations) and `block` entries (team-drafted analytics) [packages/debate-search-evidence/src/lib/shared-evidence-library.ts48-49](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/lib/shared-evidence-library.ts#L48-L49)

### Implementation & Data Flow

The library is managed primarily through the `EvidenceLibraryPanel`, which handles submission, search, and editing of evidence entries. Data is persisted primarily to `localStorage` via the `state/evidenceLibraryEntries.ts` module, ensuring speedy client-side search and offline capability [packages/debate-search-evidence/src/panels/EvidenceLibraryPanel.tsx1-114](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/EvidenceLibraryPanel.tsx#L1-L114)

**Key Components:**

- **Submission Form:**
Captures fields including `kind` (card or block), `topic`, `caseArea`, `argBlock` (argument block), `cite` (citation), `tags`, free-text `text` body, and an optional `sourceUrl`. The form automatically computes the `wordCount` from the submitted text to provide a depth-of-coverage metric [packages/debate-search-evidence/src/panels/EvidenceLibraryPanel.tsx47-50](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/EvidenceLibraryPanel.tsx#L47-L50)[packages/debate-search-evidence/src/lib/shared-evidence-library.ts108-111](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/lib/shared-evidence-library.ts#L108-L111)
- **Search Interface:**
Offers a free-text search box with filters for kind, topic, case area, and tags. Search results include inline badges indicating relevance and the presence of stale evidence [docs/features/evidence-library.md15-31](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/evidence-library.md?plain=1#L15-L31)
- **Peer-Review Gating:**
Entries are filtered through an `isCardLive` predicate to include only peer-reviewed, officially published cards in general search results [packages/debate-search-evidence/src/panels/EvidenceLibraryPanel.tsx45-47](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/EvidenceLibraryPanel.tsx#L45-L47)
- **Stale Evidence Badges:**
Cards whose citations are older than a threshold (`STALE_EVIDENCE_THRESHOLD_YEARS`) or whose citation years cannot be parsed are labeled as "Stale evidence," signaled via `getEvidenceStaleness`[docs/features/evidence-library.md25-29](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/evidence-library.md?plain=1#L25-L29)[packages/debate-search-evidence/src/lib/shared-evidence-library.ts45-47](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/lib/shared-evidence-library.ts#L45-L47)
- **Reuse Check:**
A "Check this page" box allows contributors to paste a URL and check if cards have already been cut from that page (see "On-Page Card Reuse Check" below). This feature calls both a local browser-side reuse check and an asynchronous remote check against a server-backed reuse index [docs/features/evidence-library.md71-118](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/evidence-library.md?plain=1#L71-L118)

### Search and Scoring

The core search logic resides in `searchEvidenceLibrary` (defined in `lib/shared-evidence-library.ts`). It performs a multi-stage filtering and ranking:

- **Filtering:**
Filters repository entries by `kind` (card/block), `topic`, `caseArea`, and tags (`tags` + `tagMode` — any or all) to narrow down candidates.
- **Ranking:**
When a free-text query is present, entries are ranked by keyword-overlap relevance (`scoreRelevance`) computed from entry fields (`text`, `argBlock`, and `cite`), with zero relevance entries dropped.
- **Output:**
Returns an ordered list of `EvidenceSearchResult` items, including relevance scores for UI display [packages/debate-search-evidence/src/lib/shared-evidence-library.ts124-146](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/lib/shared-evidence-library.ts#L124-L146)

## Argument Library Browser

The Argument Library provides a structured view of the evidence library, organizing flat entries into a hierarchical browser of topic folders and tag collections.

### Composition and Organization

The argument library is composed by merging two persisted data sources to create a unified, browsable representation:

1. **Evidence Library Entries:** Persisted entries in the `evidenceLibraryEntries` localStorage store.
2. **Contributions Feed:** Contributions (general submissions) from `state/contributions.ts` that have associated `topic` and `caseArea` tags.

This combination is built by `buildCombinedPersistedArgumentLibrary`[docs/features/evidence-library.md51-60](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/evidence-library.md?plain=1#L51-L60) and rendered in the `ArgumentLibraryPanel`.

### Structural Hierarchy

- **Topic Folders:** Arguments are grouped by debate topic, each split into case-area subgroups such as "DA," "CP," and "Case" [docs/features/evidence-library.md54-56](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/evidence-library.md?plain=1#L54-L56)
- **Cross-Cutting Tag Collections:** Shows collections of cards sharing common tags to facilitate navigation across topics.

### Tag Management

Tag management tools in the argument library include:

- **Tag Suggestions:** As users type tags in the submission form, `suggestTags` ranks persisted tags based on prefix matches to assist autocomplete [docs/features/evidence-library.md40-46](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/evidence-library.md?plain=1#L40-L46)
- **Bulk Tag Editing:** The `EvidenceLibraryPanel` supports bulk tag addition/removal across selected search/filter results, using `bulkEditTagsForPersistedEntries`[packages/debate-search-evidence/src/panels/EvidenceLibraryPanel.tsx80-88](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/EvidenceLibraryPanel.tsx#L80-L88)

### Live Update

The `ArgumentLibraryPanel` subscribes to the browser's `storage` event to detect changes made in other tabs (e.g., new submissions, tag edits) and refreshes its view immediately [packages/debate-search-evidence/src/panels/ArgumentLibraryPanel.tsx91-108](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/ArgumentLibraryPanel.tsx#L91-L108)

## On-Page Card Reuse Check

The reusable card check system helps contributors avoid duplicate research by identifying if a given page URL has already been cut into a card.

### Core Logic

All normalization and lookup logic is implemented purely in `lib/shared-evidence-library.ts` as testable functions:

- **URL Normalization:**`normalizeSourceUrl` removes the URL scheme (`http`/`https`), leading `www.`, trailing slashes, query strings, and fragments, and lowercases the URL for consistent matching. This ensures `https://www.example.com/article/?utm_source=x` and `http://example.com/article` normalize identically [packages/debate-search-evidence/src/lib/shared-evidence-library.ts143-174](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/lib/shared-evidence-library.ts#L143-L174)
- **Lookup:**`findEntriesBySourceUrl` searches persisted entries whose normalized `sourceUrl` matches the normalized query URL [packages/debate-search-evidence/src/lib/shared-evidence-library.ts177-185](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/lib/shared-evidence-library.ts#L177-L185)
- **Check Wrapper:**`checkPageForExistingCards` returns a summary object `{ url, alreadyCut, matches }` suitable for UI display [packages/debate-search-evidence/src/lib/shared-evidence-library.ts200-206](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/lib/shared-evidence-library.ts#L200-L206)

### Web Application Integration

Within the `/cards/library` route, `EvidenceLibraryPanel` renders a "Check this page" box:

- Performs a **local check** against persisted browser `localStorage` entries with `checkPersistedPageForExistingCards`.
- Fires an **asynchronous remote check** querying the server-backed shared reuse index with `checkRemotePageForExistingCards` for team-wide status.
- Records each lookup to a local history log (`reuseCheckHistory`), displaying recent checks and allowing recheck on click.
- Submits new or edited entries' `sourceUrl` into the shared index on submit [docs/features/evidence-library.md70-120](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/evidence-library.md?plain=1#L70-L120)[packages/debate-search-evidence/src/panels/EvidenceLibraryPanel.tsx26-34](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/EvidenceLibraryPanel.tsx#L26-L34)

### Server-Backed Reuse Index and API

A D1-backed server-side API (`/api/evidence-reuse-check`) manages a central reuse index:

- **Database Table:**`evidence_reuse_index` stores indexed entries with minimal fields (`id`, `sourceUrl`, `normalizedUrl`, `cite`, `argBlock`, `topic`, `contributorId`).
- **GET Endpoint:** Queries reuse status of a normalized URL, returns matches and a flag if previously cut [apps/debate-ai.com/app/api/evidence-reuse-check/route.ts62-99](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/evidence-reuse-check/route.ts#L62-L99)
- **POST Endpoint:** Registers or updates a reuse index entry, keyed by `id` to avoid duplication [apps/debate-ai.com/app/api/evidence-reuse-check/route.ts101-148](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/evidence-reuse-check/route.ts#L101-L148)
- **URL Normalization:** Reimplemented internally in this API to avoid heavy dependencies [apps/debate-ai.com/app/api/evidence-reuse-check/route.ts29-38](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/evidence-reuse-check/route.ts#L29-L38)

### Browser Extension (`apps/debate-web-ext`)

An independent MV3 browser extension calls the `GET /api/evidence-reuse-check` for the active tab's URL, providing near-instant team-wide reuse status. It includes options for:

- Configuring the API base URL.
- A skip-check domain whitelist to avoid querying on trusted or irrelevant domains.
- Automatic reuse checks on popup open or manual trigger [docs/features/on-page-card-reuse-search.md48-106](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/on-page-card-reuse-search.md?plain=1#L48-L106)

### Reuse Check Log & Dashboard

Every `GET /api/evidence-reuse-check` call appends an entry to `reuse_check_log` (another D1 table) capturing URL, normalized URL, whether already cut, match count, source ("web" or "extension"), and timestamp.

- **Dashboard Endpoint:**`/api/evidence-reuse-check/dashboard` aggregates recent flagged entries (max 2000 rows), grouping by normalized URL, counting flags and sources, and sorting by frequency [packages/debate-search-evidence/src/lib/shared-evidence-library.ts300-329](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/lib/shared-evidence-library.ts#L300-L329)[apps/debate-ai.com/app/api/evidence-reuse-check/dashboard/route.ts1-20](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/evidence-reuse-check/dashboard/route.ts#L1-L20)
- **UI:**`EvidenceLibraryPanel` renders this "Team reuse dashboard" as a summary view to help coaches monitor reuse patterns [packages/debate-search-evidence/src/panels/EvidenceLibraryPanel.tsx99-110](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/EvidenceLibraryPanel.tsx#L99-L110)[packages/debate-search-evidence/src/hooks/useReuseCheckDashboard.ts30-60](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/hooks/useReuseCheckDashboard.ts#L30-L60)

### Retention Purge Worker

To limit data growth:

- `getReuseCheckLogPurgeCutoff` computes a timestamp cutoff from a retention period, defaulted to 180 days [`REUSE_CHECK_LOG_RETENTION_DAYS`] [packages/debate-search-evidence/src/lib/shared-evidence-library.ts331-334](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/lib/shared-evidence-library.ts#L331-L334)
- `purgeOldReuseCheckLogRows` deletes entries older than the cutoff from the `reuse_check_log` table [apps/debate-ai.com/lib/evidence-reuse-check/purge-reuse-check-log.ts18-37](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/evidence-reuse-check/purge-reuse-check-log.ts#L18-L37)
- This purge runs weekly via the cloud worker's `scheduled` handler [apps/debate-ai.com/worker/index.ts87-90](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/worker/index.ts#L87-L90)
- Can be manually triggered from the Admin Dashboard via a `POST` API route [apps/debate-ai.com/app/api/admin/evidence-reuse-check-log/purge/route.ts1-28](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/admin/evidence-reuse-check-log/purge/route.ts#L1-L28)

## Topic Coverage Dashboard

While not directly part of the Evidence Library, the Topic Coverage Dashboard complements it by tracking a topic's argument checklist and showing which arguments are well-covered, thin, or missing based on the persisted evidence entries.

- Tracks topic-specific argument blocks (`state/trackedArguments.ts`), combines live persisted entries from the Evidence Library and Contributions Feed into coverage reports (`lib/topic-coverage.ts`).
- Graphically displays argument coverage, missing/thin/covered classifications, and includes snapshot history and cross-topic heatmaps [docs/features/topic-coverage-dashboard.md1-121](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/topic-coverage-dashboard.md?plain=1#L1-L121)[packages/debate-search-evidence/src/panels/TopicCoverageDashboardPanel.tsx1-140](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/TopicCoverageDashboardPanel.tsx#L1-L140)

## Summary

The Evidence Library and Argument Library form the cornerstone of Debate AI's research crowdsourcing infrastructure. Through a combination of client-side persistence, pure utility functions, and server-backed indexing APIs, the platform enables:

- Efficient evidence submission, tagging, and full-text search with relevance scoring.
- A unified argument library that blends official evidence with crowd contributions.
- A robust system to prevent research duplication through on-page reuse checking.
- A team-wide dashboard and logs tracking reuse check activity and trends.
- An automated retention policy ensuring storage remains performant over time.
- A browser extension that integrates seamlessly with this reuse-check infrastructure.

This layered architecture balances responsiveness, collaborative integrity, and data longevity, supporting teams in building and maintaining a comprehensive, non-redundant evidence corpus.
