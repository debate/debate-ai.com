The YouTube Sync & Video Seeding Pipeline is a multi-stage ETL (Extract, Transform, Load) process responsible for ingesting debate rounds and lectures from YouTube into the platform's flat-file database and subsequently seeding them into a SQL database for performant serving. It handles channel crawling, metadata resolution, heuristic-based classification, and automated persistence.

## Overview and Entrypoints

The pipeline is primarily driven by entrypoints within the `packages/debate-data-sync` package, orchestrated via scripts in `package.json`[packages/debate-data-sync/README.md35-41](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/README.md?plain=1#L35-L41)

1. **`syncYouTubeVideos`**: The primary crawler. It iterates through configured channels, fetches recent uploads, classifies them as rounds or lectures, and merges them into the existing data files [packages/debate-data-sync/README.md63-74](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/README.md?plain=1#L63-L74)
2. **`npm run youtube-stats`**: A post-processing script that recalculates aggregate view stats and updates `data/metadata/youtube-stats.json`[packages/debate-data-sync/README.md38](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/README.md?plain=1#L38-L38)
3. **`npm run youtube-update-views`**: A maintenance script to refresh view counts for previously synced videos in batches [packages/debate-data-sync/README.md39](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/README.md?plain=1#L39-L39)
4. **`resyncYouTubeRounds`**: This function, called by the scheduled worker and admin API, fetches videos from configured channels, classifies them as debate rounds, and upserts them into the `youtube_round_videos` SQL table so the admin page can page through up-to-date results without hitting the YouTube API on every read [apps/debate-ai.com/lib/youtube/resync-rounds.ts31-146](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/resync-rounds.ts#L31-L146)

## Two-Stage Fetch & Metadata Resolution

The YouTube API often returns truncated video descriptions in search results. To ensure accurate classification (which relies on the full description for judge decisions and team names), the pipeline implements a two-stage fetch:

1. **Initial Fetch**: `getVideosForChannel` retrieves basic snippets.
2. **Description Resolution**: The pipeline filters for descriptions ending in `"..."` and calls `fetchFullDescriptions` (using `getVideosByIds`) to retrieve complete descriptions for those specific video IDs [packages/debate-data-sync/README.md68](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/README.md?plain=1#L68-L68) This logic is also present in `resyncYouTubeRounds`[apps/debate-ai.com/lib/youtube/resync-rounds.ts55-62](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/resync-rounds.ts#L55-L62)

## Classification Pipeline

Fetched metadata undergoes classification heuristics implemented in the `src/youtube/parsers/` directory [packages/debate-data-sync/README.md75-117](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/README.md?plain=1#L75-L117)

### 1. Round vs. Lecture Classification

The classifier uses title and description patterns to identify debate rounds versus lectures. For example, presence of "vs", "Finals" in titles or debate jargon like "1AC", "2NR" in descriptions mark rounds [packages/debate-data-sync/README.md110-117](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/README.md?plain=1#L110-L117) The `isRound` function is used in the YouTube round resync to filter rounds [apps/debate-ai.com/lib/youtube/resync-rounds.ts81](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/resync-rounds.ts#L81-L81)

### 2. Round Metadata Parsing

If a video is classified as a round, parsing extracts key fields:

- **`parseDebateStyle`**: Extracts style (Policy: 1, PF: 2, LD: 3, College: 4) [packages/debate-data-sync/README.md84](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/README.md?plain=1#L84-L84)
- **`parseTeams`**: Parses Affirmative and Negative teams [packages/debate-data-sync/README.md83](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/README.md?plain=1#L83-L83)
- **`parseTournament` and `parseRoundLevel`**: Extracts tournament name and round level like Octas, Semis [packages/debate-data-sync/README.md81-82](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/README.md?plain=1#L81-L82)
- **`parseWinner` and `parseJudgeDecision`**: Parses ballot outcomes and judge votes from descriptions [packages/debate-data-sync/README.md85-86](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/README.md?plain=1#L85-L86)

These parsers are called during `resyncYouTubeRounds` for every video deemed a round [apps/debate-ai.com/lib/youtube/resync-rounds.ts83-87](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/resync-rounds.ts#L83-L87)

### 3. Lecture Classification

Lectures are categorized into 17 distinct topics such as "Topic Lectures", "Kritik / Critical Theory", and "Research & Flowing" using the `classifyLecture` function [packages/debate-data-sync/README.md88-109](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/README.md?plain=1#L88-L109)

## YouTube Round Resync (`youtube_round_videos` Table)

The `youtube_round_videos` table is a staging area for newly synced debate rounds from YouTube, providing an up-to-date queue for the admin interface prior to publishing into the main video feed [apps/debate-ai.com/lib/youtube/resync-rounds.ts31-146](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/resync-rounds.ts#L31-L146)

### Triggering Resync

- **Scheduled Cron Job**: Runs every Monday at 08:00 UTC defined in `wrangler.jsonc`[apps/debate-ai.com/wrangler.jsonc24-29](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/wrangler.jsonc#L24-L29)
- **Admin API Endpoint**: Manual trigger via `POST /api/admin/youtube/videos/resync`.

### Resync Process Steps

1. **Start Run**: Inserts a new `youtubeSyncRuns` row marked `"running"` with the trigger metadata [apps/debate-ai.com/lib/youtube/resync-rounds.ts38-41](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/resync-rounds.ts#L38-L41)
2. **Fetch Videos**: Iterates channels, fetches lists, resolves truncated descriptions [apps/debate-ai.com/lib/youtube/resync-rounds.ts47-62](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/resync-rounds.ts#L47-L62)
3. **Deduplicate & Exclude**: Filters duplicates and removes admin-excluded videos based on entries in `youtubeVideoExclusions` table [apps/debate-ai.com/lib/youtube/resync-rounds.ts65-76](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/resync-rounds.ts#L65-L76)
4. **Classification & Parsing**: Classifies rounds, parses metadata fields [apps/debate-ai.com/lib/youtube/resync-rounds.ts78-102](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/resync-rounds.ts#L78-L102)
5. **Upsert Rows**: Inserts or updates rows in `youtube_round_videos` with parsed data [apps/debate-ai.com/lib/youtube/resync-rounds.ts105-111](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/resync-rounds.ts#L105-L111)
6. **Complete Run**: Updates `youtubeSyncRuns` row to `"success"` or `"error"` with stats and error info [apps/debate-ai.com/lib/youtube/resync-rounds.ts115-142](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/resync-rounds.ts#L115-L142)

### Admin API for Managing Staged Rounds

- **List Pending Videos:**`GET /api/admin/youtube/videos` supports keyset pagination and filtering. It excludes any videos already published to the main `videos` table via a LEFT JOIN anti-join [apps/debate-ai.com/app/api/admin/youtube/videos/route.ts29-89](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/admin/youtube/videos/route.ts#L29-L89)
- **Publish Single Video:**`POST /api/admin/youtube/videos/[id]` publishes a staged round to the public `videos` table and removes it from the queue [apps/debate-ai.com/app/api/admin/youtube/videos/[id]/route.ts:13-30]().
- **Delete Single Video:**`DELETE /api/admin/youtube/videos/[id]` removes a round from the queue without publishing [apps/debate-ai.com/app/api/admin/youtube/videos/[id]/route.ts:33-46]().
- **Publish All:** A bulk publish endpoint moves all staged rounds into the `videos` table. This operation uses idempotent upserts to avoid duplication [apps/debate-ai.com/app/api/admin/youtube/videos/publish/route.ts8-31](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/admin/youtube/videos/publish/route.ts#L8-L31)

## SQL Video Table and Seeding

While the JSON assets in `debate-data-sync/data/videos/` are the canonical source of truth, the application serves video data using an SQL `videos` table for efficient querying, filtering, search, and pagination by clients [docs/features/video-library.md3-7](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/video-library.md?plain=1#L3-L7)

### Video Row Construction

JSON assets from multiple files (rounds-policy, pf, ld, college, lectures, top picks) are merged into unified rows of type `VideoRow` by `buildVideoRows` in `debate-data-sync/src/videos/video-rows.ts`[docs/features/video-library.md19-23](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/video-library.md?plain=1#L19-L23)

### Seeding via `seedVideosIntoDb()`

The function `seedVideosIntoDb(db)` performs an idempotent batch upsert of rows from JSON into the `videos` table, then deletes any entries no longer present in the JSON source [lib/videos/seed-videos-to-db.ts44-58](https://github.com/debate/debate-ai.com/blob/34937310/lib/videos/seed-videos-to-db.ts#L44-L58)

Batching logic respects Cloudflare D1's 100 KB max SQL statement size by balancing row count and SQL byte length. This batching is implemented inside `buildVideoSeedStatements`[packages/debate-data-sync/src/videos/video-seed-sql.ts133-175](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/videos/video-seed-sql.ts#L133-L175)

### API Endpoint for Seeding

- **Post Seed:**`POST /api/admin/videos/seed` runs `seedVideosIntoDb()` against the D1 binding in deployment, requiring admin access [apps/debate-ai.com/app/api/admin/videos/seed/route.ts21-47](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/admin/videos/seed/route.ts#L21-L47)
- **Get Status:**`GET /api/admin/videos/seed` returns current row count, last seed time, and indicates whether feed is served from SQL or JSON fallback [apps/debate-ai.com/app/api/admin/videos/seed/route.ts50-73](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/admin/videos/seed/route.ts#L50-L73)

### Idempotency and Pruning

- The upsert uses `ON CONFLICT("video_id") DO UPDATE` to replace existing rows safely [packages/debate-data-sync/src/videos/video-seed-sql.ts153-154](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/videos/video-seed-sql.ts#L153-L154)
- After all batches are applied, an extra statement deletes rows with `updated_at` older than the current run's timestamp, pruning records removed upstream from the JSON [packages/debate-data-sync/src/videos/video-seed-sql.ts172](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/videos/video-seed-sql.ts#L172-L172)
- This approach guarantees that the SQL table reflects the JSON assets exactly after a full seed.

## Admin Video List and Round Publishing

The admin interface for video management uses the `youtube_round_videos` table as a staging queue from which rounds can be published to the main `videos` table.

### Keyset Pagination

`GET /api/admin/youtube/videos` returns keyset-paginated round videos ordered by `publishedAt` then `id` descending, supporting filtering by style, channel, and text query. It filters out any rounds already published to the main feed by performing a left join against the `videos` table and excluding matches [apps/debate-ai.com/app/api/admin/youtube/videos/route.ts29-89](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/admin/youtube/videos/route.ts#L29-L89)

### Publishing and Deletion of Queued Videos

- **Single Video Publish:**`POST /api/admin/youtube/videos/[id]` publishes a single round to the main `videos` table using `publishRoundVideos()`, then deletes it from the queue [apps/debate-ai.com/app/api/admin/youtube/videos/[id]/route.ts:13-30]().
- **Single Video Remove:**`DELETE /api/admin/youtube/videos/[id]` deletes a single queued round without publishing [apps/debate-ai.com/app/api/admin/youtube/videos/[id]/route.ts:33-46]().

These endpoints require admin authentication and provide fine-grained control over which rounds appear in the public library.

# Summary

The pipeline efficiently ingests YouTube content on-demand, classifies and enriches metadata, stages videos for review, and finally projects the video metadata into a performant SQL table. This enables scalable UI browsing, searching, and administrative control over published debate media.
