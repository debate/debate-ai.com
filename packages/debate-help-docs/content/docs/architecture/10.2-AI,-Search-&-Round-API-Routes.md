This page provides a detailed technical overview of the backend API routes powering AI functionality, evidence search, real-time flow collaboration, round and flow cloud save, and user settings. These routes are primarily implemented in the `apps/debate-ai.com` Next.js app and integrate with shared packages such as `debate-round`, `debate-card-search`, and `debate-practice-drills`.

They form the backend interface for core features in the CARDS, FIAT, LEARN, and REASON modules.

---

## AI Analysis Route (`/api/analyze`)

The `/api/analyze` endpoint performs automated logical analysis of debate "cards" (evidence quotes). It applies a Groq + LangChain-based pipeline to identify flaws, assign a support score from 0-10, and summarize evidentiary warrants.

### Implementation Details

- Input: The client sends raw card text (citation + body).
- Prompt: Uses `findFlawsPrompt` defined in `packages/debate-speech-writer/prompts/quote-to-find-flaws.ts` which directs the LLM to produce a compact JSON summary of flaws and a score.
- Model: The LLM processes the prompt and returns structured JSON with a `summary`, `warrants`, numeric `score`, and an array of `flaws`.
- Output: This structured JSON aids UI components like `SearchInterface` in displaying card analysis insights.

## Editor AI Proxy (`/api/reason-ai`)

This route serves as a secure, server-side proxy for the reason-editor package's AI capabilities. It handles citation formatting, OCR repair, AI coaching, and integrates with the LLM Card Scoring system used in the CARDS module.

### Key Points

- Model: Uses Anthropic's `claude-sonnet-4-6` model with request and token size limits for resource safety.
- Security: Requires a valid, authenticated user session.
- Handling: Computes request size considering text content and base64 images to enforce limits.
- Functionality: Passes AI prompts and messages to Anthropic, then returns AI-generated content to client.

### LLM Card Scoring Integration

Via the `requestCardScoringAiAssessment` client in `packages/debate-card-search`, this endpoint performs expert qualitative assessments treating the AI as a debate coach. Results are cached client-side under `aiCardAssessments`.

## Shared Flow Sync Route (`/api/flow-sync`)

The `/api/flow-sync` endpoint backs the collaborative logging and merging of edits to debate flows shared in real time. It supports short-poll GET operations to retrieve recent edits and POST operations to save individual `FlowEdit` records with ID upserts to prevent duplicates.

### Details

- GET requests accept `sinceMs` and `flowId` query parameters and return a capped list of edits newer than `sinceMs`.
- POST requests accept a `FlowEdit` payload, which is validated and merged into the DB with conflict resolution on edit ID.
- Database: The `flow_sync_edits` table stores edits keyed by `id` with fields including `flowId`, `boxPath` (JSON-encoded array), `authorId`, `content`, and timestamp fields.

## Flow Presence Route (`/api/flow-presence`)

This API provides presence heartbeat tracking for collaborators editing the same debate flow. It allows clients to retrieve active collaborators within a recent time window and to update their heartbeat.

### Features

- GET: Returns list of authors with recent heartbeats on a `flowId`.
- POST: Upserts heartbeat for `(flowId, authorId)` pair, updating row timestamp.
- Database: Uses `flow_presence_heartbeats` table keyed by `(flowId, authorId)`.

## Round & Flow Cloud Save Routes (`/api/rounds`, `/api/flows`)

These routes manage persistence of saved debate rounds and flows per user account, enabling cross-device continuity.

### `/api/rounds`

- GET: Lists saved rounds for the user by `clientId`, label, and updated timestamp, ordered descending. Omits full flow data for efficiency.
- DELETE: Deletes a saved round by `clientId` for the authenticated user.
- PUT: Saves or updates a saved round. Uses upsert semantics keyed on `clientId`. Stores full round JSON data in `data` field.

### `/api/flows`

- GET: Lists saved flows similarly (by `clientId`, label, updatedAt).
- DELETE: Deletes a saved flow by `clientId`.
- PUT: Saves or updates a saved flow with full JSON data.

### Database Tables

- `saved_rounds` and `saved_flows` represent these records respectively with fields for `clientId`, `userId`, `label`, `data` JSON, and timestamps.

## Drill Sets Route (`/api/drill-sets`)

/api/drill-sets manages the persistence of user AI-generated practice drill sets.

### Implementation

- GET: Returns all persisted `DrillSetRecord`s for the authenticated user ordered by `updatedAt` descending.
- PUT: Saves or updates a drill set for a given `roundId`. Stores detailed drill data including completion state and AI-generated scripts.
- DELETE: Deletes a drill set by `roundId`.
- Database: Interacts with `saved_drill_sets` table keyed by `(userId, roundId)`.

### Client Integration

The `DrillSetsPanel` and associated `useDrillSets` hook implement a local-first synchronization pattern supporting offline use and seamless cloud merging.

## User Settings Route (`/api/settings`)

Provides account-linked storage and retrieval of user preferences including debate style, font size, color theme, favorite tools, editor preferences, and more.

### Data Operations

- GET: Returns the saved user settings or defaults if no saved data. Each user has one settings row keyed by `userId`.
- PUT: Accepts full or partial patches; validates using normalization functions from `debate-round` and related packages. Supports both full favorite tools lists and atomic add/remove favorite tool operations to avoid race conditions.
- Settings are serialized as JSON strings or primitives in the `userSettings` table.

### Client-Side Integration

- The `UserSettingsPanel` renders a form that applies changes locally immediately and attempts background save to `/api/settings`.
- Theme changes synchronize to localStorage, cookies, and DOM classes to remain consistent across UI surfaces.
- Favorite tools are toggled separately with immediate application and server sync.
- The API requires authenticated sessions and returns 401 without one.

## Cross-Tab Live Update Synchronization

Though not an API route itself, the `state/live-update.ts` module inside packages like `debate-round` and `debate-practice-drills` handles listening for `localStorage` changes in multiple tabs. It contains small, route-specific predicate functions to detect changes relevant to panels such as:

| Panel Component | Storage Keys | Predicate Function |
| --- | --- | --- |
| FlowSpreadsheet badges | `flowAnnotations`, `flowEdits`, `prepNotes` | `isFlowLiveUpdateStorageEvent` |
| Flow Annotations Panel | `flowAnnotations` | `isFlowAnnotationsPanelLiveUpdateStorageEvent` |
| Prep Note Notifications | `prepNoteNotifications` | `isPrepNoteNotificationsLiveUpdateStorageEvent` |
| Strategy Panel | `strategyRecommendations` | `isStrategyLiveUpdateStorageEvent` |
| Flow Edit Log Panel | `flowEdits` | `isFlowEditLogPanelLiveUpdateStorageEvent` |

This approach enables near-real-time UI updates without manual page refresh when multiple tabs edit the same state.

# Summary

The API routes in this section compose a foundation for:

- AI-assisted analysis and coaching (`/api/analyze`, `/api/reason-ai`)
- Evidence search backend (`/api/search`) [mentioned but not expanded here]
- Collaborative flow editing support with persistence and presence (`/api/flow-sync`, `/api/flow-presence`)
- Saved round and flow persistence for user sessions (`/api/rounds`, `/api/flows`)
- AI-generated practice drill persistence (`/api/drill-sets`)
- User preference management (`/api/settings`)

Together, they enable the multi-user, multi-device interactive debate AI environment, ensuring synchronization, AI assistance, and personalized experiences.
