This section details how the Ebb Flow Editor (`debate-flow-ebb`) is integrated as a scoped panel inside the `debate-ai.com` web application. It explains the mounting of ebb with CSS and theme isolation, the role of the `EbbFlowToolsMenu` in the host app, and how ebb preferences are managed through the settings UI.

## EbbFlowEmbed (Web Integration)

The `EbbFlowEmbed` React component is the primary integration point embedding the Ebb editor within the `debate-ai.com` Next.js app. It provides an isolated panel that contains the flow editor instance while maintaining separation from the host page environment.

### CSS Scoping and Style Isolation

To prevent CSS and style conflicts between the host app and the embedded Ebb editor, `EbbFlowEmbed` uses strict CSS scoping conventions:

- **`.ebb-scope` Root Class**
The embed container applies a root class `.ebb-scope`. This class scopes all Ebb editor styles within it, preventing any global or broad CSS selectors within ebb's stylesheets from leaking into the host app. This avoids collisions with Tailwind base styles or other UI library styles used by `debate-ai.com`.
- **Theme Isolation**
Ebb uses a dedicated theme and key scope isolated from the host app. This isolation allows Ebb to maintain its own visual preferences—for example, distinct colors, fonts, or modes—independent from the host application's current theme. This is important for consistent user experience within Ebb's flow grid and controls, unaffected by any host-level theme changes.

### Internal Navigation and State

`EbbFlowEmbed` contains internal routing handled by a `FlowNavigator` component (or similar logic). This manages navigation inside the embedded flow editor without changing or conflicting with the Next.js router state of the host application. Thus, sheet switching or settings views within Ebb occur internally without URL changes at the app level.

### CardMirror Bridge Support

A key integration feature is the bridge allowing the host app to send "evidence" content from the research editor (CardMirror) into the Ebb editor's flow. This bridge operates by passing `FlowRequest` messages or similar data structures from the host into `EbbFlowEmbed`. The embed consumes these messages, inserting cards or other content into the flow grid.

This tight integration enables users to work fluidly between research and flow synthesis inside the debate platform.

## EbbFlowToolsMenu

The `EbbFlowToolsMenu` component provides host-level quick access to common ebb actions (e.g., creating a new flow, opening or joining sessions, configuration).

- It is embedded in the `FlowPageSidebar` panel in the debate-round package, so these actions remain accessible even when the Ebb editor tab is not active.
- Actions selected via this menu trigger an `onAction` callback.
- The host page (`DebateFlowPage`) handles these actions by setting `ebbActive` to `true` (switching to the Ebb tab) and queueing the action into `ebbPendingAction`.
- When `EbbFlowEmbed` mounts or updates, it consumes this pending action and executes it.

This decoupling of UI from mounting ensures a smooth user experience, activating and passing commands into Ebb only as needed.

## Ebb Preferences in Application Settings

Ebb's user preferences are integrated into the main application's global settings page at `/settings` using the `EbbFlowPreferencesPanel` component. This allows users to configure ebb-specific options alongside other debate-ai.com preferences.

### UI Isolation with Iframe for Preferences

Similar to the CardMirror settings UI, which contains an extensive unscoped stylesheet, Ebb's preferences panel adopts an isolation strategy (likely an iframe or scoped container) to:

- Prevent CSS conflicts between the preferences UI and the host app.
- Allow Ebb's preferences UI to maintain its own styling and scripts independently.
- Enable direct fetching and saving of user preferences via `/api/settings` without interfering with host app's authentication and UI state.

The CardMirror preferences use a dedicated iframe embedding a same-origin route (`/settings/editor-panel`) that loads and confines the CardMirror settings UI and its ~15k-line stylesheet. EbbFlowPreferencesPanel follows an analogous pattern for stable integration.

### Data Flow and Synchronization

- Preferences in the EbbFlowPreferencesPanel are stored locally first, reflecting instant user interaction.
- Changes are debounced and synchronized asynchronously to the user's account via PUT requests to `/api/settings`.
- The backend persists these preferences in the user settings database.
- On subsequent page loads, preferences hydrate the UI from this saved state ensuring consistent user experience.

# Summary

The **EbbFlowEmbed Host Integration** module is designed to seamlessly embed the EbbFlow local-first editor panel in the main debate-ai.com application while maintaining strict isolation for styling and theming. The `EbbFlowToolsMenu` provides convenient access to Ebb functionality host-wide, and ebb preferences are fully integrated within the unified settings page with robust persistence and isolation.
