The LLM Card Scoring system provides a multi-dimensional quality assessment for debate evidence cards. It combines deterministic heuristics with optional, qualitative AI-backed reviews to help contributors evaluate relevance, clarity, uniqueness, evidence quality, and usability.

## Overview & Architecture

This feature is implemented primarily in the `debate-search-evidence` package and exposed via the `/cards/scoring` route [docs/features/llm-card-scoring.md9-12](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/llm-card-scoring.md?plain=1#L9-L12) It integrates multiple components to support heuristic scoring, AI qualitative assessment, keyword topic tracking, bulk imports, history persistence, and cross-tab live update.

### Core Components

- **Heuristic Scoring**: Pure, synchronous evaluation functions in `lib/llm-card-scoring.ts` score cards across five dimensions with deterministic algorithms [packages/debate-search-evidence/src/lib/llm-card-scoring.ts1-180](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/lib/llm-card-scoring.ts#L1-L180)
- **AI Assessment**: An optional Anthropic Claude-backed qualitative review is requested on demand, adding verdict and notes per dimension [docs/features/llm-card-scoring.md44-51](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/llm-card-scoring.md?plain=1#L44-L51)
- **Persistence**: Indexed by card ID and contributor, localStorage stores scored cards (`state/cardScores.ts`), AI assessments (`state/aiCardAssessments.ts`), and per-contributor score history (`state/cardScoreHistory.ts`).
- **User Interface**: The `CardScoringPanel.tsx` component ties together inputs, bulk import, scoring display, AI assessments, and contributor trends [packages/debate-search-evidence/src/panels/CardScoringPanel.tsx1-180](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/CardScoringPanel.tsx#L1-L180)
- **Keyword Tracking**: Integration with the tracked arguments state (`state/trackedArguments.ts`) supports keyword filling per debate topic [packages/debate-search-evidence/src/state/cardScores.ts90-98](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/state/cardScores.ts#L90-L98)
- **Cross-tab Live Update**: The panel uses `state/live-update.ts` helpers to listen for storage events and keep the UI synced across multiple tabs [docs/features/llm-card-scoring.md116-127](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/llm-card-scoring.md?plain=1#L116-L127)

## Heuristic Scoring Engine

All scoring dimensions are pure deterministic functions in `lib/llm-card-scoring.ts` that analyze card content, keywords, and signal inputs to compute an overall score.

| Dimension | Function | Description |
| --- | --- | --- |
| **Relevance** | `scoreRelevance` | Percent of argument-block keywords found as case-insensitive substrings within card text [lines 76-83](https://github.com/debate/debate-ai.com/blob/34937310/lines 76-83) |
| **Clarity** | `scoreClarity` | Scores based on average sentence length falling within the ideal 12–28 words range [lines 95-115](https://github.com/debate/debate-ai.com/blob/34937310/lines 95-115) |
| **Uniqueness** | `scoreUniqueness` | `100 - (100 * max Jaccard similarity)` against all other texts, including the Shared Evidence Library [lines 129-145](https://github.com/debate/debate-ai.com/blob/34937310/lines 129-145) |
| **Evidence Quality** | `scoreEvidenceQuality` | Derived from quality signals via community rating functions [lines 147-149](https://github.com/debate/debate-ai.com/blob/34937310/lines 147-149) |
| **Usability** | `scoreUsability` | Based on whether word count fits within the 150 to 500 word ideal range [lines 176-185](https://github.com/debate/debate-ai.com/blob/34937310/lines 176-185) |

The uniqueness score flags cards as `isLikelyDuplicate` if below a threshold (e.g., 25). This check compares against all stored cards and the official shared evidence corpus [packages/debate-search-evidence/src/state/cardScores.ts79-88](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/state/cardScores.ts#L79-L88)

Uses tokenization, keyword substring matching, sentence splitting, and Jaccard similarity for robust, fast heuristic scoring with no external dependencies.

## AI Assessment Integration

The AI Assessment supplements deterministic scoring with subjective qualitative feedback. It uses Anthropic Claude via the secure `/api/reason-ai` proxy (server-side route requires authentication & API key) [apps/debate-ai.com/app/api/reason-ai/route.ts5-40](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/reason-ai/route.ts#L5-L40)

### Key Implementation Details

- **Prompt Construction**:
The prompt builder `buildCardScoringAiUserPrompt` composes the card text and keywords into a detailed message conforming to a fixed `CARD_SCORING_AI_SYSTEM_PROMPT` that specifies expected JSON fields (overallScore, verdict, notes per dimension) [packages/debate-search-evidence/src/lib/llm-card-scoring-ai.ts30-54](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/lib/llm-card-scoring-ai.ts#L30-L54)
- **Proxy Client**:`requestCardScoringAiAssessment` wraps a `fetch` POST call to `/api/reason-ai`, forwarding the prompt and handling API errors such as authentication failure or missing API key. It parses the JSON response via `parseCardScoringAiResponse` with error tolerance [packages/debate-search-evidence/src/lib/llm-card-scoring-client.ts30-69](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/lib/llm-card-scoring-client.ts#L30-L69)
- **State Persistence**:
AI assessments are saved keyed by the card ID in `state/aiCardAssessments.ts`. This ensures results persist across sessions and survive page reloads [packages/debate-search-evidence/src/state/aiCardAssessments.ts10-39](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/state/aiCardAssessments.ts#L10-L39)
- **UI Interaction**:
In `CardScoringPanel.tsx`, each rated card row shows a "Get AI assessment" button. When clicked, the panel calls the client, manages loading and error states, then shows the AI verdict and notes inline [packages/debate-search-evidence/src/panels/CardScoringPanel.tsx120-148](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/CardScoringPanel.tsx#L120-L148)

## Persistence Layer

To provide fast local feedback and offline resilience, the system caches key data in `localStorage` with fallback to empty lists on SSR or missing data, never throwing errors on malformed data.

- **Card Scores (`state/cardScores.ts`)**:
Stores an array of `ScoredCard` objects keyed by card ID. Supports list, get, save (upsert), delete, and bulk save. Appends contributors' scoring history snapshots on saves [packages/debate-search-evidence/src/state/cardScores.ts30-156](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/state/cardScores.ts#L30-L156)
- **AI Card Assessments (`state/aiCardAssessments.ts`)**:
Keyed by card ID, stores final AI verdicts and notes, persisted across sessions and reloads [packages/debate-search-evidence/src/state/aiCardAssessments.ts10-39](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/state/aiCardAssessments.ts#L10-L39)
- **Card Score History (`state/cardScoreHistory.ts`)**:
Append-only log of every scoring event per contributor over time, used to render contributor score trends in `CardScoringPanel`[packages/debate-search-evidence/src/state/cardScoreHistory.ts1-94](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/state/cardScoreHistory.ts#L1-L94)
- **Tracked Arguments (`state/trackedArguments.ts`)**:
Stores tracked argument-block labels per topic, used to populate keywords on new card submissions via `deriveArgBlockKeywordsForTopic`[packages/debate-search-evidence/src/state/cardScores.ts90-98](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/state/cardScores.ts#L90-L98)

## User Interface: CardScoringPanel

The React component `CardScoringPanel` is located in `src/panels/CardScoringPanel.tsx`. It provides contributors a rich interface with these key features:

- **Single Card Submission Form**:
Inputs for card ID, full text, argument-block keywords (editable), quality signal (0 to 1 float), and optional contributor ID.
The "Use tracked keywords" button fills keywords from the selected tracked topic checklist [packages/debate-search-evidence/src/panels/CardScoringPanel.tsx115-130](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/CardScoringPanel.tsx#L115-L130)
- **Bulk Import**:
A large textarea accepts multiple cards separated by lines of `---`. Each entry may contain optional metadata lines (`id:`, `keywords:`, `quality:`) and a card text body.
The parser `parseBulkCardSubmissions` handles errors gracefully: malformed entries are skipped with counts reported [docs/features/llm-card-scoring.md73-91](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/llm-card-scoring.md?plain=1#L73-L91)[packages/debate-search-evidence/src/panels/CardScoringPanel.tsx60-87](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/CardScoringPanel.tsx#L60-L87)
- **Ranked Card List**:
Displays all persisted cards sorted by overall heuristic score. Each card row shows the dimension breakdown, the overall score, and a likely-duplicate badge if flagged [packages/debate-search-evidence/src/panels/CardScoringPanel.tsx130-180](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/CardScoringPanel.tsx#L130-L180)
- **AI Assessment Buttons & Display**:
On each row, a "Get AI assessment" button triggers the Anthropic call; results show verdict and per-dimension notes inline once loaded, or error messages if failed [packages/debate-search-evidence/src/panels/CardScoringPanel.tsx130-180](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/CardScoringPanel.tsx#L130-L180)
- **Contributor Score Trends**:
If a contributor ID is selected, their full scoring history is displayed as a vertical meter-bar chart, reflecting all past scoring events from the append-only history log [packages/debate-search-evidence/src/panels/CardScoringPanel.tsx140-170](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-search-evidence/src/panels/CardScoringPanel.tsx#L140-L170)
- **Cross-Tab Live Updates**:
The panel listens for storage events on `cardScores`, `aiCardAssessments`, and `trackedArguments`. Any changes from another tab automatically refresh the ranking, AI notes, and topic lists to keep all instances in sync [docs/features/llm-card-scoring.md113-127](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/llm-card-scoring.md?plain=1#L113-L127)

This end-to-end LLM Card Scoring & AI Assessment pipeline plays a crucial role in community-driven evidence quality control by blending deterministic heuristics with recent advances in LLM contextual assessments. It enables debate teams to curate and improve their evidence with transparency and historical scoring analytics, all within a highly integrated and performant frontend panel.
