## 1. localStorage-First Store Patterns & Zustand Architecture

The platform uses a hybrid state model where UI interactions and user preferences rely on **Zustand** stores and **localStorage** persistence for zero-latency local responsiveness, while optional backend synchronization links key preferences to the signed-in user's D1 account record.

## 3. Theme & Font Settings Management

Theme preferences (`colorTheme`, `themeMode`) and font family choices are synchronized across storage layers:

- **Color Themes**: Managed via canonical option lists (`THEME_NAMES`, `THEME_MODES`) defined in `debate-round` and consumed by `components/theme-dropdown.tsx` and `UserSettingsPanel`[docs/features/user-settings.md70-77](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/user-settings.md?plain=1#L70-L77)
- **DOM Application**: `applyThemeLocally` clears existing `theme-*` classes from `document.documentElement`, injects the selected theme class, updates `localStorage`, sets a 1-year persistence cookie (`color-theme`), and invokes `next-themes`' `setTheme()`[packages/debate-round/src/panels/UserSettingsPanel.tsx88-96](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-round/src/panels/UserSettingsPanel.tsx#L88-L96)
- **Font Settings**: Font family configurations utilize `readLocalFontFamily` and `setLocalFontFamily` for immediate offline retention [packages/debate-round/src/panels/UserSettingsPanel.tsx56-61](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-round/src/panels/UserSettingsPanel.tsx#L56-L61)

## 4. Favorite Tools Integration (`useFavoriteTools` & `FavoritesController`)

The favorite tools subsystem integrates tool starring across the `/tools` catalog and `/settings`:

- **State Hook (`useFavoriteTools`)**: Reads from `localStorage`, merges remote account state when signed in, and dispatches custom window events (`favorite-tools-changed`) to synchronize multiple mounted instances within the same tab [docs/features/user-settings.md108-115](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/user-settings.md?plain=1#L108-L115)
- **DOM Controller (`FavoritesController`)**: Prunes obsolete references against known tool hrefs and updates visibility attributes on DOM elements without requiring full React tree re-renders [apps/debate-ai.com/components/tools/FavoritesController.tsx34-53](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/components/tools/FavoritesController.tsx#L34-L53)

## 5. Offline Support & Service Worker Registration (`ServiceWorkerRegistrar`)

The application functions as a Progressive Web App (PWA) equipped with a service worker (`apps/debate-ai.com/lib/offline-sw/service-worker.ts`) to ensure tournament continuity during network interruptions.

### Service Worker Lifecycle & Strategies

- **Registration**: `ServiceWorkerRegistrar` mounts in the root layout, registering `/service-worker.js` while bypassing registration on `localhost` during development [apps/debate-ai.com/components/layout/ServiceWorkerRegistrar.tsx17-37](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/components/layout/ServiceWorkerRegistrar.tsx#L17-L37)
- **Caching Strategies**:

- **Network-First**: Applied to navigation requests, HTML documents, RSC payloads (`.rsc`), and `/api/` endpoints to prioritize fresh data, falling back to cached responses or the root `/` app shell during network failure [apps/debate-ai.com/lib/offline-sw/service-worker.ts131-154](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/offline-sw/service-worker.ts#L131-L154)
- **Cache-First**: Applied to immutable versioned static assets (`/assets/` and `APP_FILE_LIST`) to guarantee instantaneous load performance [apps/debate-ai.com/lib/offline-sw/service-worker.ts113-159](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/offline-sw/service-worker.ts#L113-L159)
