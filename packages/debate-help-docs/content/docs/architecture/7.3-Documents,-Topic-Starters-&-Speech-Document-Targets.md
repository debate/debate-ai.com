This page details the implementation of the REASON editor, focusing on document management, topic starter integration, and the speech document targeting and logging features. It covers the UI components (`FileTree`, `OpenTabsPanel`, `TopicStarterTree`, `ReasonDocsProvider`), backend API routes (`/api/doc/documents`, `/api/topic-starters`), the speech document send flow, the `SpeechSendLogPanel` with cloud save capabilities, and the state of legacy Verbatim shortcuts within the `debate-editor` (CardMirror) package.

## REASON Editor Documents and Topic Starters

The REASON editor manages documents stored persistently and shown in a file/folder tree, alongside a parallel catalogue of public topic starters — pre-built research templates or starting points for users.

### UI Components & State Management

- **ReasonDocsProvider**
Acts as the shared React context provider maintaining state for:

- `documents`: user-owned documents and folders.
- `topicItems`: public topic starters.
- `openTabs`: IDs of currently opened documents.
- `activeId`: the document currently focused in the editor.
- `topicDocument`: a selected topic starter shown read-only in place of a user document.
- Loading and saving flags.
It exposes handlers for document CRUD (create, delete, move), tab management (open, close, select), and topic selection.
It lazily loads document and topic starter data from the backend APIs on first demand rather than eagerly at mount.
See implementation in [apps/debate-ai.com/components/reason-docs/ReasonDocsProvider.tsx15-171](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/components/reason-docs/ReasonDocsProvider.tsx#L15-L171)
- **FileTree**
Displays the hierarchical folder and document structure. Supports:

- Expanding/collapsing folders.
- Drag-and-drop to move documents/folders.
- Creating new documents or folders.
- Renaming and deleting documents.
It builds a nested tree by grouping documents by `parentId`, ordering folders above files, and sorting alphabetically.
See [apps/debate-ai.com/components/reason-docs/FileTree.tsx1-194](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/components/reason-docs/FileTree.tsx#L1-L194)
- **OpenTabsPanel**
Shows a flat list of open document tabs. Allows switching between active documents or closing tabs.
See [apps/debate-ai.com/components/reason-docs/OpenTabsPanel.tsx1-60](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/components/reason-docs/OpenTabsPanel.tsx#L1-L60)
- **TopicStarterTree**
Similar to `FileTree` but displays public topic starter items with a search filter over titles and tags. Allows expanding/collapsing and selection to view a read-only topic document.
See [apps/debate-ai.com/components/reason-docs/TopicStarterTree.tsx1-41](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/components/reason-docs/TopicStarterTree.tsx#L1-L41)
- **ReasonDocsSidebarPanels**
Combines the above panels (`FileTree`, `OpenTabsPanel`, `TopicStarterTree`) in the persistent app sidebar. Controls collapsible panels with user preferences stored in localStorage. Fetches data only if visible.
See [apps/debate-ai.com/components/reason-docs/ReasonDocsSidebarPanels.tsx](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/components/reason-docs/ReasonDocsSidebarPanels.tsx)

### Backend API Routes for Documents and Topic Starters

- **`/api/doc/documents`** (GET, POST)

- GET lists all documents and folders owned by the current user or anonymous docs if signed out.
- POST creates a new document or folder with optional `title`, `content`, `parentId`, and `isFolder`.
See [apps/debate-ai.com/app/api/doc/documents/route.ts14-50](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/doc/documents/route.ts#L14-L50)
- **`/api/doc/documents/[id]`** (GET, PUT, DELETE)

- GET retrieves a single document by ID with ownership check.
- PUT updates title, content, or parentId with ownership check.
- DELETE deletes a document by ID with ownership check. For folders, clients cascade deletion of descendants.
See [apps/debate-ai.com/app/api/doc/documents/[id]/route.ts:12-73]().
- **`/api/topic-starters`** (GET)
Publicly fetches all topic starter items.
See [apps/debate-ai.com/app/api/topic-starters/route.ts10-16](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/topic-starters/route.ts#L10-L16)
- **Admin `/api/admin/topic-starters`** (GET, POST)
Admin-only routes to list, upload, and parse `.docx` and zipped topic starter documents into the database, automatically creating folder hierarchies for nested files.
See [apps/debate-ai.com/app/api/admin/topic-starters/route.ts11-69](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/admin/topic-starters/route.ts#L11-L69)

## Speech Document Targets & Send Flow

The debate-editor (CardMirror) enables users to designate one open editor pane as the "speech document" — a live target for collecting speech delivery material from other documents.

### Mechanism of Speech Document Targeting and Sending

- **Marking a Speech Document:**
Via the File menu → Speech → "Mark / Unmark Active Doc as the Speech Doc" command, a pane is marked as the speech doc. This flag is managed in the `speech-doc-registry.ts` module [docs/features/speech-document-target.md32-34](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/speech-document-target.md?plain=1#L32-L34)
- **Sending Content to Speech Doc:**
From any other document, pressing the backtick (```) key or Alt-backtick sends the current selection or card to the speech document. The key events trigger the `sendToSpeech()` function [docs/features/speech-document-target.md35-37](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/speech-document-target.md?plain=1#L35-L37)
- **Insertion Logic:**
The core insert is handled by `insertSpeechSlice()`, applying the ProseMirror slice to the speech doc pane:

- If the speech doc is in the same tab, the slice is inserted directly in the editor view.
- If in a different tab, `BroadcastChannel` plus a shared localStorage UID `pmd-speech-uid` coordinate cross-tab communication & insertion [docs/features/speech-document-target.md42-45](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/speech-document-target.md?plain=1#L42-L45)
- **Speech Send Log Recording:**
Upon successful insertion, a plain-text log entry is constructed via `buildSpeechSendLogEntry()` and appended to `speechSendLogStore` (backed by IndexedDB) [docs/features/speech-document-target.md77-79](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/speech-document-target.md?plain=1#L77-L79) This store allows cross-tab reactive sync of the send history.

### SpeechSendLogPanel & Cloud Sync

- The `SpeechSendLogPanel` React component at `/speech-documents` subscribes to `speechSendLogStore` and displays a history of everything the user sent into the speech doc, with timestamps and options to remove entries or clear all history [apps/debate-ai.com/app/speech-documents/SpeechSendLogPanel.tsx40-130](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/speech-documents/SpeechSendLogPanel.tsx#L40-L130)
- The hook `useSpeechSendLogSync()` synchronizes the IndexedDB-backed log with cloud storage via REST API routes:

- **GET `/api/speech-send-log`** fetches saved entries.
- **POST `/api/speech-send-log`** appends new entries.
- **DELETE `/api/speech-send-log/[entryId]`** removes a single entry.
- **DELETE `/api/speech-send-log`** clears all entries for the user.
This synchronization ensures cross-device persistence and account linking.

## Legacy Verbatim Shortcuts in the REASON Editor (CardMirror)

The `debate-editor` package implements legacy keyboard shortcut bindings that mirror the well-known Verbatim/paperless-debate workflows supporting efficient debate document creation and manipulation.

### Shortcut Implementation

- These commands replicate Verbatim’s F-key based hotkey scheme and include commands for emphasis, citations, underlining, document condensing/uncondensing, moving content containers, copying last cite, and AI-assisted cite insertion.
- Implemented primarily in the `ribbon-commands.ts`, `move-container.ts`, and `condense.ts` modules inside the `debate-editor` package.

### Key Shortcut Examples

| Shortcut | Command | Menu Location | Description |
| --- | --- | --- | --- |
| `F10` | `applyEmphasis` | Format → Character... | Applies Emphasis style to selection |
| `F8` | `applyCite` | Format → Character... | Apply Cite style |
| `F9` / `Mod-u` | `toggleUnderlineTyping` | Format → Character... | Toggle Underline style |
| `F3` | `condenseDefault` | Card → Condense | Condense selection/document to "read" text |
| `Alt-F3` / `Mod-Alt-F3` | `condenseNoIntegrity` | Card → Condense | Condense without paragraph integrity |
| `Mod-Alt-Shift-F3` | `uncondense` | Card → Condense | Uncondense document |
| `Mod-Alt-ArrowUp/Down` | `moveContainerUp/Down` | Edit → Editing utils | Move card/section up or down |
| `Alt-F8` | `copyPreviousCite` | Edit → Editing utils | Copy nearest preceding cite |
| `Mod-Shift-k` | `insertShortCite` | Edit → Editing utils | Prompt for author/year, insert formatted short cite |
| `Mod-Shift-x` | `aiCreateCite` | AI | Use AI to create formatted citation from selection |

> `Mod` means `Ctrl` on Windows/Linux and `Cmd` on macOS.

### Accessibility and User Controls

- Every command is accessible via:

1. Its default keybinding.
2. The `MenuBar` top menu bar dropdowns (File, Speech, Card, Edit, AI) [packages/debate-editor/src/react/MenuBar.tsx89-99](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-editor/src/react/MenuBar.tsx#L89-L99)
3. The command palette Ctrl/Cmd-Shift-Space (`quick-card-search-ui.ts`).
- Key bindings are user-remappable through CardMirror’s settings UI.
- A printable/exportable reference of these legacy shortcuts is included in the editor's Help menu for user convenience.
