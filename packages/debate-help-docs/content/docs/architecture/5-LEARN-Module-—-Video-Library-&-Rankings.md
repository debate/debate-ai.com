The **LEARN** (Lectures from Educators, Archive of Rounds & Notes) module serves as the primary educational and historical repository for the Debate AI platform. It aggregates thousands of debate rounds, instructional lectures, and competitive rankings into a unified interface. Its components provide users with powerful browsing, filtering, and playback capabilities along with competitive context. [README.md85-94](https://github.com/debate/debate-ai.com/blob/34937310/README.md?plain=1#L85-L94)

The module primarily resides in the `packages/debate-videos` package and interfaces closely with `debate-data-sync` for data ingestion and with the `/api` backend routes for video, transcript, and leaderboard data.

---

## Module Components Overview

The LEARN module is composed of three main sub-systems, each covering a distinct user-facing concern but wired to a shared data backbone:

| Component | Responsibility | Key Code Entities |
| --- | --- | --- |
| **Video Library & Search** | Provides searchable, filterable, and infinite-scroll video grids for debate rounds and lectures with client-side state sync and thumbnails. | `LecturesPage.tsx`, `LecturesVideoGridView.tsx`, `useVideoFeed`, `VideoSearchBar`, `/api/videos` |
| **Persistent Video Player & Transcripts** | Persistent video playback UI that continues playing as users navigate with synchronized transcripts and subtitle controls. | `PersistentVideoPlayer`, `videoPlayerStore`, `PlayerSubtitles`, `TranscriptModal`, `/api/transcript` |
| **Leaderboard & Team Rankings** | Fetches, aggregates, and displays team rankings and tournament standings across debate styles and years. | `LeaderboardPanel`, `/api/leaderboard`, ranking scrapers and CSV import utilities |

## Video Library, Search & Grids

The Video Library sub-system delivers fast and scalable access to thousands of debate rounds and lectures in an intuitive grid or list layout with multi-dimensional search and filtering.

- The top-level coordinator `LecturesPage.tsx` manages global filter state, slug-based routing (`/videos`, `/videos/[category]`), URL synchronization, and delegates rendering to category-specific branches such as `LecturesVideoGridView.tsx` for main grids, or leaderboard and dictionary views. [packages/debate-videos/src/panels/LecturesPage.tsx58-162](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/panels/LecturesPage.tsx#L58-L162)
- Video data is served through a SQL-backed paginated feed via the `/api/videos` endpoint, which reads from the `videos` database table seeded from bundled JSON assets. Seeding is done by `seedVideosIntoDb` function, which generates batched upsert statements to keep the table up-to-date (idempotent seed and prune routine). If SQL is unavailable or unseeded, a fallback in-memory JSON dataset is served. [docs/features/video-library.md3-65](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/video-library.md?plain=1#L3-L65)[apps/debate-ai.com/app/api/admin/videos/seed/route.ts21-73](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/admin/videos/seed/route.ts#L21-L73)[packages/debate-data-sync/src/videos/video-seed-sql.ts133-175](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/src/videos/video-seed-sql.ts#L133-L175)
- The main video grid UI (`LecturesVideoGridView.tsx`) features:

- Sticky search/filter bar (`VideoSearchBar` component)
- Quick-link navigation cards for categories and top picks
- A collapsible lecture category gallery
- Infinite scroll pagination triggering backend fetches
- Thumbnails toggle, favorites-only filter, and sort controls
- Supports grid or list (row) layouts with resizable columns
[packages/debate-videos/src/panels/LecturesVideoGridView.tsx10-183](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/panels/LecturesVideoGridView.tsx#L10-L183)[packages/debate-videos/src/components/video-search/VideoSearchBar.tsx1-126](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/components/video-search/VideoSearchBar.tsx#L1-L126)
- Client-side state for filters and user preferences such as favorited or hidden videos is managed by the `useVideoState` hook. This hook persists favorites and hidden videos in localStorage for session continuity and exports actions for toggling favorites, visibility, and filter changes. [packages/debate-videos/src/hooks/useVideoState.ts1-165](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/hooks/useVideoState.ts#L1-L165)

## Persistent Player & Transcripts

To provide an uninterrupted viewing experience, the LEARN module includes a **Persistent Video Player** component integrated at the application root level.

- The `PersistentVideoPlayer` component remains mounted across pages, enabling continuous playback as users navigate the site [apps/debate-ai.com/app/layout.tsx53](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/layout.tsx#L53-L53)
- The playback state, including current video, playback position, and controls, is managed by the `videoPlayerStore` global state hook. This state informs relevant video displays such as the video grid component [packages/debate-videos/src/index.ts10](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/index.ts#L10-L10)
- Users can view synchronized transcripts and control subtitles via components like `PlayerSubtitles` and `TranscriptModal`. Transcript fetching leverages the `/api/transcript` route which accesses YouTube transcripts through an external transcript library [README.md90-91](https://github.com/debate/debate-ai.com/blob/34937310/README.md?plain=1#L90-L91)[apps/debate-ai.com/public/debate-openapi.yml15-77](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/public/debate-openapi.yml#L15-L77)

This setup supports accessibility and learning by allowing reference to transcripts alongside video playback.

For full technical details including UI controls, subtitle handling, modal interactions, and transcript utilities, see the child page [Persistent Player & Transcripts](/debate/debate-ai.com/5.2-persistent-player-and-transcripts).

## Leaderboard & Team Rankings

The LEARN module also features a comprehensive **Leaderboard & Team Rankings** sub-system that presents competitive debate team performance data.

- Rankings combine multiple data sources including:

- Elo ratings scraped via `sync-rankings-debatedrills`
- Tournament of Champions (TOC) bid lists scraped via `sync-rankings-tocbidlist`
- Tournament results and historical standings pulled from Tabroom scrapers
- Historical champion records (2000–2025) from NDCA and other sources are served through the module’s history APIs.
- The aggregated leaderboard data is served via the `/api/leaderboard` endpoint, which merges and filters based on year and division.
- The frontend `LeaderboardPanel` UI displays standings with sorting, filtering by division/year, and qualification cutoffs. [packages/debate-videos/src/panels/LecturesPage.tsx23](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/panels/LecturesPage.tsx#L23-L23)[README.md93-94](https://github.com/debate/debate-ai.com/blob/34937310/README.md?plain=1#L93-L94)

This helps debaters track their competitive landscape and qualification status relative to peers.

For implementation specifics regarding scrapers, CSV import pipelines, the ranking merge algorithm, and the interactive frontend panels, see the child page [Leaderboard & Team Rankings](/debate/debate-ai.com/5.3-leaderboard-and-team-rankings).
