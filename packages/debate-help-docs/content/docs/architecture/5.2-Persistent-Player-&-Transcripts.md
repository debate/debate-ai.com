This page details the implementation of the persistent video player and its associated transcript functionality within the Debate AI platform. The persistent player allows users to watch videos while navigating other parts of the application, maintaining playback state across pages. The transcript features provide synchronized captions, enabling users to follow along with the video content, seek to specific points, and even create annotations linked to the video's timeline.

## Persistent Video Player (`PersistentVideoPlayer`)

The `PersistentVideoPlayer` component [packages/debate-videos/src/components/video-player/PersistentVideoPlayer.tsx](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/components/video-player/PersistentVideoPlayer.tsx) is the central element for video playback. It's a client-side component that manages the YouTube iframe, its state, and user interactions like dragging, resizing, and picture-in-picture mode.

### Implementation Details

The player leverages several React hooks and a Zustand store (`useVideoPlayerStore`) for state management.

- **State Management**: The `useVideoPlayerStore`[packages/debate-videos/src/state/videoPlayerStore.ts](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/state/videoPlayerStore.ts) is a Zustand store that holds the global state of the video player, including:

- `activeVideoId`, `activeVideoTitle`, `activeVideoMeta`: Information about the currently playing video.
- `isMinimized`, `isPlaying`, `isSlowMode`: Player UI and playback states.
- `queue`: A list of videos to be played next.
- `startTime`: The timestamp from which the video should start playing.
- `getCurrentTimeRef`: A reference to a function that returns the current playback time.
- **Persistence**: Player state is persisted to `localStorage` using `savePlayerState` and `loadPlayerState`[packages/debate-videos/src/state/videoPlayerPersistence.ts](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/state/videoPlayerPersistence.ts) This ensures that if a user navigates away and returns, or even closes and reopens the browser, the player can resume from its last known state, including the video, playback position, and queue.
- **YouTube IFrame API Interaction**: The player embeds a YouTube video using an `<iframe>`. Communication with the YouTube player is handled via `postMessage`[packages/debate-videos/src/components/video-player/PersistentVideoPlayer.tsx152-172](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/components/video-player/PersistentVideoPlayer.tsx#L152-L172)
- `startListening` and `watchUrl`[packages/debate-videos/src/components/video-player/youtubeEmbed.ts](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/components/video-player/youtubeEmbed.ts) are used to initialize and monitor the YouTube iframe.
- `sendYouTubeCommand`[packages/debate-videos/src/state/videoPlayerStore.ts134-141](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/state/videoPlayerStore.ts#L134-L141) is a utility function to send commands like `playVideo`, `pauseVideo`, `setPlaybackRate`, and `seekTo` to the embedded YouTube player.
- **Drag and Resize**: The `useDragResize` hook [packages/debate-videos/src/components/video-player/PersistentVideoPlayer.tsx62](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/components/video-player/PersistentVideoPlayer.tsx#L62-L62) provides functionality for users to drag and resize the player window.
- **Picture-in-Picture (PiP)**: The `useDocumentPictureInPicture` hook [packages/debate-videos/src/components/video-player/PersistentVideoPlayer.tsx46](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/components/video-player/PersistentVideoPlayer.tsx#L46-L46) enables toggling the video into and out of PiP mode.
- **Error Handling**: The player listens for `onError` events from the YouTube API to display relevant error messages [packages/debate-videos/src/components/video-player/PersistentVideoPlayer.tsx157-161](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/components/video-player/PersistentVideoPlayer.tsx#L157-L161)

## Player Controls and Subtitles

The `PersistentVideoPlayer` integrates `PlayerControls` and `PlayerSubtitles` components to offer a comprehensive user experience.

### `PlayerControls`

The `PlayerControls` component [packages/debate-videos/src/components/video-player/PlayerControls.tsx](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/components/video-player/PlayerControls.tsx) provides interactive buttons for common video player actions:

- **Play/Pause**: Toggles video playback.
- **Slow Mode**: Adjusts playback speed, specifically designed for slowing down "debate spread" (fast speaking).
- **Skip Next**: Plays the next video in the queue.
- **Toggle Subtitles**: Shows or hides the `PlayerSubtitles` overlay.
- **Picture-in-Picture**: Toggles PiP mode.
- **Minimize/Maximize**: Collapses or expands the player UI.
- **Close**: Removes the player from the screen.

These controls interact with the `useVideoPlayerStore` to update the player's state and send commands to the YouTube iframe.

### `PlayerSubtitles`

The `PlayerSubtitles` component [packages/debate-videos/src/components/video-player/PlayerSubtitles.tsx](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/components/video-player/PlayerSubtitles.tsx) displays synchronized captions directly on the video player.

- It uses the `useTranscript` hook to fetch and manage transcript data.
- As the video plays, it highlights the currently spoken line and updates the displayed text.
- This component is distinct from the `TranscriptModal` which provides a full-page transcript view.

## Video Player Store (`videoPlayerStore`)

The `videoPlayerStore`[packages/debate-videos/src/state/videoPlayerStore.ts](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-videos/src/state/videoPlayerStore.ts) is a Zustand store that centralizes the state and actions related to the persistent video player.

### Key State Properties

- `activeVideoId`, `activeVideoTitle`, `activeVideoMeta`: Identifies the video currently loaded.
- `isMinimized`: Boolean indicating if the player is minimized.
- `isPlaying`: Boolean indicating if the video is currently playing.
- `isSlowMode`: Boolean indicating if slow playback mode is active.
- `queue`: An array of `QueueItem` objects, representing videos lined up for playback.
- `startTime`: The initial playback position in seconds when a video is loaded.
- `getCurrentTimeRef`: A function reference to get the current playback time from the `PersistentVideoPlayer`.

- `setActiveVideo(videoId, title, meta, startTimeSeconds)`: Sets the video to be played. ## Transcript API (`/api/transcript`) with YouTube Transcript Library

### `GET` Request Handler

- **Input**: Takes `videoId` (required) and `lang` (optional, defaults to "en") as query parameters. [apps/debate-ai.com/app/api/transcript/route.ts26-28](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/transcript/route.ts#L26-L28)

[apps/debate-ai.com/app/api/transcript/route.ts30-34](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/transcript/route.ts#L30-L34)
- **Edge Caching**: Implements an edge cache (`edgeCache`) [apps/debate-ai.com/app/api/transcript/route.ts20-22](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/transcript/route.ts#L20-L22) to store transcript responses. This is crucial because YouTube frequently bot-checks server IPs, making direct requests unreliable. - **Error Handling**:

- Returns 400 for missing or invalid `videoId`. [apps/debate-ai.com/app/api/transcript/route.ts30-34](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/app/api/transcript/route.ts#L30-L34)

### YouTube Transcript Library (`lib/youtube/transcript.ts`)

This library [apps/debate-ai.com/lib/youtube/transcript.ts](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/transcript.ts) is designed to reliably fetch YouTube timed captions without a browser.

- **`TranscriptSnippet` Interface**: Defines the structure of a single caption line, including `text`, `start`, and `duration`[apps/debate-ai.com/lib/youtube/transcript.ts13-18](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/transcript.ts#L13-L18)
- **InnerTube API**: Instead of scraping public `/api/timedtext` URLs (which are often empty for non-browser callers), it queries YouTube's internal `InnerTube` API's `player` endpoint. It mimics mobile client requests using specific `User-Agent` headers and client contexts (`CLIENTS` array) [apps/debate-ai.com/lib/youtube/transcript.ts29-55](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/transcript.ts#L29-L55) to get valid caption track URLs.
- **`fetchCaptionTracks(videoId, clientConfig)`**: This asynchronous function [apps/debate-ai.com/lib/youtube/transcript.ts75](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/transcript.ts#L75-L75) makes a `POST` request to the InnerTube API to retrieve a list of available caption tracks for a given `videoId`.
- **`rankTracks(tracks, lang)`**: Sorts the available caption tracks by usefulness, prioritizing the requested language, then human-generated captions over auto-generated ones [apps/debate-ai.com/lib/youtube/transcript.ts116-126](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/transcript.ts#L116-L126)
- **Parsing Caption Payloads**:

- `parseJson3(body)`: Parses the `fmt=json3` caption format, which is a JSON structure [apps/debate-ai.com/lib/youtube/transcript.ts151-170](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/transcript.ts#L151-L170)
- `parseXml(body)`: Parses legacy XML caption formats (`<p t="…" d="…">` or `<text start="…">`) [apps/debate-ai.com/lib/youtube/transcript.ts173-197](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/transcript.ts#L173-L197)
- `decodeEntities(text)`: Decodes HTML entities found in caption text [apps/debate-ai.com/lib/youtube/transcript.ts139-147](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/transcript.ts#L139-L147)
- **`fetchTrack(track, userAgent)`**: Downloads and parses a single caption track, preferring JSON over XML [apps/debate-ai.com/lib/youtube/transcript.ts200](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/transcript.ts#L200-L200)
- **`fetchYouTubeTranscript(videoId, lang)`**: The main entry point for the library. It iterates through `CLIENTS` to find a working configuration, fetches caption tracks, ranks them, and then fetches and parses the best available track. [apps/debate-ai.com/lib/youtube/transcript.ts202-264](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/transcript.ts#L202-L264)
- **`TranscriptUnavailableError`**: A custom error class [apps/debate-ai.com/lib/youtube/transcript.ts67](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/youtube/transcript.ts#L67-L67) thrown when no usable captions can be retrieved.

## Flow Annotations Integration

The persistent video player and transcript functionality are integrated with the "Flow-in-Speech Flow Annotations" feature, allowing users to create timestamped notes linked to specific arguments in a debate flow.

### `FlowAnnotation` Data Model

The `FlowAnnotation` type [packages/debate-round/src/flow/flow-annotations.ts15](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-round/src/flow/flow-annotations.ts#L15-L15) includes:

- `videoId`: The ID of the YouTube video the annotation is associated with. [packages/debate-round/src/flow/flow-annotations.ts27](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-round/src/flow/flow-annotations.ts#L27-L27)
- `videoTitle`: The title of the video. [packages/debate-round/src/flow/flow-annotations.ts29](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-round/src/flow/flow-annotations.ts#L29-L29)
- `timestampMs`: The playback position in milliseconds. [packages/debate-round/src/flow/flow-annotations.ts23](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-round/src/flow/flow-annotations.ts#L23-L23)
- `boxPath`: A path identifying the specific argument box in the debate flow. [packages/debate-round/src/flow/flow-annotations.ts19](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-round/src/flow/flow-annotations.ts#L19-L19)
- `speechId`, `note`, `createdAt`, `speaker`, `tag`. [packages/debate-round/src/flow/flow-annotations.ts21-34](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-round/src/flow/flow-annotations.ts#L21-L34)

### Creating Annotations

When a user drops an annotation in the `FlowAnnotationsPanel`[docs/features/flow-annotations.md48](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/flow-annotations.md?plain=1#L48-L48) the `createFlowAnnotation` function [packages/debate-round/src/flow/flow-annotations.ts58](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-round/src/flow/flow-annotations.ts#L58-L58) is called. It captures the `activeVideoId` and `activeVideoTitle` from `useVideoPlayerStore` along with the current playback position. [docs/features/flow-annotations.md53-54](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/flow-annotations.md?plain=1#L53-L54)

### Jumping to Annotations

The `jumpToAnnotation` helper function [packages/debate-round/src/flow/flow-annotations.ts177](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-round/src/flow/flow-annotations.ts#L177-L177) is central to navigating annotations:

- If the annotation's `videoId` is already loaded in the `PersistentVideoPlayer`, it sends a `seekTo` command via `sendYouTubeCommand`[docs/features/flow-annotations.md64](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/flow-annotations.md?plain=1#L64-L64)[packages/debate-round/src/flow/flow-annotations.ts187-188](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-round/src/flow/flow-annotations.ts#L187-L188)
- If a different video is loaded or no video is playing, it calls `useVideoPlayerStore.setActiveVideo`[docs/features/flow-annotations.md67](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/flow-annotations.md?plain=1#L67-L67) to load the correct video and seek to the specified `startTimeSeconds`. This uses the video's `&start=` URL parameter for initial loading, as the player might not be ready for a `seekTo` command immediately. [packages/debate-round/src/flow/flow-annotations.ts189-191](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-round/src/flow/flow-annotations.ts#L189-L191)

### Flow Spreadsheet Affordance (Removed)

The `FlowSpreadsheet` (part of the FIAT module) previously displayed a small clock badge next to cells that had associated `FlowAnnotation`s [docs/features/flow-annotations.md93](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/flow-annotations.md?plain=1#L93-L93) Hovering showed annotation details, and clicking jumped to the earliest annotation for that box using the same `jumpToAnnotation` helper.

**Note**: This functionality was removed in PR #498 (merged 2026-09-03) with the deprecation of the AG Grid-based `FlowSpreadsheet` in favor of the new "ebb flow" editor (`debate-flow`). The new editor currently lacks an equivalent in-grid annotation indicator, representing a known capability gap. [docs/features/flow-annotations.md93-110](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/flow-annotations.md?plain=1#L93-L110)
