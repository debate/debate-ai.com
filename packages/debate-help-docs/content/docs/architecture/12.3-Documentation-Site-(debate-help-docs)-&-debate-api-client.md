This page details the implementation and architecture of the `debate-help-docs` documentation site powered by Fumadocs, and the OpenAPI-generated `debate-api-client` SDK. It covers configuration and layout aspects of the docs site, the content/docs structure especially for features and packages, the docs/features specification catalog, and the debate-api-client’s generation, usage, and npm release flow.

---

## Documentation Site (`debate-help-docs`)

The `debate-help-docs` package provides the technical documentation for the Debate AI platform. It is built on Next.js and utilizes Fumadocs — a MDX-based documentation framework — to offer a rich authoring and navigation experience.

### Fumadocs Source Configuration

The docs site is configured at its source in `source.config.ts` ([packages/debate-help-docs/source.config.ts1-22](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-help-docs/source.config.ts#L1-L22)):

- **`loader`** sets up the base routing (`/docs`) and the root directory for documentation content (`content/docs`).
- **`createMDXSource(map)`** wraps the file map for MDX file processing, enabling rich documentation pages.
- The exports `get`, `getPage`, `getPages`, and `getPageTree` provide accessors for individual pages and navigation structure consumed at the layout and page rendering level.

This configuration consolidates static content and MDX into a structured site route hierarchy.

---

### Layout Configuration and React Components

The main layout configuration is found in `app/layout.config.tsx` ([packages/debate-help-docs/app/layout.config.tsx1-48](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-help-docs/app/layout.config.tsx#L1-L48)):

- The `RootProvider` from Fumadocs wraps the entire layout to supply UI theming, search capabilities, and global providers.
- The page tree (`pageTree`), reflecting the docs content structure from the source config, drives navigation menus and sidebars.
- The `DocsLayout` component renders the core docs UI around content, navigation, and sidebar areas.
- Custom components such as `Search` (search UI), `Breadcrumb` (breadcrumb navigation), and `AskAIDropdown` (AI query interface) are integrated into the layout, enhancing navigation and help features.

The layout configuration notably enables:

- Seamless page tree navigation generation.
- Plugin-like component architecture for search and AI interactions.
- Sidebar and navigation config driven by the stored page tree.

---

### MDX Components

The site augments Fumadocs’ default MDX components with additional specialized components declared in `mdx-components.tsx` ([packages/debate-help-docs/mdx-components.tsx1-21](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-help-docs/mdx-components.tsx#L1-L21)):

- Custom components provide enhanced visuals for type tables, callouts, feature grids, code examples, and API docs.
- The `ApiPage` component embeds OpenAPI interactive documentation (described below).
- These extensions enrich the static docs with interactive, common UI elements aligned with site styling.

---

### API Documentation & OpenAPI Integration

The API documentation is dynamically rendered using the OpenAPI spec served at `/api/api-docs` and public spec file `debate-openapi.yml` ([apps/debate-ai.com/public/debate-openapi.yml](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/public/debate-openapi.yml)).

- The `ApiPage` component ([packages/debate-help-docs/components/fumadocs/api/api-page.tsx](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-help-docs/components/fumadocs/api/api-page.tsx)) is a simple wrapper forwarding to a client component `ApiPageClient` ([packages/debate-help-docs/components/fumadocs/api/api-page.client.tsx](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-help-docs/components/fumadocs/api/api-page.client.tsx)), which renders the OpenAPI explorer UI.
- The OpenAPI spec defines the entire backend API surface, automatically documented and integrated via Scalar or similar tools.
- Additional customization hooks for generated docs are possible in `customize-docs.ts` ([packages/debate-help-docs/lib/fumadocs/customize-docs.ts](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-help-docs/lib/fumadocs/customize-docs.ts)).

## `debate-api-client` SDK

The `debate-api-client` package is a typed TypeScript SDK for the Debate AI API. It is generated from the OpenAPI spec to ensure full client/server contract coherence and ease of use.

### SDK Generation Flow

- The SDK is generated from the OpenAPI spec (`debate-openapi.yml` in `apps/debate-ai.com/public/`) using the Hey API `openapi-ts` generator ([packages/debate-api-client/openapi-ts.config.ts](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-api-client/openapi-ts.config.ts)[packages/debate-api-client/package.json](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-api-client/package.json)).
- The generation produces request/response types and schemas under `src/generated/`.
- Handwritten files `src/client.ts` and `src/sdk.ts` build on top these definitions to provide:

- **Transport layer:** using `grab-url` for HTTP requests with caching, retry, and rate limit support.
- **Operation functions:** Typed functions named after each API operation, returning `{ data?, error? }` promises; errors are modeled as part of result objects, not exceptions.

---

### SDK Usage

The `debate-api-client` exports operation functions and a preconfigured global `client` object ([packages/debate-api-client/content/docs/packages/debate-api-client.mdx20-55](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-api-client/content/docs/packages/debate-api-client.mdx?plain=1#L20-L55)).

Example usage:

- Each API method returns a promise resolving `{ data?, error? }`, never throwing exceptions directly.
- The global `client` can be customized at runtime or new clients created for isolated configuration.
- Supports caching, retry, and throttling integrated in the `grab-url` transport layer for efficient network usage.

---

### NPM Release Flow

The `debate-api-client` package is the only one published to npm in the monorepo. The release process is automated with a GitHub Actions workflow triggered by a git tag matching `debate-api-client@x.y.z`, defined in `.github/workflows/npm-release.yml` ([.github/workflows/npm-release.yml](https://github.com/debate/debate-ai.com/blob/34937310/.github/workflows/npm-release.yml)[packages/debate-api-client/content/docs/packages/debate-api-client.mdx62-66](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-api-client/content/docs/packages/debate-api-client.mdx?plain=1#L62-L66)).

- The workflow builds the package, runs test suites to ensure stability, and on success publishes the package automatically.
- This process guarantees the `debate-api-client` versioned release matches the source tag and is well-tested before deployment.
