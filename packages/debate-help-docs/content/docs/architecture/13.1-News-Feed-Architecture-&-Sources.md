The News Stream is a unified activity feed for the Debate AI platform, aggregating hand-maintained product updates, automated tool spotlights, and community events into a single, filterable view. It is designed to prevent information silos by surfacing updates from disparate modules—such as the **CARDS** module's Daily Best Card and the **LEARN** module's rankings—into one central stream at the `/news` route [docs/features/news-stream.md1-10](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L1-L10)

## System Architecture

The architecture follows a "projection" pattern where the news feed does not own the source data. Instead, `buildNewsFeed` queries various feature-specific stores and re-shapes their persisted records into a common `NewsItem` type [docs/features/news-stream.md94-104](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L94-L104)

### Data Flow & Composition

The feed is assembled through a multi-layered composition pipeline that resolves package-level circular dependencies at the application root.

## Source Composition Types

The `buildNewsFeed` function aggregates various data sources:

### 1. Static & Synthesized Updates

- **Product Updates (`PRODUCT_NEWS`):** A hand-maintained list of noteworthy feature launches included in `lib/news-stream.ts`. These entries describe new features, fixes, or other significant releases tracked manually by the team [docs/features/news-stream.md16-17](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L16-L17)
- **Tool Spotlights:** The `buildAutoFeatureNews()` function generates synthetic entries for any `APP_FEATURES` catalog item that lacks a corresponding hand-maintained product news post. These entries use an artificially older timestamp to ensure they always rank below official updates, giving all tools some presence in the feed [docs/features/news-stream.md18-27](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L18-L27)

### 2. Announced Stores

These are dedicated announcement data sources which already have explicit announcements persisted:

- **Daily Best Card:** Pulled from `listAnnouncedDailyBestCards()`, this source announces the featured Daily Best Cards per day [docs/features/news-stream.md28-30](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L28-L30)
- **Contributor Awards:** Similar to Daily Best Card, Contributor Awards are sourced from `listAnnouncedContributorAwards()`[docs/features/news-stream.md31-33](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L31-L33)

### 3. Derived Histories

These sources derive news items without requiring a separate announcement step by deterministically analyzing existing logs or histories:

- **Quest Streaks Milestones:** The exact day a contributor reaches a pre-defined milestone streak, found by analyzing daily mission results [docs/features/news-stream.md37-39](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L37-L39)
- **Group Challenges Completed:** Triggered when a challenge's target contribution count is reached [docs/features/news-stream.md40-42](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L40-L42)
- **Top Daily Revision Incentives:** Identifies and announces the top contributor for revision incentives for each UTC day [docs/features/news-stream.md43-45](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L43-L45)
- **Daily Quest Completions:** Announces when a daily quests board is fully completed by a contributor for a given day. This source is volume-capped since completions can occur daily [docs/features/news-stream.md72-81](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L72-L81)

### 4. Atomic Events (Volume Capped)

These are immediate events where each new entry could generate a news item. To prevent feed flooding, only the 20 most recent items per source (defined by `MAX_COMMUNITY_ITEMS_PER_SOURCE`) are surfaced:

- **Sprint Notes:** Recent prep notes logged via Team Collaboration Mode [docs/features/news-stream.md46-52](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L46-L52)
- **Evidence Library Entries:** New cards or analytic blocks submitted and published in the shared evidence library, uncapped aside from the volume cap [docs/features/news-stream.md53-61](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L53-L61)
- **AI Coaching Sessions:** Coaching sessions generated by the AI Coach mode for rounds, injected via dependency injection, because this source is located in `debate-round` which depends on `debate-community`[docs/features/news-stream.md62-71](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L62-L71)

**Sources:**[docs/features/news-stream.md16-81](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L16-L81)

## Circular Dependency Resolution

The News Stream core package (`debate-community`) cannot directly depend on `debate-round`, which exports the `coachingSessionNews()` source, due to circular import issues.

**Solution:**`coachingSessionNews()` is called in the top-level app component `NewsPageContent.tsx` inside `apps/debate-ai.com`, then passed as the `extraItems` prop into the `NewsStreamPanel`, effectively injecting this source at runtime.

| Entity | Location | Role |
| --- | --- | --- |
| `coachingSessionNews()` | `debate-practice-rounds/src/state/coachingSessions.ts` | Generates news items for AI coaching session events |
| `extraItems` | `NewsStreamPanel` prop | Optional array of additional `NewsItem`s to merge into feed |
| `NewsPageContent` | `apps/debate-ai.com/app/news/NewsPageContent.tsx` | Client component that calls `coachingSessionNews()` and passes `extraItems` |

### Feed Assembly Logic

The `buildNewsFeed` function consolidates the various sources into a single array sorted by descending timestamp (newest first). The steps are:

1. Load the hand-maintained `PRODUCT_NEWS` entries.
2. Generate auto-feature spotlight entries from the `APP_FEATURES` catalog.
3. Collect announcements from featured stores like daily best cards, awards, and community-derived items.
4. Merge any injected `extraItems` (e.g., coaching sessions).
5. Sort the combined list by timestamp.

**Sources:**[docs/features/news-stream.md105-106](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L105-L106)

### Viewer State: Read and Like Flags

Each news item can be marked *read* (on hover) and *liked* (toggle click). This state is stored locally for each viewer in `localStorage` under the key `newsStreamViewerState`.

- The viewer-local record holds two arrays:

- `newsRead`: list of read item IDs
- `newsLiked`: list of liked item IDs

These states visually update the UI by showing a "New" badge and a left border highlight for unread items.

However, this local state does not affect or feed back into the source data for the announcements or contribute to aggregated counts elsewhere [docs/features/news-stream.md83-84](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L83-L84)

#### Account-level Sync

For signed-in users, to synchronize read/liked states across browsers and devices, this local state is additionally persisted in the user’s `user_settings` table row with columns:

- `news_read` (text storing serialized read IDs)
- `news_liked` (text storing serialized liked IDs)

See migration:

The React hook `useNewsStreamSync` manages this two-way syncing by:

- Hydrating local state from the `/api/settings` endpoint on mount.
- Pushing updates on state changes back to the server via API.

The design follows a best-effort sync approach where local application of read/like changes is never blocked by server failures, matching patterns elsewhere in the codebase such as `useFavoriteTools` and `UserSettingsPanel`. Successful sync ensures consistent user experience across session contexts [apps/debate-ai.com/lib/hooks/useNewsStreamSync.ts1-67](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/lib/hooks/useNewsStreamSync.ts#L1-L67)[docs/features/news-stream.md83-90](https://github.com/debate/debate-ai.com/blob/34937310/docs/features/news-stream.md?plain=1#L83-L90)[apps/debate-ai.com/drizzle/0013_late_jazinda.sql1-2](https://github.com/debate/debate-ai.com/blob/34937310/apps/debate-ai.com/drizzle/0013_late_jazinda.sql#L1-L2)

## Summary

The Debate AI News Feed architecture composes diverse announcement and event streams, both hand-curated and automatically derived, using a modular layered design:

- **Source modules** publish or synthesize news events as `NewsItem`s.
- `buildNewsFeed` merges these events into a sorted aggregate feed.
- A client-side interactive component `NewsStreamPanel` renders, manages local read/liked state, and syncs with persistence backend.
- The AI Coach Mode source is injected via `extraItems` to avoid package circular dependencies.
- Volume caps apply to high-frequency atomic event sources to contain feed size.

This approach enables a unified presentation of platform-wide important updates and community achievements to users at the convenient `/news` route.
