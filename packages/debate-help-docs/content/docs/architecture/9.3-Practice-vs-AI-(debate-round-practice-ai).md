This page details the TypeScript port of the original Go vs-bot server that powers the "Practice vs AI" feature on debate-ai.com. It covers the implementation of the AI opponent personalities, prompt construction for AI speech generation, AI judging systems, gamification mechanics such as points and badges, and the abstractions for model interaction (`ModelClient`) and data persistence (`DebateStore`). It also explains the API routes under `/api/vsbot` and how the `/versus-ai` page integrates the full feature into the frontend.

---

## Overview

"Practice vs AI" enables users to engage in simulated, full-form timed debate rounds against an AI opponent. Users pick a debate format and side, optionally select an AI persona and difficulty level, then submit speeches turn-by-turn while the AI responds with generated speeches. Post-round, users receive AI judging feedback and gamification points.

This feature is implemented in the `debate-practice-vs-ai` package, a complete TypeScript re-implementation of the original Go backend and its Vite/React client, designed to run inside debate-ai.com as Next.js API routes and React components.

The frontend integrates the `DebatePracticeVsAi` React component, available at `/versus-ai` in the main app, which manages the user interface, interacts with local state stores, and communicates with the `/api/vsbot/*` backend.

## Architecture and Data Flow

The system is split between frontend UI components and backend API handlers communicating via JSON.

### Frontend `/versus-ai` Page and `DebatePracticeVsAi` Component

- The Next.js page at `/versus-ai` mounts the `DebatePracticeVsAi` component, passing user session data (`userId`, `userDisplayName`, `userAvatar`) to personalize the experience.
- This component manages round state persistently stored in browser `localStorage`, including:

- The current practice round setup and metadata.
- The submitted speeches in the round (both user and AI speeches).
- Post-round AI judge feedback.
- It invokes APIs on `/api/vsbot` for:

- Generating AI speeches in response to user turns.
- Generating AI judge decisions and scorecards.
- It also supports gamification progress display and integrates microphone transcription for speech submission.

### Backend `/api/vsbot` Routes

- The backend routes implement the core AI logic, ported from the Go server to TypeScript.
- Key responsibilities include:

- Providing 13 predefined bot personalities with distinct argument styles.
- Constructing detailed prompts for AI models, reflecting round state, opponent persona, and user submissions.
- Managing AI judge reasoning and scorecard generation.
- Handling gamification: awarding points, incrementing win/draw/loss streaks, and granting badges.
- The core abstractions are:

- `ModelClient`: An interface to different AI model providers (Anthropic, Gemini, OpenAI) via `fetch`.
- `DebateStore`: An abstract persistence interface that allows storing rounds and gamification data. For debate-ai.com, a Drizzle/D1 implementation plugs in.
- The package exports a `createPracticeVsAiBackend` function to create handlers for Next.js API routes.
- The `/api/vsbot` routes expect a resolved `DebateActor` that encapsulates the authenticated user; they rely on the host app to handle auth.

### Client-Side State Persistence

- Local state persistence uses the `aiVersusRounds.ts` module from `packages/debate-round`.
- This manages the records of speech submissions keyed by a `roundId`, storing:

- The debate format (`styleKey`), user-chosen side.
- An ordered array of submitted speeches (user and AI), including speech text and speaker role.
- The `buildAiVersusSpeechOrder` helper recreates the turn order from the format and side.
- Speech regeneration is supported on any AI speech, by replacing a single speech in place.
- The frontend synchronizes this state across tabs via `storage` events for live-update.

- The separate `practiceRounds.ts` state module tracks each practice round's setup, post-round feedback, and AI judge decision.

- Round setup like `judgeParadigm`, `opponentPersona`, and `opponentDifficulty`.
- AI-generated feedback and judge verdicts.
- Feedback and judge decisions are derived from the full debate flow and are saved for future inspection.
- Helpers exist to build and save feedback derived from the flow transcript and judge paradigm.

## AI Opponent Personalities and Difficulty

The system includes 13 AI bot personalities, each representing a distinctive debate style, ported from the 1000-line Go personality switch.

### Example Personas

- **Neutral:** A balanced, default persona.
- **Rookie Rick:** Beginner-level guidance-focused bot.
- **Darth Vader:** Aggressive, thematic character.
- **Policy Heavy:** Emphasizing advanced theory like counterplans and disadvantages.
- **Kritik:** Focuses on framework and critical theory.
- **Lay:** Uses simple non-jargon language.
- **Fast Flow:** Maximizes argument volume and speed.

### Difficulty Levels

Each persona supports configurable difficulty levels determining speech characteristics and strategy:

- **Beginner:** Drops arguments, argues slowly, and produces simpler extensions.
- **Intermediate (default):** Generally follows the persona description.
- **Advanced:** Catches argument drops, uses strategic extensions.
- **Elite:** Tournament-elite style with complex strategy and thoroughness.

### Prompt Construction

- The persona and difficulty combine to generate detailed AI prompts for speech generation.
- Prompts include:

- The bot's personality description.
- The selected difficulty's style modifiers.
- Prior speech history.
- The current speech context.
- This modular prompt construction ensures coherent, persona-specific responses from the AI models.

## AI Judging and Scorecards

- After a full debate round, users may request AI judging.
- The judging system:

- Uses the saved `judgeParadigm` from the round setup.
- Retrieves a summary of the debate flow.
- Builds a judge decision prompt input.
- Calls the AI judge model via the `/api/vsbot` endpoint.
- Saves the resulting `JudgeDecisionAiResult` data back onto the practice round record.
- Judging covers win/draw/loss verdicts, skill feedback, and flaw analysis.
- The judge decisions system is extensible to multiple judging paradigms and styles.

## Gamification: Points and Badges

- The gamification module ported from Go defines:

- Points allocation for wins (50 points), draws (25 points), losses (10 points).
- Badge thresholds such as `FirstWin`, `Novice`, `Streak5`, and `FactMaster`.
- The system tracks users' practice round results and awards points and badges accordingly.
- This encourages continued practice and skill development via AI rounds.

## ModelClient and DebateStore Abstractions

### ModelClient

- Abstract interface for a client calling AI models.
- Supports multiple implementations:

- Anthropic.
- Gemini (with 4 safety/blocking modes).
- OpenAI.
- Implements prompt sending and response retrieval via simple `fetch` calls.
- Allows easy swapping or multi-provider support.

### DebateStore

- Abstract interface for debate data persistence.
- Abstracts over storage such as MongoDB in Go and Drizzle/D1 in debate-ai.com.
- Supports storing practice round metadata, game state, and gamification info.
- Enables host app to inject appropriate storage backend.

## API Routes `/api/vsbot/*`

The `/api/vsbot` routes are implemented using the backend code in the `debate-practice-vs-ai` package:

- **POST /api/vsbot/create**
Create a new practice debate round.
- **POST /api/vsbot/speech/generate**
Generate an AI speech for a round turn, given prior speeches and opponent persona.
- **POST /api/vsbot/judge**
Generate an AI judge decision for a completed round.
- **POST /api/vsbot/submit**
Submit a user speech, advancing the round state.

Each handler receives an authenticated `DebateActor`, request payload, and returns a status/body response. They call into the AI logic modules, prompt builders, ModelClient, and DebateStore implementations.

# Summary

The `debate-round-practice-ai` package delivers a fully featured, AI-driven practice debate round experience as a TypeScript port of a sophisticated Go server originally implemented for AI vs human debate rounds. It provides a robust and modular backend AI logic system, richly configurable AI personas, integrated AI judging, persistent state management, and gamification mechanics. The `/api/vsbot` routes leverage this backend, while the frontend `/versus-ai` page hosts the user-facing interface, completing a tightly integrated practice environment within the debate-ai.com platform.
