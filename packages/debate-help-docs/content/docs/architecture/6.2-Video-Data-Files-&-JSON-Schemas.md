This page documents the flat-file JSON database structure used by the LEARN module to store and serve debate video metadata. The system utilizes a positional array format to minimize file size while maintaining a strict validation contract via JSON Schemas.

## Overview of Data Storage

Debate AI uses a "flat-file" approach for its video library. Instead of a traditional relational database for video metadata, the platform stores thousands of round records in version-controlled JSON files within the `packages/debate-data-sync/data/videos/` directory. This allows for rapid global distribution via CDNs and enables easy contributions via Pull Requests.

## The 17-Field Positional Format

To optimize for payload size, debate rounds are stored as an array of arrays rather than an array of objects. Each inner array represents a single video and must contain exactly **17 fields** in a specific order.

### Field Mapping (Schema Contract)

| Index | Field Name | Type | Description |
| --- | --- | --- | --- |
| 0 | `youtubeId` | String | The 11-character YouTube video ID |
| 1 | `title` | String | Original YouTube video title |
| 2 | `date` | String (ISO) | ISO-8601 upload date (YYYY-MM-DD) |
| 3 | `channel` | String | YouTube channel name |
| 4 | `duration` | Number | Video length in seconds |
| 5 | `description` | String | YouTube video description |
| 6 | `style` | Number (Enum) | Debate style as an enum: 1 (Policy), 2 (Public Forum), 3 (Lincoln-Douglas), 4 (College) |
| 7 | `tournament` | String | Extracted tournament name (e.g. "2026 TOC") |
| 8 | `round` | String | Round type (e.g., "Finals", "Octas", "R3") |
| 9 | `aff` | String | Affirmative team/debater name |
| 10 | `neg` | String | Negative team/debater name |
| 11 | `affWon` | Boolean/Null | True if Affirmative won, False if Negative won, Null if unknown |
| 12 | `decision` | String/Null | Judge names and vote count (e.g., "3-0"), or null |
| 13 | `affCase` | String/Null | Short summary of Affirmative case arguments |
| 14 | `negCase` | String/Null | Short summary of Negative case arguments |
| 15 | `isFeatured` | Boolean | If true, appears in featured sections |
| 16 | `tags` | Array/Null | Optional categorization tags |

This compact positional format reduces JSON size and is enforced via JSON Schema validation (see below).

### Lectures Format

The `debate-lectures.json` file uses a simplified 7-field array format that captures educational or topical content:

| Index | Field Name | Type | Description |
| --- | --- | --- | --- |
| 0 | `youtubeId` | String | YouTube video ID |
| 1 | `title` | String | Video title |
| 2 | `date` | String (ISO) | Date posted |
| 3 | `channel` | String | YouTube channel |
| 4 | `duration` | Number | Length in seconds |
| 5 | `description` | String | Video description |
| 6 | `category` | String | Content category tag (e.g., "Round Analysis") |

This structure supports lectures, analyses, topic introductions, and research videos.

### Handling of Metadata Nuances

- **Lincoln-Douglas (`rounds-ld.json`)**: Fields 13 and 14 commonly contain case-specific philosophical or strategic notes (e.g., "Greatest Hits", "Topicality") that are useful for deep searching or filtering [packages/debate-data-sync/data/videos/rounds-ld.json17-19](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/data/videos/rounds-ld.json#L17-L19)
- **Public Forum (`rounds-pf.json`)**: Often includes detailed judge panel information and decision specifics in the decision field [packages/debate-data-sync/data/videos/rounds-pf.json10-17](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/data/videos/rounds-pf.json#L10-L17)
- **College (`rounds-college.json`)**: Includes data from National Debate Tournament (NDT) rounds with extensive metadata about teams and judges [packages/debate-data-sync/data/videos/rounds-college.json101-110](https://github.com/debate/debate-ai.com/blob/34937310/packages/debate-data-sync/data/videos/rounds-college.json#L101-L110)
