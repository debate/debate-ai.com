# REASON docs sidebar — files on the document routes, opened in Debate Editor

The two collapsible sections, **Topic Starters** and **My Personal
Documents**, that are the whole sidebar on `/reason-editor`, and the URL round trip that turns a click on one of them into "that
file, loaded in Debate Editor, in the main column."

- **Routes:** `/research/cards` (and below it) and `/reason-editor` — the routes the
  documents are the subject of, per
  `apps/debate-ai.com/lib/reason-docs/sidebar-routes.ts`
- **Panels:** `packages/debate-webview/src/components/reason-docs/`
  (`ReasonDocsSidebarPanels`, `FileTree`, `TopicStarterTree`,
  `FileManagerDialog`), over `ReasonDocsProvider` in the
  root layout
- **URL rules:** `apps/debate-ai.com/lib/reason-docs/route-selection.ts`
- **Where they show:** `apps/debate-ai.com/lib/reason-docs/sidebar-routes.ts`
- **Editor:** `/reason-editor` (`debate-editor`'s Debate Editor embed), with
  its tab strip in `components/reason-editor/EditorTabStrip.tsx` and the tab
  rules in `lib/reason-docs/tab-actions.ts`

## Where the panels mount

`ReasonDocsSidebarPanels` is one component mounted in two places:

1. `AppSidebarShell`'s `<aside>`, on the routes `showsReasonDocsPanels`
   admits — `/research/cards` (the dock's "Shared" destination, and any page below
   it) and `/reason-editor`, whose desktop file navigation *is* this
   sidebar, the editor route having no `<aside>` of its own.
2. `/reason-editor` itself, as a collapsible strip below `md`, since that
   sidebar is `hidden md:flex`.

They are deliberately absent everywhere else. The panels used to ride in
every sidebar, `/videos` included — which took a third mount, an app-owned
`docsSlot` on `LecturesPage`, since `/videos` renders its own sidebar rather
than the shell. That put a document tree above the video library's own nav
on a page that is not about documents; the slot is gone and the videos
sidebar is the dock plus the video nav. The trade is that
a file opened from `/research/cards` is no longer one click away after hopping to the
video library — the dock hop back is.

On `/reason-editor` the two sections are all the sidebar shows: they sit
under the dock and share the rest of the column's height, and the Videos
library tree and tool sections are not drawn. The dock stays as the way back
out; any other destination brings the full tree back. The phone drawer does
the same, with the bottom dock as the way out. Topic Starters comes first,
then My Personal Documents. There is no panel switcher and no Open Tabs list: the
open files are the tab strip above the editor (below).

Each section has a chevron header and is expanded by default. Collapsing one
sticks, per-device, in `localStorage` (`reason-editor-sidebar-topics-open`,
`reason-editor-sidebar-files-open`). Nothing is fetched until a section is
actually open, so a page that leaves both collapsed makes no document
request at all.

## Tabs above the editor

Every file opened on `/reason-editor` gets a tab in the strip above
Debate Editor — your own documents and public topic starters alike. Clicking a
topic starter opens it in a new tab beside whatever is already open instead of
replacing it; clicking one that is already open switches to its tab. Click a
tab to switch to it, or its × to close it.

Each tab keeps its own undo history for the session: Undo in one tab only
walks back edits made in that tab, and switching away and back keeps both the
edits and the history. Reloading the page starts every tab's history fresh.

Right-click a tab for:

- **Close** that tab.
- **Close others**: every tab but this one, which becomes the open file.
- **Close to the right**: every tab after this one.
- **Close all**.
- **Undo close**: reopens the most recently closed tab. It walks back through
  the last 20 closed tabs, skipping files deleted since.

Closing the open tab moves to its neighbour, preferring the tab that slid
into its place.

## Opening a file

Picking a file — an owned document or a public topic starter — does two
things:

- sets it active in `ReasonDocsProvider`, so a client-side hop switches the
  editor instantly; and
- routes to `/reason-editor/<the file's name>` — `/reason-editor/cp-answer-to-states`,
  not `/reason-editor?topic=2` — so the selection is addressable, and legible
  in a shared link.

Provider state alone covers the hop but not a reload, a pasted link, or a
hard navigation — `/videos` is its own layout branch and can boot the editor
with an empty provider. Carrying the file in the URL is what makes "click a
file, get *that* file in Debate Editor" hold from every sidebar rather than
only from the ones that hop client-side.

The name is the title slugified (`lib/reason-docs/doc-slug.ts`): lowercased,
accents folded, apostrophes dropped, everything else non-alphanumeric
collapsed to single hyphens, capped at 80 characters on a word boundary, and
`untitled` when a title leaves nothing behind. Titles are not unique and ids
are, so two files that slugify the same are told apart by a `~<id>` suffix —
`impact-turns~d12` for document 12, `impact-turns~t7` for topic starter 7.
No title can forge one: `~` is stripped out of titles by the same slugifier.

Already on the editor route, a pick routes nothing at all. `/reason-editor`
and `/reason-editor/<slug>` are separate Next routes, so routing between
them would remount Debate Editor — and its undo history — on every tab switch;
the provider already has the file open, and `ReasonDocsRouteSync` renames
the address bar in place with `history.replaceState`. That same rewrite is
what upgrades an older `?doc=<id>` / `?topic=<id>` link (still read, and
still resolved) to the named path once the catalogue says what that file is
called, and what keeps the address on a file that is renamed while open. Any
other query parameter is kept — `?share=` and `?shareWith=` are read by the
same page.

`ReasonDocsRouteSync` (mounted once on `/reason-editor`, inside a
`<Suspense>` since it reads `useSearchParams`, renders nothing) reads it
back. The rules themselves are pure functions in
`lib/reason-docs/route-selection.ts`, shared with the sidebar so the two
ends of the round trip cannot drift, and unit-tested in
`lib/reason-docs/__tests__/route-selection.test.ts`.

Resolution order, per URL:

1. the path's name — an exact `~<id>` discriminator first, then the bare
   slug matched against topic starters and then the reader's own documents,
   then the segment read as an id;
2. the URL's `topic` id, if it names a live topic starter;
3. the URL's `doc` id, if it names one of the reader's own non-folder
   documents;
4. otherwise, and only when nothing is open, the first file — so the reader
   lands on something readable instead of an empty pane.

A name or id that matches nothing (a renamed file, a deleted one, someone
else's link) falls through to that same fallback rather than erroring — a
stale link is not a 404 — and a malformed id (`?doc=abc`, `?doc=3.5`) reads
as absent. The deep link applies once per URL: after it opens its file the
reader can pick another from the sidebar without the stale URL dragging them
back, and every pick rewrites the address, which re-arms it.

The deep-link rule and the first-file fallback are one function on purpose.
As two React effects they raced: the fallback's closure still saw no
selection in the commit where the deep link opened its file, and opened the
first file over the top of it.

## Topic starter addresses: `/docs/<topic code>/<file>`

A public topic starter's link names the resolution it is for and the file's
path in the library:
`/docs/vcx27/neg/cp/aca-expansion-cp-cndi-2026`. The topic code is the
format, the last two digits of the year in `debate-topics.json`, and — for
the formats that change topic during the season — a letter for which topic
of that year, in start-month order:

| Format | Code | Example |
| --- | --- | --- |
| High-school policy | `vcx<yy>` | `vcx27` (National Health Insurance) |
| College policy (NDT/CEDA) | `ndt<yy>` | `ndt27` |
| Lincoln-Douglas | `ld<yy><a-e>` | `ld27a` (September), `ld27b` (November) |
| Public Forum | `pf<yy><a-g>` | `pf27a` |

Two dropdowns on one line above the Topic Starters tree — a small **format**
picker and the **topic** picker — go to a topic's address. The topic dropdown
lists every topic the format has had, grouped by year, newest first. A bare `/docs/<topic code>` opens the first starter, and every starter
opened after that keeps the code in its link.

These addresses share `/docs` with the help docs, so only a first segment
shaped like a topic code is the editor's — no help page is named like
`vcx27` or `ld27a`. `next.config.mjs` rewrites exactly that shape onto the
`/reason-editor` page (a `beforeFiles` rewrite, ahead of the help docs'
catch-all), and `isDocsPath` leaves it out so the app shell rather than the
help-docs chrome renders it. The rules are in
`packages/debate-webview/src/lib/reason-docs/topic-doc-paths.ts`; the
resolution list and its codes in `topic-codes.ts`.

Older links keep working: `/reason-editor?topic=neg/cp/aca-expansion-cp-cndi-2026`
still opens the file, and `ReasonDocsRouteSync` then rewrites the address to
`/docs/vcx27/neg/cp/aca-expansion-cp-cndi-2026`. A link with no code — that
one, or a starter opened while on `/reason-editor` — gets the default code,
the newest high-school policy topic (`DEFAULT_TOPIC_CODE`).

**Known gaps:**

- The library itself is not split by topic yet: every code shows the same
  Topic Starters tree, and a file opens under whichever code is in the
  address. The code says which topic the reader is browsing; it does not
  filter the files.
- The redirect from `?topic=` is client-side (a `history.replaceState` once
  the catalogue loads), not an HTTP 308.
- The browser extension's route table (`routes/index.ts`) has no
  `/docs/<topic code>` pattern; there the old `?topic=` form is still the
  working link.

## Read-only topic starters

A topic starter opens in the same Debate Editor embed as an owned document, but
read-only: no toolbar, no AI tools, no `onChange`, a `readOnly` title, and a
"Public topic starter" label beside it. It gets its own `contentKey`
namespace (`topic-<id>`) so the engine treats it as a distinct claim from an
owned document that happens to share the id — the same reason `?doc=7` and
`?topic=7` are different URLs.
Its tab id is the row id negated (`lib/reason-docs/tab-ids.ts`), so topic
starter 7 and document 7 are two tabs in the same strip.

## Topic starters are stored as `.cmir`

The admin importer on `/admin` takes a `.docx` (or a `.zip` of them) and
stores each one as a Debate Editor native file — `.cmir`, gzipped JSON,
base64-encoded into the row's `content` column, with `format` set to
`"cmir"`.

The conversion is Debate Editor's own OOXML importer (`docxToCmir` in
`packages/debate-editor/src/native/convert.ts` — `fromDocxFull` piped into
`serializeNative`, the same pair the desktop bulk converter runs), wrapped
for the route by `packages/debate-webview/src/lib/topic-starters/import.ts`. What that
buys over the card HTML the importer used to store is everything HTML has no
element for: the Verbatim outline (pocket / hat / block / tag / analytic) as
typed nodes rather than `<h1>`…`<h4>`, comment threads, inline images, and
the named character styles that distinguish a cite from an emphasis from a
plain underline.

Reading it back is client-side: `topicStarterHtml`
(`lib/topic-starters/content.ts`) parses the file with `parseNative` and
serializes it through the schema's own `toDOM` specs for the embed's
`content` prop, memoized per file on `/reason-editor`. Doing it in the
browser keeps the catalogue endpoint — which returns up to 100 rows — from
converting files nobody opens.

Rows imported before this carry HTML and still open: `format` says which a
row is (`lib/topic-starters/format.ts`), and content that arrives without
its row falls back to sniffing the bytes for the gzip magic. A `.cmir` that
will not parse renders a notice naming the failure rather than a blank
document.

## Organising files

Every file is a Debate Editor file whatever it was uploaded as, so no row in
either tree carries a `DOCX` or `CMIR` badge; the name is the whole label.

Right-clicking a row opens the same menu as its "…" button, so every action
on a file is one gesture from the file itself:

- **Files:** Open, Edit, Share…, Rename, Duplicate, Move to (any folder, or
  the top level), Download as .docx, Add to Topic Starters, Delete. Folders
  get New File / New Folder in place of Open, Edit and Share.
- **Topic Starters:** Open, Edit a copy, Save to my files, Copy link,
  Download as .docx, and — when you're signed in — Rename, Move to and
  Delete (folders also get New folder). A topic starter's *contents* are
  still edited by editing your own copy of it; the menu rearranges the
  catalogue (see "Editing Topic Starters" below).

**Share…** opens the file in the editor with the share-with-contacts dialog
already up (`?shareOpen=1`, read and stripped by `ShareWithContacts`).
Sharing starts a live co-editing session in the editor, which is why the file
has to be open there first.

The **Sort** button in the My Personal Documents header orders the tree by name (A–Z or Z–A)
or by last modified (`lib/reason-docs/file-sort.ts`). Folders always come
before files. The choice is remembered per device.

## Moving files between Files and Topic Starters

Rows drag both ways between the two trees, and each drop means what it can
(`lib/reason-docs/drag-data.ts`):

- **Topic Starters → Files:** saves your own copy into the folder you drop
  on. A folder comes with everything in it, and a `.cmir` stays a `.cmir`.
  "Save to my files" in the menu does the same.
- **Files → Topic Starters:** submits the file to the public catalogue.
  Anyone signed in can; a moderator's or admin's file goes in at once, and
  anyone else's waits for a moderator's approval.
- **Topic Starters → Topic Starters:** moves the row into the folder you drop
  on (signed in only, moderated the same way). A folder can't be dropped into
  itself.
- **Files → Files:** moves the row, as before. A folder can't be dropped into
  itself.
- **Desktop → either tree:** an upload, as before.

## Editing Topic Starters

Signed-in readers can rearrange the public catalogue from the sidebar:
rename, move (menu or drag), delete, add folders (the folder button in the
section header, or New folder on a folder's menu) and submit their own files
(drop one from Files, or "Add to Topic Starters"). Moderators and admins
control the catalogue: their edits apply at once. Everyone else's edit is
sent to them for approval — the toast says "Sent to the moderators for
approval" — and nothing changes in the tree until a moderator approves it.

Moderators get a notification for each proposal, and review them on `/admin`
under **Topic starters**, which also shows every public topic starter as a
tree they can rename, move, delete and add folders in directly. Approving a
change applies it; one that no longer fits (its file was deleted meanwhile)
stays in the queue with the reason, to be rejected.

The importer itself (**Imports → Topic Starter library**) shows the same
catalogue under its upload form — including files imported with "Share
publicly" off — and reloads it after each upload, so an admin can tidy up
what a ZIP produced on the spot. Right-click a row (or use its "…" button)
to Rename, Copy, Paste, Move to a folder, Delete (a folder goes with
everything in it, after a confirm) or add a New folder; rows also move by
dragging one onto a folder. Paste puts a full copy of the copied file or
folder into the folder you right-clicked, or beside the file you
right-clicked, with " (copy)" added when it lands next to the original.
Those edits go to `PATCH` / `DELETE /api/admin/topic-starters/[id]`,
`POST …/[id]/copy` and `POST …/items`, and change what Debate Editor shows
everyone (`TopicStarterLibraryTree` in
`packages/debate-webview/src/components/admin`).

### Organize by argument (AI)

The sparkle button in the Topic Starters header asks the AI to sort every
public file by side and argument type: affirmative cases under **Aff/Case**,
and the negative's positions under **Neg/DA**, **Neg/CP**, **Neg/T** and
**Neg/K** (answers to an argument keep its type and take the side that reads
them, so "AT Elections DA" in an aff file lands in **Aff/DA**; anything else
goes under **Theory** or **Other**). The AI reads only file and folder names,
never the files. It shows its proposal — how many files go where — before
anything moves; confirming applies it for moderators and sends it for
approval for everyone else. Existing `Aff`/`Neg` folders are reused, files
already in the right folder are left alone, and folders the moves empty are
removed.

**How it works.** Every edit is a change record
(`@debate-ai/webview/lib/topic-starters/changes`): `move`, `rename`, `delete`,
`create-folder`, `submit` or `reorganize`. `POST /api/topic-starters/changes`
applies it for staff and otherwise stores it in `topic_starter_changes`
(created on first use) for `GET /api/admin/topic-starters/changes` and
`POST /api/admin/topic-starters/changes/[id]` (`approve` / `reject`).
Approval runs the same `applyTopicStarterChange` a staff edit does, so the
two can't disagree. `POST /api/topic-starters/organize` returns the AI's
`reorganize` change without applying it; it classifies at most 600 files, in
batches of 150, with the site's AI key.

## File manager

The File manager button in the My Personal Documents header opens a full-window file
manager over the same files: SVAR's `@svar-ui/react-filemanager`, the widget
quick search's REASON sidebar opens from its own file manager dialog. Every
action it offers is routed back to the real rows
(`components/reason-docs/file-manager/FileManagerView.tsx`, with the path ↔ row mapping
in `lib/reason-docs/file-manager-data.ts`):

- **Open** (double-click or Enter) opens the file in this app's editor.
- **Add file, add folder and upload** create rows in your folders.
- **Rename, delete, cut/paste and drag** rename, delete and move your rows.
  **Copy/paste** duplicates them.
- **Download** is the same `.docx` download as the sidebar menu.

Topic Starters appear under a read-only "Topic Starters" folder. Copying or
moving out of it saves your own copy. Copying or moving one of your files
into it submits it (straight in for moderators, for approval otherwise). Renaming or deleting inside it is
refused. The widget is loaded only when the dialog first opens.

## Searching files from Ctrl/Cmd-K

The app-wide search palette (Ctrl/Cmd-K) lists matching files under
**Files**, below the tools: your own files and the public Topic Starters,
matched by name, folder, **outline headings and contents**
(`lib/reason-docs/file-search.ts`). Every word you type has to appear
somewhere. Name matches rank first, then outline matches (a pocket, hat,
block or tag heading holding every word, shown as `§ Heading`), then contents
matches, which show the text around the match. Picking a file opens it in the
editor.

Below the files, **Videos & Lectures** lists up to eight matches from the
whole video library, rounds and lectures alike, most-viewed first. The
palette asks the Videos page's own feed (`/api/videos?q=…`) once typing
pauses, so nothing about the library is downloaded until you search. Picking
one opens its watch page (`lib/videos/video-palette-search.ts`).

A `.cmir` file's text is read with Debate Editor's engine, which is loaded the
first time a query needs it, so the first search over card files can take a
moment longer. On `/reason-editor` the palette answers Ctrl/Cmd-K, while
Ctrl/Cmd-P stays the editor's own palette.

## Save status above the editor

The status line over the REASON editor (`/reason-editor`) says where the open
document stands: **Unsaved changes** (an edit is queued), **Saving…**, or
**Couldn't save — retrying** (shown in red; your edits stay in the tab and the
queue retries with backoff). Once the document is saved the line disappears. A public topic starter
reads **Public topic starter** because it is read-only. The text comes from
`describeDocSaveStatus` (`lib/reason-docs/doc-save-status.ts`).
