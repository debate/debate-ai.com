## Legacy Verbatim / Debate Editor Compatibility [#legacy-verbatim-shortcuts]

Debate Editor ==has the same keyboard shortcuts as Verbatim==, so a
Verbatim-trained debater's habits work in any Debate Editor document. In the
table, **Mod** means Ctrl on Windows and Linux and ⌘ on a Mac.

### Shortcuts

| Shortcut | Command |
| --- | --- |
| `F10` | Apply Emphasis |
| `F8` | Apply Cite |
| `F9` / `Mod-u` | Toggle Underline |
| `F3` family | Condense variants |
| `Mod-Alt-ArrowUp/Down` | Move card/section |
| `Alt-F8` | Copy previous cite |
| `Mod-Shift-k` | Insert short cite tag |
| `Mod-Shift-x` | AI-format a citation |

==Every binding is user-remappable== in Debate Editor's keybindings editor. The
shortcuts reference has Print and Export actions, and ==a one-time onboarding
nudge points a Verbatim-trained user at it==. ==Print and Export both scope to
an active search== — typing into the reference's search box before printing
or exporting narrows the output to the matching rows, the same way it
narrows the on-screen list.

## Offline Storage [#offline-storage]

==Where Debate AI keeps your work on this device==, and ==how to get unlimited
offline storage with the browser extension==.

Find it in **Settings → Storage on this device**.

### What it does

- **==Your account is the real copy==.** Signed in, your flows, rounds, cards and
  settings are ==saved to your account and follow you to any device==.
- **==The browser keeps an offline copy==** ==so you can keep flowing without a
  connection==. Flows, rounds and flow history live in the browser's database, ==which has
  room for gigabytes==; ==the browser's small settings storage is kept for
  preferences only==. You will not see "storage quota exceeded"
  warnings, and ==nothing is deleted to make room==.
- **==The browser extension makes it unlimited==.** Install the Debate AI
  extension and it asks for the *unlimited storage* permission. While it is
  installed, ==the site mirrors its offline copy into the extension, where no
  browser quota applies==, and ==restores from it if the browser ever clears the
  site's own copy==.

The Settings card ==shows which of these is active on this browser==: whether the
offline copy is in the browser database, whether the extension is connected,
how much space the site is using, and ==whether the browser has agreed not to
clear it==.

Older versions kept flows in the browser's small settings storage. The first
visit after updating ==moves them into the browser database automatically and
frees that space==.

## Quick Cards Cloud Save [#quick-cards-cloud-save]

==Syncs your Debate Editor Quick Cards (your library of reusable snippets) to
your account when you're signed in==, like your flows, rounds, word-count
history, judge decisions, editor documents and Speech Documents send log.
Before this, ==the library lived on one device only==.

### What it does

When the editor opens, ==your library is merged once with your account==: ==a card
saved from another device but missing here is added==, and a card that exists
only here (saved offline, or before this feature) is uploaded — ==neither side
ever overwrites the other, it only fills gaps==. After that, every card you add,
edit, import, delete, or clear ==is saved to your account==. Signed out, ==the
library keeps working exactly as before, on this device only==.

==An edit never overwrites a newer one==: if a card was changed on another device
and that change hasn't reached this browser yet, ==this browser takes the newer
version instead of losing it==.

## App nav dock and tool sidebar [#app-nav-dock]

==The macOS-style icon dock that carries the app's main destinations==, and
==the sidebar it sits in on nearly every page==.

### The dock [#app-nav-dock-the-dock]

==Five destinations== — Videos, Shared, Debate, Practice vs AI, Research — ==plus a
gear-icon Settings menu==, with **Alt+1** to **Alt+5** ==as shortcuts in dock
order==. ==Hovering an icon (or tabbing to it) shows its name==.

==Every dock icon opens its page==; **the gear opens one menu** for both getting
around and settings, top to bottom:

- **Search** (the Command Palette), then a submenu for each sidebar section —
  **Videos, Research, Practice Debates, Insights** — with the same links the
  sidebar has. On a phone, ==this is how you reach every sidebar link==.
- **Settings**, then a **Themes** submenu holding the light/dark switch, the
  Light / Dark / System choice and the color themes.
- **Hide Dock**, a Site Links submenu (Features, Docs, GitHub, Support, Privacy,
  Reddit and the other site links), and your account.

==Tools aren't dock icons==: they're in the sidebar's Research, Practice Debates
and Insights sections, and the full catalog is the **Features** row in Site
Links.

#### Hiding the dock [#app-nav-dock-hiding-the-dock]

Choose **Hide Dock** in the gear menu and ==the row of icons folds away to a small
arrow tab==: hanging from the top-left corner or the top of the sidebar, or
rising from the bottom of the screen on a phone. Hover the tab (or Tab to it, or
tap it) and ==the full dock slides back; move away and it folds up again==. ==It
stays out while one of its menus is open==, and the same menu's **Show Dock** puts
it back for good. ==The choice holds on every page and is remembered in this
browser==.

### The sidebar [#app-nav-dock-the-sidebar]

==Every page draws the same sidebar==: the dock, then **Videos** and the Research,
Practice Debates and Insights sections, then a **Docs** section listing every
help page, then the site links on one compact line. In these docs, ==the docs'
own page list is a section of the sidebar== too. A few pages add their own
panels to it, such as the document panels in the card search and Debate Editor.

- **One section open at a time.** ==Opening a section closes the one that was
  open==, and ==the section for the page you're on opens by itself==. Clicking a
  section heading only opens or closes it; ==each section's main tool is its first
  link==. You can still open another section by hand.
- **Only the page you're on is highlighted**, and ==its row scrolls into view== if
  it's off screen. Team Rankings stays highlighted while you're reading a team or
  school page.
- **Every tool has its own small grey icon**, so ==a long section can be scanned
  by shape==.
- **Icons that move.** ==On by default==; turn off **Animate sidebar icons** in
  Settings → General to stop it. Hovering or tabbing to a row ==makes its icon
  wiggle, bounce, pulse==, spin and so on, ==a different one each time==, at most
  once every three seconds. If your system asks for reduced motion, ==the icon
  only changes colour==.

#### The bottom of the sidebar [#app-nav-dock-the-bottom-of-the-sidebar]

==The account menu is pinned at the bottom==, with a **Settings** button and the
**hide button** beside it. ==Settings opens the tab that fits the page you're on==.
The row shows your picture and name, ==never your email address==, with a badge
==counting unread notifications==. The account menu holds Settings, a
**Notifications** submenu (open a notification, clear it, or **Clear all**), a
**Switch account** submenu (see [Switching accounts](#app-nav-dock-switching-accounts)), a **Theme**
submenu (==synced to your account==), the site links, and Sign out. ==Signed out,
the row is a Sign in button== that ==opens the sign-in dialog without leaving the
page==. Organizations are not in this menu; manage them from
[Contacts](/docs/features/team-collaboration#contacts-organizations).

**Docs** and **Settings** ==are always just above the account row==, on every
page, ==so you never have to open a menu to reach them==.

#### Switching accounts [#app-nav-dock-switching-accounts]

==You can stay signed in to up to five accounts in one browser== — say, your own
and a team or coaching account — ==and switch between them without signing
out==. Open the account menu and choose **Switch account**:

- ==Pick an account to switch to it==. The page reloads as that account.
- **Add another account** ==opens the sign-in dialog while keeping you signed in
  to the current one==. After you sign in, the new account is the active one.
- The **X** beside an account ==signs just that account out==. **Sign out of**
  *name* ==signs out the account you're using and switches to another==.

==With more than one account signed in, the menu's last item reads== **Sign out
of all accounts**, ==which signs every account on this browser out==.

#### Resizing the sidebar [#app-nav-dock-resizing-the-sidebar]

==Drag the thin line on the sidebar's right edge to make it wider or narrower==.
==The width is remembered in this browser== and ==every page opens the sidebar at
that width==. ==Double-click the line to reset it==. The line also takes keyboard
focus, and ==the arrow keys resize it==.

#### Hiding the sidebar [#app-nav-dock-hiding-the-sidebar]

==Hide the sidebar with the panel button at its bottom-right==, with **Ctrl+B**
(**⌘B** on a Mac), or by dragging its edge most of the way in. ==The page then
takes the full width==, and ==a small tab on the left edge brings the sidebar back==,
as do the same shortcut and dragging the edge out. ==The choice holds on every page
and is remembered in this browser==. While you're typing in an editor or a text
box, Ctrl/⌘+B stays **bold** ==and doesn't touch the sidebar==.

**Peeking.** ==While the sidebar is hidden, move the pointer to the very left edge
of the window== and ==it slides out *over* the page== without pushing it aside. Move
away (or press Esc) and it slides back; ==pin it with the panel button==, which
reads **Keep sidebar open** while peeking. Each time it comes or goes it ==plays
one of ten animations at random==, ==none if your system asks for reduced motion==.

==While the sidebar is hidden the dock floats at the top-left==, ==so the main
destinations stay one click away==.

**Pages with their own sidebar.** The flow workspace and the research docs ==have
a sidebar of their own==, so there ==the app sidebar starts hidden==. ==It still
peeks from the left edge==.

### On a phone [#app-nav-dock-on-a-phone]

==The dock is a bar along the bottom of the screen==, starting with a **Sidebar**
button that ==opens a drawer from the left==. What the drawer shows depends on the
page: the sidebar sections on most pages, the document panels in the card search
and Debate Editor, or the flow workspace's own flows and rounds. ==The drawer
closes when you go to another page==.

### Video library [#app-nav-dock-video-library]

- **All Videos** ==is the first row under **Videos**, lists every round and lecture,
  and is the home page==. **Lectures** is a single row at the end of the section;
  ==the lecture categories are a bar of cards at the top of the lectures page==
  (see [Lecture categories](/docs/features/video-library#video-library-lecture-categories)).
- ==Only the collection you're browsing is highlighted== (All Videos, Lectures,
  College Policy, HS Policy, LD, Public Forum, Greatest of All-Time, My
  Favorites, Watch History).
- **Search floats over the results.** ==A small magnifier in the top-right corner
  of the results== opens the search box, filters, sort and grid/rows toggle over
  the results. ==It stays open while you're typing or a search is active==, closes
  on Escape or a click outside, and ==keeps what you typed==.
- **Results open as rows** — ==about four times as many per screen as the
  thumbnail grid==, which is one toggle away in the search panel.

### Moving between pages [#app-nav-dock-moving-between-pages]

==Switching pages keeps the dock, the sidebar and the video player in place==, so
==a lecture keeps playing as you move around==. The dock ==loads its destinations
ahead of time== so a switch is quick (but not on a data-saver or 2G connection).
==A slim bar across the top of the window shows a page switch in progress==, like
YouTube's; ==switches that finish almost at once don't show it==. The
[Features page](/docs/features/ui-navigation#features-page) opens inside the app
like any other page. ==These docs are a separate site==, so links into them load a
new page, and ==outside sites open in a new tab==.

### Good to know [#app-nav-dock-good-to-know]

- The flow workspace and the research docs ==still have their own sidebars
  instead of the shared one==.
- ==On a pen or touch screen that reports hover, a hidden dock opens on a tap==, and
  folds again on the next page or a second tap on the tab.
- ==In these docs the search box is in the header==, and with the sidebar hidden
  ==the docs have no dock==.

## Features Page [#features-page]

==One page that outlines every user-facing surface in the app==: each
feature's name, a one-line description, its route, and a link to its
long-form doc, ==grouped into eight categories and filtered by a search box==.

Find it at **/practice/features**.

### Why this exists [#features-page-why-this-exists]

==Nothing else in the app lists everything it does== — the dock's Settings menu
is a flat list of forty-odd items, and the Research and Coaching workspaces
each cover only their own tools. ==This page is the map==.

### What it shows [#features-page-what-it-shows]

The project's banner and badges, a count of features, ==a strip of the five
workspace screenshots== (CARDS, FIAT, LEARN, STREAM, REASON) each linking to its
page, the CARDS overview and seven-point vision, a **Downloads**
section under the badges (==the Chrome extension install button==, which used to
sit on the card search's empty state), a search box (matching each feature's name, description, address and
keywords), and a tab bar of the feature categories (Core Workspaces, Evidence &
Research, Team Collaboration, Flowing & Round Analysis, Pre-Round
Intelligence, Practice & Coaching, Recognition & Progress, Documents), each tab showing
its feature count. ==One category is shown at a time==: the first tab is
selected on load, ==clicking a tab shows only that category's feature cards==,
and a link to a category ==opens on that tab==. ==Searching narrows every tab's count==, and if the selected tab has no
matches the first tab that does is shown. ==Each feature card links to its
route and docs page==.

The **Documents** tab ==groups the document
surfaces== (Reason Docs, the Reason Editor and Speech Documents) and, under
their cards, ==embeds the shared Google Drive folder of PDF guides and
handouts==, with an **Open in Google Drive** link.

Under the badges, **Latest videos** ==scrolls the ten newest videos in the
library==. Each one ==opens that video's page in the site's video library (not
YouTube)==, and ==a round is named the way its page is titled== — year,
tournament, level and round, then the teams with their ranks and arguments
when known (`2026 NDT College Octas: Kansas #14 OW (K) vs CSULB #7 MO
(Policy)`) — rather than by its YouTube upload title. ==A lecture keeps its own
title==. **Popular cards this week** follows.

==Pointing at a card lights it up== — a gradient that follows the cursor, a
glowing border and a coloured title — in a shade of its own, so ==neighbouring
cards never come up the same colour==.

### Good to know [#features-page-good-to-know]

==The list is kept by hand==, so ==a brand-new page can take a little while to
appear on it==.

## REASON docs sidebar [#reason-docs-sidebar]

The two collapsible sections, **Topic Starters** and **My Personal Documents**,
==that make up the sidebar in Debate Editor and the card search==. ==Click a file in
either one and it opens in Debate Editor in the main column==.

### The sidebar [#reason-docs-sidebar-the-sidebar]

In Debate Editor and the card search, ==the two sections are all the sidebar
shows==, under the dock; ==the dock is the way back out==, and any other destination
brings the full sidebar back. The phone drawer does the same. An **Evidence
Library** link above them opens the card search. ==Arriving in the card search opens
the sidebar== if it was hidden, so you start with your documents on screen.

==Each section has a chevron header and starts expanded==, and ==collapsing one is
remembered on this device==. ==With both open, drag the bar between them up or down
to give one more room== — with a mouse, a finger, or the arrow keys — and ==the split
is remembered too==.

### Tabs above the editor [#reason-docs-sidebar-tabs-above-the-editor]

==Every file you open gets a tab in the strip above Debate Editor== — your own
documents and public Topic Starters alike. Opening a file ==adds a tab beside the
ones already open instead of replacing it==; ==opening one that's already open
switches to its tab==. Click a tab to switch to it, or its × to close it.

==Each tab keeps its own undo history while the page is open==: ==Undo in one tab
only undoes edits made in that tab==. ==Reloading the page starts every tab's history
fresh==.

Right-click a tab for **Close**, **Close others**, **Close to the right**,
**Close all**, and **Undo close** (==reopens the last closed tab, up to 20 back==).
==Closing the tab you're on moves to its neighbour==.

#### Suspended tabs [#reason-docs-sidebar-suspended-tabs]

==Only five tabs are kept live at once==, to keep the page light. Open a sixth and
==the tab you used least recently is suspended==: it ==stays in the strip==, dimmed with
a moon icon, but ==it's unloaded from memory==. The moon menu at the end of the
strip lists every suspended tab and ==can close them all at once==. ==Clicking a
suspended tab reloads it with all your edits==; only ==its undo history starts
fresh==. ==The tab on screen is never suspended==.

### Links to a file [#reason-docs-sidebar-links-to-a-file]

==Every open file has its own address, named after its title==, so you can bookmark
it or share the link. Two files with the same title get a short code added to tell
them apart. ==The address follows a file that's renamed while open==, and older
links keep working. ==A link to a file that's been renamed, deleted or isn't yours
opens your first file instead of an error==.

#### Your own file addresses [#reason-docs-sidebar-your-own-file-addresses]

==Your own files live under your username==, then the folder they're in, then
the file's name, such as **/alexgul/aff/k-aff-answers**. ==Your username comes
from your account name==, letters and digits only. If someone already has it,
yours gets a number on the end (**alexgul2**). Older **/reason-editor?doc=** links
still open the file and then switch to the new address. While you're signed
out, your files keep the older address.

#### Topic Starter addresses [#reason-docs-sidebar-topic-starter-addresses]

A public Topic Starter's link ==names the resolution it's for and where the file
sits in the library==, such as **/docs/vcx27/neg/cp/aca-expansion-cp-cndi-2026**.
==The topic code is the format and the last two digits of the year==, plus, for the
formats that change topic during the season, ==a letter for which topic of that
year==:

| Format | Code | Example |
| --- | --- | --- |
| High-school policy | vcx + year | `vcx27` (National Health Insurance) |
| High-school policy before 2000 | vcx19 + year | `vcx1928` (1927-28, Department of Education) |
| College policy (NDT/CEDA) | ndt + year | `ndt27` |
| Lincoln-Douglas | ld + letter + year | `lda27` (September), `ldb27` (November) |
| Lincoln-Douglas before 2000 | ld + letter + 19 + year | `lda1999` (1998-99, September) |
| Public Forum | pf + letter + year | `pfa27` |
| Big Questions | bq + year | `bq27` (Tech Ethics) |

Older links that put the letter last (`pf24a`, `ld21b`) ==still open the same
topic==.

Two dropdowns on one line above the Topic Starters tree — a small **format**
picker and the **topic** picker — ==go to a topic's address==. ==The format
dropdown lists Policy, College Policy (NDT), Lincoln-Douglas and Public Forum;
Big Questions is not listed==, though a link to a Big Questions topic still
opens it. The topic dropdown
==lists the format's topics from the 2015 season (2014-15) on, grouped by year,
newest first==. Older topics, including every national high-school policy
resolution from 1927-28 and every NSDA and NCFL Lincoln-Douglas topic from
1979-80, ==are on the [Topics & Statistics](/practice/statistics) page==: pick
**Older topics…** at the bottom of the dropdown to go there. A link to an older
topic's address still opens it, and that topic stays in the dropdown, under
**Older**, while it is open. ==Every NSDA topic is listed==, from the September/October topic
through the NSDA Nationals topic (filed under June) and the NCFL Nationals
topic (filed under May). A link with just the topic code ==opens that topic's
first starter==.

### Older links [#reason-docs-sidebar-older-links]

==Older links keep working==: a Topic Starter link from before topic codes were
added still opens the file and then switches to the new address. A link with no
topic code ==opens under the newest high-school policy topic==.

**Known gaps:**

- ~~The library itself is not split by topic yet.~~ **Fixed:** ==each topic
  has its own Topic Starters tree== — see "Each topic has its own tree" below.
- In the browser extension, ==the older link form is still the working one==
  for Topic Starters.

### Your files load fast and work offline [#reason-docs-sidebar-your-files-load-fast-and-work-offline]

==The sidebar keeps a list of every Topic Starter and every one of your own
files on this device==, so ==the tree is on screen right away== when you come
back, before the server answers, and ==it stays there offline==. A fresh copy is
fetched in the background and replaces the stored one. The Topic Starters list
is refreshed every day and whenever the library is edited.

- ==A file's content is downloaded when you open, download or copy it==. A file
  you've already had open on this device opens with no wait.
- ==Only files changed on another device or tab are downloaded again==; files
  deleted elsewhere drop out of the tree.
- ==If the server can't be reached, your local copy stays== instead of the tree
  going empty.
- ==Each browser copy belongs to one account==: signing in as someone else on
  this browser clears the previous account's tree and tabs and loads the new
  account's files.
- ==An edit can never be saved over a file whose content hasn't loaded yet==.

### File details on hover [#reason-docs-sidebar-file-details-on-hover]

==Hover over any file to see its details==: when it was last modified, who wrote it,
its year, and how big it is — pages, quotes (evidence cards), blocks and
characters.

- ==Each file also shows its quote and block counts as small badges== beside its
  name: blue for quotes, grey for blocks. A count of zero shows no badge.
- The author is the name saved in the Word file when it has one; otherwise it's
  whoever uploaded it.
- A Topic Starter's year is its topic's season. Your own files show the year you
  made them.
- Pages are an estimate (about 3,000 characters a page).
- Older files can show "not counted yet" until they're counted.

### Argument-type badges on Topic Starters [#reason-docs-sidebar-argument-type-badges-on-topic-starters]

==Every Topic Starter shows a small coloured badge for what kind of argument it
is==, read from the file's name and its folders (`Neg/DA/Politics`, `Federalism
CP`, `T - Substantial`), nearest first.

| Badge | Means | Color |
| --- | --- | --- |
| `AFF` | Affirmative case (1AC, plan) | blue |
| `ADV` | Advantage | sky blue |
| `A2` | Aff answers (2AC blocks, "AT …") | indigo |
| `NEG` | Case negative (answers to an aff) | rose |
| `T` | Topicality | amber |
| `CP` | Counterplan | green |
| `DA` | Disadvantage | red |
| `K` | Kritik / critique | purple |
| `TH` | Theory, framework | slate |
| `IMP` | Impacts | orange |
| `DOC` | Nothing to go on | grey |

==Aff badges are all shades of blue; each neg position has its own colour==. A file
with no type word takes its side's badge. Hover a badge for its full name.

### Read-only Topic Starters [#reason-docs-sidebar-read-only-topic-starters]

==A Topic Starter opens read-only==: ==no toolbar and no AI tools==, and its tab names
it. ==To change one, edit your own copy== (see below). ==Topic Starters open in read
mode==.

### Each topic has its own tree [#reason-docs-sidebar-each-topic-has-its-own-tree]

==Picking a different format or topic shows a different Topic Starters tree==. Files
added before topics existed are in the newest high-school policy topic's tree.
==New folders, "Add to Topic Starters" and "Organize by argument" all work inside
the topic on screen==.

### Organising files [#reason-docs-sidebar-organising-files]

==Every file is a Debate Editor file whatever it was uploaded as==, so ==the name is
the whole label==. ==Right-clicking a file opens the same menu as its "…" button==:

- **Topic Starters:** Open, Edit a copy, Save to my files, Copy link, Download as
  .docx, and — when you're signed in — Rename, Move to and Delete (folders also get
  New folder).
- **Share…** ==opens the file in the editor with the share-with-contacts dialog
  already up==, since ==sharing starts a live co-editing session==.

The **Sort** button in the My Personal Documents header ==orders the tree by name
(A–Z or Z–A) or by last modified==. ==Folders always come first==, and ==the choice is
remembered on this device==.

### Moving files between Files and Topic Starters [#reason-docs-sidebar-moving-files-between-files-and-topic-starters]

==Files drag both ways between the two trees==:

- **Topic Starters → Files:** ==saves your own copy into the folder you drop on==. ==A
  folder comes with everything in it==. "Save to my files" does the same.
- **Files → Topic Starters:** ==submits the file to the public library==. Anyone
  signed in can; ==a moderator's or admin's file goes in at once, and anyone else's
  waits for a moderator's approval==.
- **Topic Starters → Topic Starters:** ==moves it into the folder you drop on==
  (signed in only, approved the same way).
- **Files → Files:** moves it. ==A folder can't be dropped into itself==.
- **Your computer → either tree:** ==uploads it==.

### Editing Topic Starters [#reason-docs-sidebar-editing-topic-starters]

==Signed-in readers can rearrange the public library from the sidebar==: rename,
move, delete, add folders and submit their own files. ==Moderators' and admins'
edits apply at once==; ==everyone else's are sent for approval== ("Sent to the
moderators for approval"), and ==nothing changes until a moderator approves it==.
==Moderators get a notification for each proposal== and review them in the admin
panel's **Topic starters** section, where they can also rename, move, copy, paste,
delete and add folders in the library directly. A change that no longer fits (its
file was deleted meanwhile) ==stays in the queue with the reason, to be rejected==.

Admins add Topic Starters with **Sync Topic Starters from openCaselist** in the same
section: ==pick a season and caselist, a format and topic, and press Sync==. ==Each
Word file is converted to a Debate Editor file and filed under that topic==, and
==the card shows progress and any files that failed==, so the page can be closed once
the download is stored.

#### Organize by argument (AI) [#reason-docs-sidebar-organize-by-argument-ai]

The sparkle button in the Topic Starters header ==asks the AI to sort every public
file by side and argument type==: affirmative cases under **Aff/Case**, and the
negative's positions under **Neg/DA**, **Neg/CP**, **Neg/T** and **Neg/K**
(==answers to an argument keep its type and take the side that reads them==, so "AT
Elections DA" in an aff file lands in **Aff/DA**; anything else goes under
**Theory** or **Other**). ==The AI reads only file and folder names, never the
files==. ==It shows its plan before anything moves==; ==confirming applies it for
moderators and sends it for approval for everyone else==. ==Existing Aff/Neg folders

### 1. Get your API key [#mcp-server-1-get-your-api-key]

coach materials) ==needs one==.

1. Sign in to Debate AI.
2. Open **Settings → Debate Account** and scroll to **API & MCP server**.
3. ==Type a name for the key== (for example "Claude Desktop") and press
   **Create API key**.
4. **Copy the key.** It starts with `dai_`. ==Your keys stay listed on the same
   page==: **Show** reveals a key again with a **Copy** button, **Reset** gives
   it a new secret (after you confirm; ==the old one stops working at once==, so
   paste the new one into your client), and **Revoke** deletes it.

==A key acts as you, so treat it like a password==. ==It lasts a year== (longer while
you keep using it; a reset starts a fresh year).
==Signing out of all your other sessions revokes your keys too==.

==Every client below sends the key the same way, as an HTTP header==:

```
Authorization: Bearer dai_your_key_here
```

### 2. Connect your AI tool [#mcp-server-2-connect-your-ai-tool]

Replace `dai_your_key_here` with your key in each example. The settings page
==also shows a ready-to-paste config with your new key filled in==.

#### Claude Code [#mcp-server-claude-code]

```bash
claude mcp add --transport http debate-ai https://debate-ai.com/api/mcp \
  --header "Authorization: Bearer dai_your_key_here"
```

Or add it to your project's `.mcp.json`:

```json
{
  "mcpServers": {
    "debate-ai": {
      "type": "http",
      "url": "https://debate-ai.com/api/mcp",
      "headers": { "Authorization": "Bearer dai_your_key_here" }
    }
  }
}
```

#### Claude Desktop [#mcp-server-claude-desktop]

Claude Desktop's config file starts local servers, so it ==reaches a remote
server with a header through the== `mcp-remote` bridge (needs Node.js). Open
**Settings → Developer → Edit Config** and add:

```json
{
  "mcpServers": {
    "debate-ai": {
      "command": "npx",
      "args": [
        "-y", "mcp-remote", "https://debate-ai.com/api/mcp",
        "--header", "Authorization: Bearer dai_your_key_here"
      ]
    }
  }
}
```

Restart Claude Desktop. ==The Debate AI tools appear under the tools icon==.

#### Claude.ai and ChatGPT (custom connectors) [#mcp-server-claudeai-and-chatgpt-custom-connectors]

In Claude.ai, open **Settings → Connectors → Add custom connector**; in ChatGPT,
turn on developer mode and add a connector. Use
`https://debate-ai.com/api/mcp` as the URL with no authentication. ==These
connectors can't send a custom header==, so ==you get the public tools== (search,
videos, transcripts, schools, tournaments, leaderboard) ==but not your account's
data==.

#### Anything else [#mcp-server-anything-else]

Point the client at `https://debate-ai.com/api/mcp` as a Streamable HTTP
server and add the `Authorization` header. To test by hand:

```bash
curl -s https://debate-ai.com/api/mcp \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer dai_your_key_here" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

### What the tools can do [#mcp-server-what-the-tools-can-do]

==There is one tool per operation in the== [Debate AI API](/api), named after its
operation (for example `searchCards`, `listVideos`, `getVideoTranscript`,
`listFlows`, `syncRound`). ==Tools that only read are marked read-only, and
delete tools are marked destructive==, ==so your client can ask before running
them==. ==Admin, sign-in and API-key operations are not exposed==.

==Your API key also works with the REST API itself==: send the same header to any
route listed at [/api](/api).

### Security [#mcp-server-security]

- ==Your API key acts as you==, with access to your whole account, so keep it
  private. **Reset** or revoke a key you no longer trust; ==the old one stops
  working at once==.
- ==An API key can't be used to see or create other keys==; that only works
  while you're signed in to the site.
- ==The server never uses your browser's sign-in==, only the key you give your
  AI tool, so a web page can't act as you through it.

### Good to know [#mcp-server-good-to-know]

- ==No OAuth==. Clients that can only connect with OAuth or no auth (Claude.ai and
  ChatGPT custom connectors) ==get the public tools only==.
- ==No streaming==: the server never sends progress, and tools that stream on
  the site ==return their whole answer at once==.
- ==A key's scope is the whole account==. ==There are no read-only keys==.
- ==Some tools have thin descriptions==, which gives your AI less to go on.
- ==Each API key also shows up in your list of signed-in sessions==.
