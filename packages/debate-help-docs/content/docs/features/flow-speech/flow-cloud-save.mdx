# Flow Cloud Save

==Lets a signed-in user save an individual flow to their account and load it
back on any device==.

Open the flow history dialog: the **Saved to account** tab lists your saved
flows, and each flow chip in the **Rounds** tab has a cloud-upload icon.

## What it does

==Clicking a flow's cloud icon saves that flow to your account==. The **Saved
to account** tab ==lists every saved flow with Load and Remove actions==. ==A
signed-out user sees a sign-in prompt== instead; ==working locally is never
blocked==.

==A search box at the top of the "Saved to account" tab narrows both the saved
flows and the saved rounds by name== as you type. Every word you type must
appear, in any order, and case doesn't matter. ==A flow saved as part of a
round also matches on that round's name== (tournament and round level), so
searching a tournament finds its flows. Clearing the box shows everything
again. The search only filters what the tab already loaded; it doesn't send
anything to the server. It appears once you're signed in and your saved flows
have loaded.

==The save is optimistic-concurrency checked==: it sends along the `updatedAt`
of the cloud copy this browser last knew about (from the last list/load/save
response it saw). If that doesn't match what's actually saved — someone else
saved a newer version since — ==the save is rejected with a conflict instead
of silently overwriting it==, and the flow's cloud icon turns into a warning
that ==a second click (an explicit "save anyway") resolves==.

## Data flow

```
state/savedFlows.ts (pure validation, hasFlowSaveConflict)
round/saved-flows-client.ts (fetch: list/fetch/save/delete)
state/savedSummaryFilter.ts (pure search: filterSavedSummaries)
dialogs/FlowHistoryDialog.tsx
apps/debate-ai.com/app/api/flows/[route.ts, [clientId]/route.ts]
```
