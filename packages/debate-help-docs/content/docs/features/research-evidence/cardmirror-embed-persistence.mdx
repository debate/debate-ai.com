# How Debate Editor keeps your files safe

==Debate Editor saves your work to your account as you type==, and it is built so
that ==a file you've loaded can never be saved over with a blank page==. This page
explains what you'll see while it saves, and what happens when something goes
wrong.

It applies ==anywhere Debate Editor is open==: the editor itself and Flow's
speech-doc panels.

## Saving as you type

- ==Edits are saved a moment after you stop typing==, separately for each
  document, so ==switching between files, or renaming one and typing in
  another, never drops a change==.
- ==Closing or hiding the tab saves anything still waiting==, so ==closing a tab
  mid-sentence doesn't lose the sentence==.
- The header shows **Saving…**, **Unsaved changes**, or **Couldn't save —
  retrying…**. ==A failed save keeps retrying on its own==, and a retry never
  brings back older text.
- Moving a file to another folder is saved the same way.
- ==Deleting a document cancels any saves still waiting for it==.

## Deleting text is still an edit

==If you empty a file yourself, the empty file is saved==. What can't happen is
the editor replacing your file with a blank page on its own: ==if a blank page
appears where your document was, the editor puts your document back==.

## When a document can't be read

If a stored document can't be opened (for example markup from an older editor,
or a file that was cut short), ==the editor keeps whatever is already on screen
instead of showing a blank page==, ==shows a notice==, and ==stops saving that
document==, so ==nothing typed in the pane can overwrite the copy on the server==.
The notice has a **Download** button that saves what was in the pane, so ==you
can rescue it==. ==The copy on the server is untouched==. Opening the same
document again later, once it reads cleanly, saves normally again.

Footnotes are kept through every save.

## No pop-ups on open

==Because the site opens Debate Editor on nearly every visit==, the embedded editor
==doesn't show its first-launch pop-ups==: no draft-recovery sidebar, no UI tour
and no Verbatim nudge (**Help → UI tour** still starts the tour), and the
"Receiving cards in-browser needs your account" notice ==shows only once per
browser==. ==The outline pane still opens beside the document as before==.

## `.cmir` files open in read mode

==Opening any `.cmir` document turns read mode on==, the same as the Read mode
button: Topic Starters, uploaded documents, and files you open from your
computer, recents or the command palette. Documents you wrote in the editor
still open editable. ==Turning read mode off sticks for that document until you
open another one==.

## Good to know

==Flow's speech docs are protected the same way==, but they are saved as part of
their flow rather than one document at a time.
