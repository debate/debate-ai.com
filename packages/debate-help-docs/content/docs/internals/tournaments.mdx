# Tournaments: engineering notes

Two sidebar entries in the Practice section reach Tabroom.

| Sidebar row | Route | What renders |
| --- | --- | --- |
| Tournaments | `/practice/tournaments/[[...slug]]` | `TournamentsApp` from `debate-tournaments/ui`, fed by `/api/tabroom-beta` |
| Tabroom | `/practice/tabroom/[[...slug]]` | an `<iframe>` of `https://beta.tabroom.com` |

`/practice/tournaments-beta` was the native route's first name; the table in
`debate-data-sync`'s `routes/category-paths.ts` redirects it (and everything
under it) to `/practice/tournaments`.

Both rows live in `packages/debate-videos/src/components/category-gallery/sidebar-tool-sections.ts`;
both routes are in `packages/debate-webview/src/routes/index.ts` and have a
one-line `page.tsx` under `apps/debate-ai.com/app/practice/`.

## The imported UI

`packages/debate-webview/src/routes/tournaments/[[...slug]]/page.tsx`
mounts ``<TournamentsApp segments={slug} basePath="/practice/tournaments" apiBase="/api/tabroom-beta" Link={Link} />``.
`TournamentsApp` resolves the slug with `matchTournamentRoute()`
(`debate-tournaments/routes`) and renders one of six pages: upcoming, invite,
pairings, one round, results, one result set. Every request goes to
`apiBase`, so the browser never contacts a Tabroom origin.

The pages are built from shadcn primitives copied into
`packages/debate-tournaments/src/ui/primitives.tsx` (Card, Badge,
`buttonVariants`, Input, Table, and the Tabs look for the section links).
They are copies rather than imports because `debate-tournaments` must not
depend on `debate-webview`, where the app's own shadcn set lives. They use only
shadcn theme tokens (`bg-card`, `text-muted-foreground`, `ring`, …), so every
theme in `debate-webview/src/styles/themes.css` restyles them, and
`app.css` already lists `debate-tournaments/src` as a Tailwind `@source`.

## The proxy

`apps/debate-ai.com/lib/tournaments/tabroom-beta-proxy.ts`, mounted at
`app/api/tabroom-beta/[...path]/route.ts`, forwards
`/api/tabroom-beta/<path>` to `https://api.tabroom.com/v1/<path>`. That is the
API beta.tabroom.com's own frontend calls; beta.tabroom.com itself serves only
the SvelteKit site.

- Only `GET` and `HEAD`; anything else answers 405.
- Only paths under `rest/` and `pages/`; anything else answers 404 without a
  request upstream. Empty, `.` and `..` segments are refused.
- Only an `accept` header is sent upstream. The visitor's cookies and
  credentials never leave this app.
- A successful answer is cached for 60 seconds (`public, max-age=60, s-maxage=60`);
  an error status passes through with `no-store`.
- A network failure or a 15 second timeout answers 502 with a `detail`
  message, which the UI's `ErrorNote` shows.

## The D1 API is separate

`/api/tabroom` (`lib/tournaments/handler.ts`) still serves the vendored
Tabroom API from the app's own D1 database, seeded by
`bun run db:seed:tournaments`. The `debate-tournaments` UI works against
either base; only `/practice/tournaments` is mounted, and it reads live
Tabroom.

## Known gaps

- The framed view loads all of beta.tabroom.com on every visit, which is the
  cost the September 2026 performance pass removed by linking out instead
  (see [performance](/docs/internals/performance)). It is back by request.
- The framed view keeps its own URL; navigation inside the frame does not
  update the address bar.
- The proxy forwards public, read-only routes only, so paradigms (login
  required upstream) and every write are unavailable in the imported UI.
- Tournament logos load from `/tournament-logos/<webname>.png`, which exists
  only for tournaments the app ships a logo for.
