# native-wrapper

A generic [Tauri](https://tauri.app) shell that packages any website as a native desktop
(Windows/macOS/Linux) and mobile (Android/iOS) app — a titled window that loads the site directly,
with the OS-level plumbing a plain webview doesn't get for free: a real app icon on every
platform, a Google-OAuth-compatible login handoff, and a fullscreen toggle. Ships pre-configured
to wrap [debate-ai.com](https://debate-ai.com); point it at a different site by swapping the
active profile (see `profiles/README.md`).

## What this is not

Not a place for app-specific UI or logic — the wrapped site provides all of that. This package's
job stops at: open a window at the configured URL, register the app's identity (icon, name,
bundle id) with each OS, and get a browser-based OAuth login back into that window. Anything more
belongs in `apps/debate-ai.com` itself, not here — see `docs/OAUTH.md`'s "Extending this to
another site" for why that separation is what makes this package reusable.

## Layout

```
native-wrapper/
├── profiles/             # one JSON file = one app identity (see profiles/README.md)
│   ├── debate-ai.json     #   the profile this repo ships configured with
│   └── example.json       #   template for pointing this wrapper at a different site
├── scripts/
│   ├── configure.mjs      # profile -> src-tauri/tauri.conf.json + generated_scheme.rs
│   └── generate-icons.mjs # profile's iconSource -> full src-tauri/icons/ set
├── src-tauri/
│   ├── src/lib.rs          # window setup, deep-link OAuth handoff, fullscreen toggle
│   ├── capabilities/       # Tauri's permission grants (default.json + a scoped remote.json)
│   ├── icons/               # generated by generate-icons.mjs, checked in for the debate-ai profile
│   └── tauri.conf.json      # generated by configure.mjs, checked in for the debate-ai profile
└── docs/
    ├── OAUTH.md            # why login needs a system browser + deep link, and how it works here
    ├── BUILDING.md         # local dev/build commands + what the two CI workflows do
    ├── MOBILE.md           # Android/iOS host requirements and gen/android, gen/apple
    └── APP_STORES.md        # Microsoft Store, Mac App Store, iOS App Store, Google Play
```

## Quick start

```bash
cd packages/native-wrapper
npm run dev              # opens a window on the debate-ai profile's URL
```

To build installers, retarget at a different site, or ship to a store, see the docs above —
`docs/BUILDING.md` is the right starting point.

## Why a window, not a bundled frontend

`tauri.conf.json`'s main window points its `url` straight at the profile's site over HTTPS —
there's no local copy of the app's UI to keep in sync with the real site (`build.frontendDist`
still points at `dist/`, an unused placeholder Tauri's bundler requires to exist). The tradeoff:
the app needs network access to be useful, same as opening the site in a browser tab would. If a
future use of this package needs an offline mode, that's an addition to `dist/`'s placeholder
page and the window-creation logic in `src-tauri/src/lib.rs`, not a redesign of this package.
