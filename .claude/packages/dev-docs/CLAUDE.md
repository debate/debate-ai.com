# CLAUDE.md — `debate-help-docs/dev-docs`

The developer docs. Not a package: a folder of `debate-help-docs`, compiled as its own Fumadocs
collection (`devDocs` in `source.config.ts`) with its own loader (`lib/fumadocs/dev-source.tsx`),
layout, sidebar, search index and Copy-Markdown route (`routes/dev-*`). The web app mounts them
at `app/docs/dev`, so the site is served at **`/docs/dev`**.

## It is unlisted, not private

- Nothing on the site links to `/docs/dev`: not the user docs, not the app sidebar, not the
  nav. Keep it that way. Links may go from the dev docs to `/docs`, never the other way.
- It is not in `sitemap.xml`, the user docs search, `llms-full.txt` or the app sidebar's Docs
  tree — those read `source`, never `devSource`. Do not merge the two.
- Every page is `noindex` (metadata in `routes/dev-docs-layout.tsx`). Do not list it in
  `robots.txt`: that file is public and would advertise the URL.
- There is no auth gate, and the repo is public. Never write a secret value here.

## Layout

| Folder | Section |
| --- | --- |
| `index.mdx` | Overview |
| `setup/` | Self-hosting: local development, database setup, deploy, environment variables, operations |
| `database/` | `app-schema.md` (every table in `apps/debate-web/lib/database/schema.ts`) and `tabroom-schema.md` (generated by `packages/debate-tournaments/scripts/sync-upstream.mjs`; descriptions carried over) |
| `packages/` | One page per `@debate-ai/*` package: its README (or `packages/README.md` entry), then `<DependencyGraph>` and `<FileTreeView>` |
| `internals/` | Feature internals; `meta.json` groups them under separators |

Every page needs frontmatter with a `title`. `.md` files compile as plain Markdown; `.mdx` files
have the two MDX traps in `.claude/architecture/documentation.md`. Link between pages by relative
file path (`./deploy.md`, `../database/app-schema.md`): `dev-docs-page.tsx` resolves those to
page URLs. Link to the user docs with `/docs/...`.

## Package code graphs

The `<DependencyGraph package="<dir>" />` and `<FileTreeView package="<dir>" />` views on the
package pages are code-tree-graph's components, vendored into `components/code-graph/` (the npm
build stubs out `fs`, ships one 6 MB bundle with no `'use client'` split, and parses with the
TypeScript JS API, which TypeScript 7 doesn't have). The Worker has no filesystem, so
`devDocsCodeGraph()` in `vite.mjs` scans `packages/*` at build time with `lib/code-graph/`
(parser: `oxc-parser`) and serves each package's tree as a lazily loaded client chunk; the
server environments get an empty loader map, so none of it reaches the Worker bundle. Folders
skipped per package are in `lib/code-graph/index.ts`.

## Keeping it current

- A new `@debate-ai/*` package needs a `dev-docs/packages/<dir>.mdx` page with both views, and a
  card on `packages/index.mdx`; `apps/debate-web/lib/__tests__/docs-dev-code-graph.test.ts`
  fails until it has one.

- When a change adds or alters a table in `schema.ts` or a `packages/*/migrations/*.sql` file,
  update the table's entry under `database/` in the same change.
- When a change adds an environment variable, add it to `setup/environment-variables.md` (name,
  purpose, where it is read, required or optional).
- A new internals page needs adding to `internals/meta.json`, under the right separator, or it
  will not appear in the sidebar.
- Build the web app to check it: the docs are excluded from the test run.
